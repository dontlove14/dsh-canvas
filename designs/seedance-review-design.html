先确定素材组边界

按画布自动创建的组使用 AIGC 类型，用于虚拟人像素材。真实人物使用已认证的真人组；一个真人组只能对应一个人，不能把画布上所有人物放进同一个自动组。

所有有实际文件的图片、视频、音频节点都提供预审入口。文件类型支持并不代表内容适用于虚拟素材库：非虚拟人像类素材无需进入该库，真人应选择真人认证组。

建议的首轮范围：设置两家供应商、按画布创建虚拟组、单素材异步送审、逐素材状态与恢复、生成引用。真人素材支持选择官方已认证的组；无可用真人组时，引导到官方控制台完成认证。本轮不在插件内新建 H5 认证系统，不新增审核策略开关。

这是针对官方接口限制提出的方案，不把上传虚拟组当作真人认证。是否将完整 H5 真人认证也纳入首轮，属于待评审范围。

02 · 顶部预审入口，名称旁显示结果

图片、视频、音频节点的顶部操作栏新增盾牌图标，提示为「Seedance 预审」。生成节点必须已有保存完成的输出文件才可送审；空节点、生成中但尚无文件的卡片没有可送审目标。

点击后打开一个小面板，明确本次素材和目标供应商。只有一家可用配置时直接选中；两家均配置时优先带入唯一连接的官方 Seedance 供应商，否则使用本画布最近一次选择，首次无默认时由用户选择。不会因一张图连接两家模型而自动双份送审。

面板提供「虚拟素材 / 已认证真人素材」路径。虚拟素材使用本画布的默认组；真人素材选择该供应商、该项目中已认证的人物组，没有组则停在认证引导。点击「提交预审」后本地异步任务被接受，立即显示「审核中」，关闭面板和离开画布不取消任务。

交互示意 · 切换展示方式，点击盾牌，再使用「模拟通过 / 失败」查看标记 · 不调用任何接口

状态名称旁展示点击状态后的行为
未送审不显示状态标记从顶部盾牌打开送审面板。
排队 / 准备 / 提交 / Processing青蓝色小点 +「审核中」显示本次供应商和阶段；不编造完成百分比、预计完成时间。

提交结果不确定 / 无法继续查询中性提示图标「待确认」优先恢复查询 / 核对已提交结果。网络超时不冒充审核失败，也不自动重新上传。

样式以参考图为准：名称旁显示小字或小图标，不给整个节点蒙层，不替换既有生成与媒体 Loading。颜色跟随 Harness 主题。图标具有键盘操作、说明文字和屏幕阅读器名称；详情点击不触发改名、拖动、播放或打开历史编辑器。

两家结果同时存在时：展示两枚紧凑标记，分别标注 BD / B+；例如「BD 审核中」「B+ 盾牌勾」。不把某一家通过显示为全供应商通过。

03 · 两类堆叠使用不同送审目标

场景本次送审对象状态位置与切换
普通资源 / 单输出当前 assetId 对应的图片、视频或音频原文件名称旁显示该素材状态。
单次批量结果，切换主图只送当前主图，不批量送审其他结果。展开后也以主图为默认入口。节点名称旁显示主图状态。主图从 A 换为 B 时切换到 B 的状态；A 的任务继续、结果保留。A 通过不代表 B 通过。
多次生成历史，展开每次提交中的每一份实际输出都可单独送审，包括一条历史提交内的多输出。每个输出单元增加自己的轻量名称 / 状态行与盾牌入口；不只把图标放在整个历史节点的标题旁。
多次生成历史，收起只送当前实际显示的封面输出，通常是最新提交的第一份结果。显示封面对应状态。最新提交尚无结果时，不拿上一张图的通过标记顶替；提示展开查看可送审历史结果。
同一素材在画布上被多个节点引用同一供应商、项目、组、原文件身份下共享审核记录。多处同步显示，同一内容不因节点位置、改名、连线、封面旋转而重新送审。

审核完成不切换主图、不重排历史、不抢焦点，也不改旧连线指向的素材。每个状态以实际文件身份为准，节点只是它的展示位置。

04 · 新建画布时登记建组，云端异步完成

采用你的按画布建组建议，但不等待云端接口完成才让画布创建成功。新画布保存成功的同次处理登记补建意图，随后后台为已配置的两家供应商各创建一份 AIGC 组。只配一家就只建一家。

1 · 画布立即可用不被云端建组耗时、断网或权限错误阻塞。
2 · 两家分别建组画布 × 供应商 × 账号配置域 × ProjectName 各自绑定。
3 · 送审等待对应组组未就绪时审核任务排队；失败提供明确原因与重试。

组名称建议由画布名称的短前缀与稳定画布标识组成，满足官方长度限制；改名不重建组。旧画布首次使用补建；删除或复制画布不隐式删除、复用别的画布的云端组。

真人素材使用“画布关联人物组”的方式，一个画布可以关联多个已认证组；同一个人在两家供应商的授权和 Group ID 分开维护。自动创建的 AIGC 组不会替代真人认证。

ProjectName 改变后使用新项目中的组；旧任务继续使用接受时的项目。AK/SK 轮换先检查原组是否仍可访问，不能仅凭字符串变化认定账号已换，也不能把无权限当作组已删除。

05 · 预审结果如何供视频生成引用

按用户确认规则：审核通过用 Asset ID；未送审或审核失败，仍允许生成并使用原 URL。审核中、待确认也使用原 URL，不把预审作为生成的必经门槛。

仅对 Bytedance / BytePlus 的 Seedance 官方渠道使用。已通过素材在对应请求的 image_url.url、video_url.url、audio_url.url 中写入 asset://<官方 Asset ID>，保持原来的引用排序和 reference_image / reference_video / reference_audio / first_frame / last_frame 角色。

对应供应商下的参考素材状态建议行为
从未送审保持现有原 URL 生成路径，不自动上传所有参考素材。
Active，项目及账号访问匹配使用官方 Asset URI；接受生成任务时固定本次引用，不因后续状态或设置变动重新选择。
正在预审 / 失败 / 待确认允许正常提交视频生成，使用原 URL。预审失败标记仍保留，不伪装通过，也不重新上传素材。
只有另一供应商或旧项目的通过记录不复用该 Asset ID，当前供应商使用原 URL。状态说明所属供应商 / 项目，不当作当前通过。
Model Link / 其他模型保持原路径，不传官方 Asset ID，不自动切换供应商。

模型 API Key、EP 与素材组需要处于兼容账号 / 项目权限范围。仅配置一个 ProjectName 无法自动证明模型凭据属于该项目；生成前进行可用性检查，官方若返回跨项目 / 权限错误，保留原记录并报告错误，不自动迁移或降级。

一个请求允许混用：参考图 A 已通过则传 Asset URI，参考视频 B 未通过则传 URL。引用方式在任务接受时固定：当次用了 URL，后来素材审核通过也不会修改或重新提交该任务，下一次生成才使用 Asset ID。

入库成功不保证每个模型都接受该素材的时长、尺寸，也不保证最终提示词与视频产物通过所有审核。生成仍执行对应版本的输入限制。

06 · 关闭页面、重启与失败恢复

情况处理
重复点击 / POST 回包丢失复用本地请求身份和已接受任务。没有官方 Asset ID 且提交结果不明时，先核对，不能直接再发一次 CreateAsset。
关闭面板 / 离开画布后台继续；重新进入读取当前状态。关闭面板不等于取消已接受任务。
Harness 重启 / 电脑关闭关机期间不在本机执行。再次启动后恢复持久任务；已有 Asset ID 只查询，不重新上传原素材。
GetAsset 返回 HTTP 200仍读取 Status；只有 Active 才显示通过。Failed 读取错误码和原因。
已通过素材再次点击打开详情与可用性查询，默认不重新送审、不创建新 Asset。
明确失败后重试用户显式发起新一次任务。旧错误及旧 Asset ID 保留；网络错误优先恢复查询。
素材改名 / 节点移动 / 主图切换保留原素材审核记录；状态展示跟随具体 assetId。原文件字节改变则不继承旧通过状态。
本地删除素材 / 画布不自动调用官方删除接口。停止无主轮询并保留必要任务证据；云端清理需另行明确操作。
签名 URL提交时针对固定原文件生成新 URL，不能上传压缩封面或波形，不能持久缓存临时 URL 当作素材身份。
缺权益 / 授权 / 权限画布继续可用，送审显示明确的配置或开通问题。不会自动创建真人组或改用另一供应商。

首轮 BytePlus 使用 Moderation.Strategy=Default，Bytedance 不发送此字段。附件里的 Skip 是另一种官方策略，需单独的产品决定和权益核对；本稿不把“预审”自动解释为启用 Skip。

需要你评审的核心取舍：普通虚拟组按画布自动创建；真人使用已认证人物组；新建画布不等云端返回；多次历史逐输出送审。其余未验证的真实账户行为在技术设计中单列。
