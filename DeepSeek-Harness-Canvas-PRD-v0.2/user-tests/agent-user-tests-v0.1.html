  • 三类用户用于测试分组，不要求产品增加身份标签、熟练度问卷或固定角色模式。实际交流深度应随本次表达变化。

  • 由用户手动操作；测试准备者负责提供指定画布、有效配置和可复现异常。每条用例可独立执行，旅程串联时只复用同一目标画布。
  • 模型甲、模型乙是测试代号，执行前替换为真实、已配置且满足当前任务要求的候选。模型选项和能力以真实配置为准。
  • 准备素材“杯子正面图”“店面参考图”，记录它们的实际文件与结果身份；准备一张已有画布和一个没有关联画布的新会话。视频案例使用已验证支持参考输入与所选画幅的真实模型。
  • 当前手动可测只表示用例可在现有功能上执行，不表示已通过。其余用例等待 Agent 接入或对应具体功能实现。
  • P0：创作完成、控制权、明确选择、事实与数据保留等关键路径。P1：引导深度、偏好切换和补充体验。优先级是本测试计划的建议。
  • 通过：已执行且全部关键预期满足；失败：已实现并可执行但出现偏差；阻塞：环境、配置、能力或规则尚不足；不适用：该版本明确排除该能力，并写明理由。未执行不填写“通过”。
  • 真实任务只有文件实际可用且能预览或下载才算交付。计划、空节点和等待状态不能当作成品。
  • 模型输出的美感与细节是单独的人工作品反馈。模型偶发偏差与 Agent 漏掉或改写已确认输入分别记录，不用一次成品的审美好坏代替架构验收。
  • 画布在 Agent 操作期间只读；观察、播放、下载不等于内容修改。接管取消 Agent 与撤销写入权；已接受媒体任务的实际取消能力单独核对。

A-01

手动画布基线：引用不自动生成

P0当前手动可测未执行
前置条件
  • 对象存储和图片模型已配置；画布未被 Agent 占用。
用户原话我先自己放好参考图和生成节点，再决定什么时候生成。

操作步骤

  1. 上传“杯子正面图”，创建图片生成节点并填写提示词。
  2. 把参考图连接到生成节点；观察任务入口。
  3. 由用户主动点击一次生成，等待实际结果。

预期结果

  • 建立引用只保存输入关系，不自动创建生成任务。
  • 主动点击生成后使用当时的提示词、参数和具体参考素材；只提交该次任务。
  • 文件实际就绪后可预览和下载，刷新后保留引用与结果。

观察重点：熟悉的手动流程是否保持一致；引用关系和真实任务是否容易区分。

A-04

执行中接管，不等待整条创作完成

P0Agent 接入后未执行
前置条件
  • Agent 正在操作，至少已有一项已保存修改；还有后续步骤未执行。

操作步骤

  1. 点击画布的接管入口。
  2. 观察当前回复和后续画布操作是否停止。

  • 已确认成果保留，旧回复不继续增长，未执行的后续步骤不再执行。

观察重点：接管是否让用户实际取得控制，而非只切换了按钮样式。
