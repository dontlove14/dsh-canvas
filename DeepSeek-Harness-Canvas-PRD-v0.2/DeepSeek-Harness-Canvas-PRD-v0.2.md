## 1. 定位、目标与版本变化

### 1.1 两种主要交互方式

**[已确认] 人工画布创作。**用户直接创建和组织节点、编写提示词、引用素材、发起生成与编辑媒体，自由决定内容、流程和结果。

**[已确认] Agent 对话创作。**用户在 Harness 中描述需求，由 Agent 理解、规划并操作画布。系统自动打开对话侧边栏中的画布，创建所需文件夹与画布，在画布上呈现实际创作过程。用户在 Agent 操作期间以只读方式观察；点击人工接管按钮后，Agent 操作立即停止，当前对话回复结束，用户开始编辑。用户之后继续提出创作要求时，系统自动把人工操作转换为文本上下文，交给 Agent 续作。[来源 1]

**[已确认] Agent 必须使用多模态模型。**无限画布助手以音频、图片和视频创作为主要用途；用户在该助手会话的对话模型选择器中只能选择合格的多模态模型，非多模态模型禁止选择。完整选择、校验与缺失处理见 FR-13。

两种入口使用同一份画布、素材、输入和任务历史。切换操作者不能复制成另一份隐蔽项目，不能要求用户重新上传已有素材，也不能要求用户手工解释每一项已保存的修改。

### 1.2 用户、触发与完成条件

- 主要用户：希望在 Harness 内创作图片、视频、配音等媒体，并按需要在手动操作与对话委托之间切换的人。
- 人工入口触发：用户打开插件，选择或创建画布，直接操作。
- Agent 入口触发：用户在无限画布助手会话中提出需要实际生成或编辑媒体的创作要求。只讨论方案、询问能力或切换预设本身，不创建项目、不提交生成。
- 完成条件：本轮要求的媒体已生成或编辑，文件实际可用，位于明确的画布 / 节点 / 任务中，可预览、引用或下载；Agent 对话能够说明已完成、未完成和需要用户处理的事项。
- 中断后的完成条件：用户能接管已完成的内容，操作不会被旧 Agent 回调覆盖；之后 Agent 能识别人工修改，从当前真实状态继续。

**[已确认]** 同时服务专业媒体创作者与不了解画布 / 剪辑的普通用户。前者可以通过画布精细组织内容，也可以委托 Agent；后者可以只表达想要的结果，由 Agent 逐步引导。入口选择不等于专业程度，不能因为用户使用对话就默认其不专业。

| 用户情况 | 产品需要提供的支持 |
| --- | --- |
| 专业创作者 | 保留准确的专业术语、参数与素材组织方式，尊重明确的创作决策；人工画布与对话委托可随时切换 |
| 普通用户 | 用日常语言理解目标，帮助补齐必要信息，解释下一步与结果；不要求先掌握节点、连线、模型或剪辑术语 |
| 熟悉程度未知 / 使用偏好变化 | 默认通俗、简洁；按用户表达和反馈调整，不增加强制专业水平问卷或身份标签 |

| 主题 | 旧稿 / 当前基线 | v0.2 需求 |

## 3. Agent 预设架构与控制模型

### 3.1 已选定的接入方案

**[已确认] 方案：Harness 原生工具＋插件共享创作服务＋自定义 Agent 预设。**

插件在宿主中加载一份共享创作服务，人工页面和 Agent 工具都通过它处理业务。Agent 工具通过 Harness 的 `ctx.tools` 注册，加入无限画布助手预设的作用域。预设选择使用哪些能力，不再创建一份独立画布运行时。[来源 5]

| 组成 | 职责 | 边界 |
| --- | --- | --- |
| Harness Agent 与模型 | 对话、理解需求、规划步骤、调用工具、生成回复 | 使用宿主已有 Agent 驱动与模型路由，不在插件内再实现一套聊天循环 |
| 无限画布助手预设 | 组合创作角色、用户引导、技能与允许工具；应用模型资格规则 | 预设描述不是业务授权，也不是实际执行者 |
| Agent 原生工具入口 | 接收结构化操作意图，确认调用上下文，调用共享服务并返回结果 | 不直接读写数据库，不调用浏览器点击、拖拽或坐标脚本 |
| 插件共享创作服务 | 处理业务校验、控制权、数据变更、任务与已确认操作记录 | 人工与 Agent 遵守同一业务规则；真实结果只在执行确认后发布 |
| 插件页面 | 手动编辑、只读观察、接管入口、展示已确认结果 | 页面不是 Agent 执行器，打开侧栏通过插件与宿主的正式集成完成 |

服务接口、调用适配和页面展示在职责上分开，当前保持一个安装包。具体目录、导出路径、服务键、接口参数和持久布局属于后续技术设计。

**选型依据与代价：**

| 方案 | 本次结论 | 理由 |
| --- | --- | --- |
| 原生工具调用共享服务 | 采用 | 与 Harness 的工具、作用域、会话和取消机制直接配合，复用现有插件业务 |
| 先建立外部 MCP 服务器 | 当前不采用 | 当前使用者就在 Harness 内；额外连接与身份适配仍不能代替画布控制权管理 |
| Agent 直接操作数据库 | 不作为产品接入方式 | 会绕过业务校验、保存规则和操作者约束，并把内部结构暴露为工具契约 |
| 浏览器模拟操作 | 不作为主要创作方式 | 执行依赖界面和视口，难以保证确认结果、后台生命周期和强制接管 |

正面影响：人工和 Agent 结果一致，安装链路简单，后续能力可以逐项接入。维护代价：插件需要维护工具契约、资格校验和交接规则，并跟随所支持的 Harness 版本核对公开接口。责任由项目维护者承担。

这是一项可扩展的接入选择：未来需要其他客户端或外部 Agent 使用画布时，可以在同一共享服务上增加 MCP 适配，不复制业务逻辑或建立第二份数据来源。是否对外提供 MCP 的认证与可访问范围在出现该需求时另行设计。[来源 6]

### 3.2 预设组成与作用域

**角色与指导负责“如何创作”，工具与服务负责“能做什么、是否允许做”。**

- 角色提示规定助手是媒体创作伙伴，既理解专业要求，也能引导普通用户。
- 技能承载可按需读取的创作方法和使用说明；具体技能内容随功能定义补充。
- 工具只暴露已接入并允许当前会话使用的业务能力。没有实现的能力不注册为可用工具，提示词也不能声称可以执行。
- 模型资格、控制权与调用校验由程序执行，不能仅靠提示词要求模型自律。
- 向用户请求必要选择或信息时，组合 Harness 的 `ask_user_question` 工具与宿主应答界面，按照 FR-14 调用和处理结果；不通过解析普通回复中的 JSON 或 Markdown 自建一套提问协议。

**[已确认]** 创作工具在无限画布助手预设的作用域中组合，宿主共享服务只加载一次。不同会话可以有不同的工具组合，但操作同一画布仍服从单一操作者规则。

Harness 作用域管理能力可见性和注册生命周期，并不自动形成数据库、文件或操作权限边界。因此该预设应限制继承的通用执行能力，避免从文件、终端或浏览器工具绕过画布服务；共享服务仍须验证真实会话与当前控制权。[来源 4]

### 3.3 生命周期、事实来源与依赖方向

**生命周期分工：**

| 事项 | 归属 |
| --- | --- |
| 对话轮次、模型请求、回复与取消 | Harness Agent |
| 预设工具与指导的注册 / 撤销 | 对应预设作用域及插件生命周期 |
| 画布、素材、已保存内容与持久媒体任务 | 插件共享创作服务及其后台运行时 |
| 当前目标、操作者、交接状态与人工修改批次 | 插件交接管理，按会话和画布核对 |
| 面板展开、观察视口与页面呈现 | 客户端展示，不取得 Agent 的写入权 |

Agent 工具依赖业务接口，不依赖页面组件或存储实现；页面也通过同一业务接口提交人工意图。服务确认内容变更后，页面刷新 / 订阅该事实，Agent 收到相应回执。执行通知可以推动展示，但不能成为另一份独立项目状态。

提交长时间任务时，工具返回明确的接受结果和任务身份；任务状态由共享服务继续维护。工具调用的取消不等于外部媒体任务已取消。保留现有持久执行与恢复能力，不用进程内的 `jobs-local` 取代持久队列。[来源 7]

人工接管使用 Harness 的公开 Agent 取消接口停止本轮活动，并由共享服务立即撤销旧操作者的写入资格。服务拒绝晚到写入；停止与清理结果再回报页面。保留原会话与历史，不以销毁会话、杀掉整个宿主进程或清空画布作为接管方式。人工修改通过公开上下文机制在续作前交付，编辑期间不自动唤醒 Agent。

框架取消是需要执行方响应的机制，不会自动强制终止任意宿主代码。因此工具与服务必须及时处理取消，并在最终提交前再次核对写入资格；“旧 Agent 不再改变内容”不能仅靠取消信号或页面禁用来保证。

原生工具和 MCP 都不会自动带来全部音视频理解。当前官方图片附件链路可复用；音视频直接输入、分析形式与模型适配需分别核对。Agent 收到的“实际媒体内容”与名称、元信息、文本说明必须区分，不能把后者当作已经看过或听过素材。[来源 6]

提问界面与答案通道由 Harness 的用户提问能力负责；预设提供提问工具及使用指导。插件负责业务选项有效性、当前控制权和答案应用的最终校验。等待回答属于对话状态，不是画布控制权转移，也不等于媒体任务停止。[来源 8]

### 3.4 对象的唯一含义

| 对象 | 定义与边界 |
| --- | --- |
| 文件夹 | 插件目录中的一级分类。Agent 自动创建的文件夹与人工创建的文件夹使用同一套管理入口。 |
| 画布 | 节点、引用关系与媒体创作内容的项目载体；不等同于 Harness 文件工作区。 |
| 会话 | 用户与 Harness Agent 的对话。会话可关联创作画布，不改变文件工作区本身。 |
| 本轮创作 | 一条实际创作要求引发的操作序列；完成、失败、停止或接管都会结束本轮自动操作。 |
| 当前创作画布 | 本轮明确操作的目标。一个会话同一时刻只有一张当前创作画布。 |
| 控制权 | 决定当前谁可以修改画布内容与发起创作动作。作用于画布本身，不只作用于当前浏览器。 |
| 人工修改批次 | 人工接管后至下一次成功交回 Agent 之间，已经保存的人工操作集合。 |
| 媒体任务 | 一次生成、导入或视频结果制作；有独立状态与输出，不等同于 Agent 的回复。 |

**[产品判断]** 一个会话可以先后关联不同画布，但每次操作必须明确目标。用户要求新项目时新建；指定已有项目时读取并复用。自动创建多张画布或跨画布搬移素材须符合本轮要求，不作为每次对话的默认行为。

### 3.5 控制状态

| 状态 | 内容操作者 | 用户可以做什么 | 离开条件 |
| --- | --- | --- | --- |
| C-01 人工编辑 | 用户 | 编辑、生成、预览、保存；有关联会话时可请求 Agent 续作 | 续作同步完成后进入 C-02 |
| C-02 Agent 创作中 | 当前关联 Agent | 只读观察、查看任务、预览 / 下载、人工接管、在对话中停止 | 本轮结束进入 C-03；接管进入 C-04 |
| C-03 Agent 待命 | 保留会话关联，无正在执行的 Agent 创作 | 只读观察、发送下一条创作要求、人工接管 | 新创作进入 C-02；接管进入 C-04 |
| C-04 接管确认中 | 撤销旧 Agent 写入，尚未开放人工内容编辑 | 观察接管结果；不允许两方同时修改 | 确认写入已冻结、当前状态可用后进入 C-01 |
| C-05 续作同步中 | 暂无内容写入方 | 查看；等待已有编辑保存与上下文同步 | 成功进入 C-02；失败回 C-01 |
| C-06 状态待核对 | 暂无可确认的写入方 | 查看最后确认的内容、重新连接、核对状态 | 确认后回到实际控制状态，不能自动发起新生成 |

**[Assumption, TBD]** Agent 本轮完成后保持 C-03，只读待命，用户若要编辑仍点击接管；后续创作对话可以直接进入新一轮。这样避免任务结束瞬间无提示地改变画布操作含义。此规则待 D-06 评审，并非用户已经确认的完成后交互。纯人工使用不进入 C-03。

**等待用户回答：**属于当前会话的子状态，不新增操作者。已进入 C-02 的画布继续只读且可人工接管；进入创作前的澄清不会自动改变 C-01。用户回答本身不等于交回控制权，实际执行仍遵守 FR-08 与 FR-14。

### 3.6 操作权限矩阵

| 操作 | 人工编辑 | Agent 创作中 / 待命的用户 | 当前 Agent |
| --- | --- | --- | --- |
| 查看、平移、缩放、选择、预览、下载 | 允许 | 允许 | 可读取必要内容 |
| 改名、移动节点、编辑提示词 / 参数 | 允许 | 禁止 | 仅持有本画布控制权时允许 |
| 新建 / 删除节点、建立 / 解除引用 | 允许，遵守现有业务校验 | 禁止 | 同左，遵守本轮需求与业务校验 |
| 生成、重试生成、导入素材、编辑视频 | 允许，按能力与任务规则处理 | 禁止 | 同左；超出本轮授权范围时需用户新指令 |
| 修改目标画布所属目录 / 删除目标画布 | 按现有任务与目录规则 | 禁止 | 仅明确的用户管理要求；不能为清理流程自动删除 |
| 读取或更改密钥原文 | 不通过画布提供 | 不通过画布提供 | 不提供此能力 |

观察模式中的视口与选择只影响本人的查看状态，不持久化为对 Agent 的内容修改，也不触发人工接管。修改模型 / 存储配置沿用设置入口；改配置不会自动取得画布控制权，也不改变已提交任务的固定输入。

### 3.7 四条共享规则

**SR-01 单一操作者。**同一画布同一时刻只允许一方执行创作性写入。所有入口、旧请求、相关子 Agent 和延迟回调都服从当前控制关系；不能只把浏览器按钮禁用而仍接受后台 Agent 写入。另一个会话不能抢走正在创作的画布。

**SR-02 以已确认内容为准。**只展示实际成功的操作。已完成的节点修改保留；未执行的计划不画成完成结果。交接以最新保存状态为基线，不能通过旧整图覆盖当前内容。

**SR-03 Agent 停止与媒体任务分开。**接管立即终止 Agent 后续创作与回复。已在外部服务执行的媒体任务能否取消由服务能力决定，不能显示未经确认的“已取消”。具体处理见 FR-06。

**SR-04 人工修改先同步、后续作。**人工编辑期间不自动唤醒 Agent。继续创作前，自动提供已保存修改摘要与当前内容；失败则不交出控制权、不让 Agent 使用旧状态。

## 4. Agent 预设的交互与约束

### FR-01 安装后的能力入口与前置条件

**目的：**用户安装一次插件，即可选择手动创作或无限画布助手，不需要再手工安装一份预设。

**入口与行为：**

- **[已确认]** 插件提供自定义“无限画布助手”预设，随插件一起交付。预设描述清楚图片、视频、音频生成及视频编辑用途。
- 预设出现在 Harness 的可选列表中。**[产品判断]** 安装不擅自替换用户的新会话默认预设，也不改变已经开始的普通会话。
- 预设可以组合创作角色、工具与技能。Harness 官方支持通过插件组合包声明自定义预设；预设本身不等于已具备画布操作能力，相关能力必须一并交付。[来源 4]
- **[已确认]** 预设明确“创作引导者”的职责，并包含 FR-12 的通俗表达、需求补齐、专业程度适配与错误解释规则，不能只配置工具列表而忽略用户听不懂的问题。
- **[已确认]** 该预设只允许使用 FR-13 规定的多模态 Agent 模型；不能仅在提示词中推荐，而仍允许用户选择纯文本模型。
- 预设必须包含 FR-14 的原生提问工具与使用指导。宿主提问服务和 Web 应答界面就绪后，Agent 才能请求结构化选择；没有应答能力时不得声称已发出可操作卡片。
- 使用者仍在 Harness 会话中与 Agent 对话，插件不再增加另一套聊天窗口或独立账号。

**前置校验与反馈：**

| 条件 | 结果 |
| --- | --- |
| 未配置对象存储 | 目录和设置可打开；新建画布、导入和新生成被阻止，提供对象存储设置入口 |
| 未配置当前类型媒体模型 | 可讨论 / 整理已有内容；不能提交该类型生成，说明缺少什么配置 |
| Agent 模型不可用、非多模态或能力未确认 | 手动画布入口仍可用；禁止用该模型发送助手消息或开始 / 继续创作，引导选择或配置合格的多模态模型 |
| 视频 / 音频类型尚未接入所需能力 | 不显示虚假可用模型，不把模拟结果当真实输出；告知无法完成的部分 |
| 预设加载失败或被禁用 | 保留手动入口与已有数据；会话无法使用相应 Agent 能力，说明加载问题 |

用户只写入配置，画布与 Agent 只得到“已配置 / 未配置”和可用能力，不取得密钥原文。聊天模型用于理解与规划，媒体服务负责实际生成；二者配置职责保持明确。

### FR-02 人工画布创作

**触发：**用户从插件入口进入，选择或新建画布；未被 Agent 占用时为 C-01。

**处理与结果：**

- 人工创作使用插件已定义的业务能力，Agent 使用对应的受控工具；二者操作相同的项目、素材和成果。
- 人工意图由页面提交给共享服务；只进行观察的动作不触发创作，也不被误记为人工修改。
- Agent 接入不重新定义插件的媒体、保存和历史业务规则，具体功能随插件设计补充。
- 从其他窗口打开正在由 Agent 创作的画布，进入同一只读观察状态；要修改仍须通过 FR-06 接管。
- 纯人工画布没有关联会话时，不把操作记录发送给任意 Agent。用户明确在助手会话中选择该画布后，可把当前内容交给 Agent。

**例外：**保存失败保留草稿；存在冲突时不覆盖其他已确认内容；进行中任务相关操作遵守实际功能规则。控制权示意仅解释交接，不规定创作功能的界面。

### FR-03 对话创作自动准备目录与画布

**触发：**无限画布助手收到一条需要实际创作的用户指令，并已确定目标范围。

**处理顺序：**

1. 按 FR-13 校验 Agent 模型资格，再校验本轮需要的存储、媒体生成模型与素材能力。缺少配置先说明并引导设置，不创建一批无法执行的空项目。
2. 用户指定已有画布时先定位并读取；同名候选不能唯一确定时只澄清目标，不猜测并覆盖。
3. 没有另行指定目标时，默认复用本会话当前关联画布，包括上一轮已结束后说“继续”或追加修改要求。用户明确要求新项目时新建；没有关联、也没有指定目标时，才准备一个与需求相关的一级文件夹和新画布。名称由需求产生；未要求嵌套目录时不新建多级文件夹。
4. 自动打开当前对话的无限画布侧栏并定位目标画布，建立会话关联。
5. 取得该画布控制权，进入 C-02。Agent 可以开始节点创作，用户以只读状态观察。

**[产品判断]** 新建项目与用户已经明确要求“实际创作”的意图一起执行，不要求用户再次逐项确认创建文件夹和空画布。需要额外内容授权时按 D-03 处理。

**复用与边界：**

- 重复回执、重新连接或继续同一轮要求，复用已经确认的文件夹 / 画布，不重复创建。
- 没有实际创作要求的能力问答、只给方案或尚未选定目标的讨论，不自动创建。
- 当前目标已由另一会话创作时，本会话不能写入；用户可以打开观察并显式接管，或指定其他目标。
- 对话切换后侧栏显示该会话关联的画布；没有关联的普通会话仍使用当前列表入口。打开关联画布不代表自动恢复 Agent 执行。
- 会话关闭或删除不连带删除文件夹、画布、素材与任务。画布不存在时保留对话记录，说明关联失效，不自动重建原项目。

### FR-04 原生工具的业务调用边界

**触发：**Agent 持有当前目标画布控制权，且正在处理用户的实际创作要求。

**[已确认]** Agent 发出业务操作意图，由原生工具调用共享服务完成；Agent 不直接操作数据库、媒体目录或浏览器。工具用于表达插件允许的操作，而非提供任意执行通道。

每次调用应有清楚的输入约束和结构化结果。实际执行身份来自 Harness 的调用上下文，不能信任模型自行填写的身份或授权声明。服务先核对目标、能力与操作者，再处理业务；返回成功、拒绝、冲突或结果待确认等真实结论。

**处理规则：**

- 读取结果只包含该操作所需的内容；需要理解媒体时，通过受控媒体读取与适配提供真实内容。
- 修改由共享服务按实际功能规则校验，并返回已确认结果；未执行的计划不当作已保存内容。
- 重复调用核对同一次操作，不能重复产生项目或外部效果。响应不明时先核对，不盲目重做。
- 取消信号需要传递到可取消的工作；真正写入前仍核对控制权，不能只依赖取消通知。
- 工具失败不清空已确认成果；服务或预设不可用时明确停止相应能力，不绕过到数据库或浏览器。
- 用户素材与人工摘要是创作数据，不自动成为新的系统指令。面向模型的结果与面向用户的解释分别呈现，但采用同一事实来源。

工具名称、数量、每项操作的参数、返回字段、生成与编辑规则均待插件具体功能确定后补充。本节不预先列出一套尚未完成的创作工具清单。

### FR-05 只读观察与过程可视化

**布局：**Harness 对话负责说明需求和回复；右侧无限画布负责显示目录、目标项目、节点、引用、实际结果与任务入口。画布顶部常驻当前操作者及“人工接管”按钮；这不增加节点内部状态文字。

**[已确认]** C-02 中用户不能修改创作内容。编辑、拖动节点、连线、删除、粘贴建节点、文件拖入、生成和编辑视频等入口统一受限；键盘快捷键和其他窗口遵守相同规则。

**[Assumption, TBD]** C-03 也沿用上述只读规则，是否在本轮完成后仍须接管才能编辑，按 D-06 评审。本稿状态表与演示使用这一建议口径。

**观察行为：**

- 用户可平移、缩放、选择、查看输入、预览媒体、打开任务详情及下载已有结果，这些行为不结束 Agent 回复。
- 新节点、参数变化、引用和结果在实际确认后更新，不播放与真实操作无关的“假执行过程”。
- 正在执行的节点使用既有加载规范；任务阶段和错误说明可从任务详情 / 对话查看，不添加节点状态文字。[来源 2]
- **[Assumption, TBD]** 开始创作时让当前操作区域可见；用户主动平移或缩放后，系统停止主动移动其视口，后续仍更新内容。是否提供额外“跟随 Agent”按钮留待设计评审，不列为必选功能。
- 默认不自动播放产生声音的内容。用户明确点击播放后，沿用当前媒体播放规则。
- 窄侧栏仍可看到操作者和接管入口；折叠面板不改变控制权。用户可以通过 Harness 对话停止当前轮次。

**可观察的事实：**对话可以说明“正在准备参考素材”“等待视频任务”等阶段，但不能虚构百分比、费用、预计耗时或成功状态。

### FR-06 人工接管与强制停止

**触发：**用户在关联画布中点击接管按钮。按钮建议文案为“人工接管”；用户本轮所说“人工托管”按“用户取得操作权”的意图处理，最终文案见 D-06。

**[已确认] 接管规则：**

1. 正常连接时，点击按钮立即触发本轮及相关子 Agent 的强制停止，同时停止本页旧回复增长与创作增量，显示 C-04。不能先等待接管确认，再开始发送停止要求。
2. 宿主收到接管请求立即撤销旧 Agent 对本画布的写入权，终止所属会话本轮回复、相关子 Agent 创作以及尚未执行的后续步骤。停止处理不能排在普通创作步骤之后，C-04 只用于核对冻结结果与最后已提交内容，不是允许 Agent 继续执行的窗口。
3. 不等外部媒体生成结束。写入已冻结、最后确认的内容可用后，进入 C-01，用户立即可以操作。
4. 接管前已确认的节点与修改保留；未确认请求核对后只采用真实结果，不回滚整轮创作，不清空任务或素材。
5. 对话保留此前回复，标记本轮因人工接管而结束；旧文本不继续增长，不自动追加“继续执行”回复。

接管发生在等待用户回答时，同样立即触发停止并取消本轮等待；不能等用户先完成回答才允许接管。原问题和已提交答案可作为历史事实保留，尚未提交的选择不是授权。迟到提交或恢复旧提问不得继续旧创作，按 FR-14 核对后续新要求。

“立即停止”要求从接管生效时阻止新动作和回复；不得等模型整段回答、下一个普通步骤或整条媒体链结束才停止。断线时无法假装宿主已收到请求，按 FR-11 显示待核对状态。

**接管瞬间的不同事项：**

| 事项 | v0.2 处理 |
| --- | --- |
| 已成功的画布修改 | 保留，成为人工编辑起点 |
| 未开始的 Agent 图操作 / 下游步骤 | 不再执行；晚到回调不得恢复操作 |
| 本轮相关子 Agent | 同时失去本画布写入能力；不能在父 Agent 停止后继续写 |
| Agent 生成已排队，但尚未发送给外部服务 | **[Assumption, TBD]** 停止派发，保留已停止的记录，不新增外部调用 |
| 外部已接受的生成 | **[Assumption, TBD]** 继续追踪与保存原结果，不自动启动下游；是否主动调用取消由 D-04 明确 |
| 提交是否被外部接受不明 | 标记待确认，核对原任务，不当作取消成功或自动重提 |
| 接管前已提交的本地编辑结果制作 | **[Assumption, TBD]** 可取消且未产生结果时停止；已完成结果保留，晚到结果只归原任务 |
| 其他画布、其他会话、用户手动提交的任务 | 不被本次接管停止 |

**晚到结果：**仍归属于原任务，可在原节点历史或任务详情查看。不得自动修改人工的新输入、重建已删除节点、切换人工选定的结果、建立新连线或继续下游。用户可以主动引用该结果。

**失败与重复点击：**重复接管不重复结束回复或创建人工批次。无法确认旧写入已冻结时不开放两方同时编辑；保留只读内容并展示原因，用户可以重连核对或使用 Harness 的停止入口。

### FR-07 人工操作自动转换为文本

**触发：**人工接管后，用户完成一项创作性修改且保存成功。记录归属于当前画布与人工修改批次；不要求用户逐次录入操作说明。

**摘要依据：**以已保存修改和真实结果为依据；自动摘要不能因为模型推测而补出用户未做的动作。记录既保留必要过程，也提供当前有效改动，供续作使用。

| 人工操作 | 转换成的语义信息 | 不应记录成什么 |
| --- | --- | --- |
| 新建、删除、改名节点 | 类型、对象身份、名称变化及关联影响 | 用户删除了不相关的整套项目 |
| 修改提示词 / 模型 / 参数 | 对象身份、旧值与新值或必要变化片段 | 把历史任务参数改成了新值 |
| 新增 / 移除引用 | 源素材、目标节点、输入关系 | 仅凭节点相邻位置推测引用 |
| 手动上传或提交生成 | 新素材或任务的真实身份、输入概要与最新状态 | 把未结束生成写成已完成 |
| 更换使用的结果 | 明确选用的素材与受影响目标 | 仅预览另一结果就改写下游引用 |
| 后续新增的创作 / 编辑操作 | 按已定义功能记录对象、输入变化与确认结果 | 从尚未定义的编辑能力臆造用户操作 |
| 移动节点 | 合并同一次拖动为一次布局变化 | 每一帧鼠标位置都变成一条对话 |
| 观察、选择、视口变化、播放 / 下载 | 不作为创作修改；必要时另提供当前选择上下文 | 无意义的海量操作消息 |

**合并与撤销：**

- 连续输入与同一次拖动在语义完成时合并，保留重要最终值；不把每个按键或每帧运动发给 Agent。
- 撤销 / 重做按最终保存状态反映。没有提交生成等外部效果的“创建后删除”可在净变更摘要中合并为无有效新增。
- 已发起任务、导入和产生结果等外部事实不能因后来删节点或撤销输入而从摘要中消失。
- 保存失败的本地草稿标注尚未保存，不进入“已完成修改”摘要；续作前必须先处理保存问题。

**可见性与交付：**在关联会话提供“人工修改摘要”的查看位置；用户不需要复制粘贴。人工编辑期间不把每条记录作为新用户消息发送，也不自动开始回复。成功交接时，未同步批次作为上下文一次性送入，保留与会话的关联证据。

**示例（仅说明摘要表达）：**“人工接管后，用户修改了项目内容，已保存；本轮新要求尚未执行。继续前请读取当前项目，并保留人工已经确认的修改。”实际摘要必须记录真实对象和变化，不能使用此泛化示例代替实际操作事实。

密钥、签名链接、鉴权请求、未经需要读取的宿主文件内容不进入摘要。长文本保留必要变化及完整内容的可读取对象引用；不得静默截掉影响续作的参数、素材或未完成任务。

给 Agent 的上下文保留识别对象所需的身份信息；用户可见摘要优先使用素材名称和改动效果。不能把一串内部 ID、接口字段或编辑对象结构直接当作面向普通用户的解释。两种表达来自同一份已确认操作事实。

### FR-08 用户继续对话，Agent 接着创作

**触发：**处于 C-01 的用户在关联会话提出“继续”“按我刚才的修改接着做”等实际创作要求。C-03 中追加创作要求时，按 FR-03 默认复用当前关联画布，并重新读取真实状态；没有人工修改批次时无需伪造一份人工摘要。

**交接顺序：**

1. 保留用户的新要求，先按 FR-13 校验多模态 Agent 模型；不合格时保持人工控制并提示更换。通过后进入 C-05，短暂阻止新的内容修改。
2. 等待当前编辑保存，读取最新画布、素材可用性、编辑内容和任务状态。
3. 生成并同步尚未交付的人工修改摘要，明确区分人工操作、系统任务结果和用户本次新要求。
4. 确认这些上下文已供本轮 Agent 使用后，交回控制权，进入 C-02，自动打开 / 定位目标画布。
5. Agent 根据当前状态续作，保留人工明确选用的内容；需要改变用户修改时，应能解释与新要求的关系。

**交接约束：**

- 同一已成功同步批次不重复伪装成新操作；摘要不能替代读取当前真实画布。
- 用户只询问“生成到哪一步了”“我改了什么”等信息时，可以回复查询结果，但保持 C-01，不自动开始创作性写入。
- 用户继续输入人工修改时，尚未成功交接的旧摘要不能抢先触发执行；本次续作必须基于实际冻结后的状态。
- 保存失败、摘要同步失败、目标冲突或断线时保留 C-01 或进入 C-06；新要求保留可重试，不用旧状态开始。
- 正常接管与续作使用同一会话。历史上下文压缩后，人工修改和最新项目状态仍须可供当前创作读取。
- 没有有效关联会话时，不把摘要发给其他会话；由用户明确选择助手会话与目标，再执行交接。
- 被接管取消的旧提问不能作为自动续作入口。用户的新要求可以重新使用仍有效的明确偏好；必要选择已失效时重新提问，不能重放旧调用。

重复发送、重连或收到晚到回执时，不能据此重复创建画布或付费生成。交接成功回执与任务创建不明的恢复分别处理。

### FR-09 具体创作功能的后续补充边界

**[已确认]** 图片、视频、音频生成与视频编辑属于产品方向。Agent 通过插件已实现的能力创作；本次先确定架构，不定义具体功能清单。

待插件功能确定后，逐项补充人工行为、Agent 可调用范围、输入 / 输出语义、失败与取消规则、模型和媒体支持范围。只有完成这些定义与实现的能力，才能注册为预设可用工具或在指导中宣称可用。

具体媒体操作、编辑动作、参数范围、界面与工具契约当前均为 **[TBD]**，不在本次通过示例演示提前确定。

### FR-10 结果交付与本轮结束

**触发：**本轮目标完成，或因明确失败、停止、接管而结束。

- 只有媒体文件实际可用，才能称对应输出已完成。已生成但尚未保存、不可播放或缺失的文件，不能作为成功交付。
- Agent 回复指明完成的内容、所在画布 / 节点、仍在执行的任务和未完成原因。只交付计划或创建了空节点时，不回答“视频已完成”。
- 用户可从同一画布预览、下载或引用具体结果；对话中的定位入口与实际对象一致。
- 图片、视频、音频以及编辑结果保留明确的输入与所属任务。引用具体素材，不因最新结果出现而改变已有引用。
- 正常结束进入 C-03；人工接管结束按 FR-06 进入 C-01；失败仍保留已有成果，可接管或提出新的处理要求。
- 失败恢复优先查询或保存原任务结果；需要作为新任务重新生成时，按本轮授权范围和现有不明任务规则处理。

完成条件不包括自动公开发布或自动删除中间素材。

### FR-11 关闭、断线、冲突与恢复

**[Assumption, TBD]** 沿用当前“关闭侧栏不取消已接受媒体任务”的原则。用户主动隐藏 / 关闭画布时，不在每次进度变化后反复抢回面板；下一次实际对话创作或续作再自动打开。当前 Agent 是否在关闭对话标签后继续由宿主执行，以 Harness 行为与 D-05 确定，不能由插件另行假定。

| 情况 | 保留的内容 | 可见反馈与下一步 |
| --- | --- | --- |
| 用户接管时断线 | 最后确认内容、接管意图与任务身份 | C-06；说明接管尚未确认，不开放可能冲突的写入；重连核对 |
| Agent 写入失败 / 请求超时 | 已成功的修改与原请求结果线索 | 核对是否已执行，不自动重新提交不明生成 |
| 人工保存失败 | 当前草稿与此前已保存修改 | 不交回 Agent；展示保存失败并允许重试 |
| 续作摘要传递失败 | 人工批次与新的创作要求 | 保留人工控制，重新同步，不重复已确认的批次 |
| 多窗口 / 多会话冲突 | 最新确认内容、各自未保存草稿 | 当前操作者才能写；不按最后到达的整图覆盖 |
| 人工修改期间原任务完成 | 原任务输出与当前人工内容 | 更新原任务 / 结果历史，不恢复 Agent 或执行下游 |
| 重新打开侧栏 / 刷新浏览器 | 关联画布、已保存内容、任务与控制状态 | 显示真实状态；不能重复创建项目或提交生成 |
| Harness 重启 | 已保存项目与任务 | **[Assumption, TBD]** 先核对关联和未结束任务，默认不自动恢复 Agent 创作；用户明确续作后交接 |
| 关联画布已删除 / 不可访问 | 会话与已留存的历史事实 | 说明目标失效；用户重新指定，不自动复建 |
| 模型、对象存储或资源不可用 | 输入、编辑草稿、已有结果 | 说明具体缺口；修复配置后按当前状态继续 |

**[Assumption, TBD] 重启后的控制落点（D-05）：**核对未完成时统一为 C-06。核对后，已确认的人工控制恢复 C-01，并保留未同步修改批次；原 Agent 创作已中断、未发生人工接管的画布转 C-03，不自动恢复回复或操作。中断的接管在确认旧写入已冻结后完成为 C-01；中断的续作若尚未交出控制则回 C-01，若已经交出但本轮因重启停止则到 C-03。交接结果仍不明时继续 C-06，不能猜测执行或重复提交。C-03 的只读待命口径仍待 D-06 评审。

恢复不能把“旧 Agent 已停止”变成“自动重放它尚未执行的全部步骤”。接管后的内容优先，系统任务状态独立核对。

### FR-12 Agent 预设的用户引导与表达规则

**目的：**让普通用户能说清想要的内容、理解正在发生什么并完成创作；让专业用户保持表达精度和操作自由。此要求属于 v0.2 必须交付的预设行为。

**触发：**需求收集、创作方案、必要选择、进度说明、错误处理、人工接管提示与续作确认，均使用本规则。

**专业程度适配：**

- **[已确认]** 用户没有表明熟悉程度时，默认用通俗、简洁的话，不预设用户懂画布、模型或视频编辑。
- 用户表达“不懂”“不会剪辑”等情况时，Agent 承担引导，先围绕用途和想要的效果提问，不要求用户填写一串专业参数。
- 用户给出专业术语与明确参数，或要求精细控制时，准确沿用这些表达，不强行换成模糊说法，也不重复科普其已经理解的内容。
- 尊重用户本次“简单说”“给我详细参数”等要求；不能把熟悉程度当作固定身份。同一用户可以在不同任务中选择不同交互深度。

**需求补齐：**

- **[产品判断]** 先理解用途、主要内容、已有素材和希望得到的结果；只问当前最影响下一步的问题，避免一次抛出一长串表单式问题。
- 对不懂的选择，先解释它怎样影响成品，再给容易比较的选项；能采用可逆默认值时，说明默认安排及可以怎样修改。
- 信息足够时，Agent 说明准备做什么并继续完成，不要求用户为理解工具流程先学习节点或连线。
- 仍遵守 FR-01 的能力限制与 D-03 的生成授权范围。引导不能把未确认的额外生成、付费重试或内容方向包装成用户已同意。
- 需要用户回答后才能决定下一步时，使用 FR-14 的原生提问卡片；普通解释与进度说明直接回复。不能每句话都变成提问，也不能重复索取用户已经明确提供且仍有效的信息。

**用词与解释：**

| 场景 | 面向普通用户的表达原则 | 面向专业用户的表达原则 |
| --- | --- | --- |
| 说明方案 | 说“先做画面，再配介绍声音，最后合成视频”，解释产物与顺序 | 可描述分镜、画幅、片段、音轨、引用素材与具体参数 |
| 询问设置 | 先问用途或发布场景；必要时解释“横着看 / 竖着看”等影响 | 沿用用户指定比例、时长、分辨率等，校验服务是否支持 |
| 解释过程 | 说正在准备哪部分、哪部分已经完成、什么还在等待 | 可补充准确任务阶段与依赖关系，不虚构进度 |
| 引导接管 | 说“点画布上的‘人工接管’，我会停下来，你可以直接修改” | 明确停止本轮操作与交接边界，可保留简洁专业说明 |
| 续作说明 | 说出已看到的人工改动和接下来会怎么做 | 准确说明片段、素材、参数或引用的变更 |
| 错误提示 | 说明哪里出了问题、已有成果是否保留、下一步做什么 | 默认也先给可操作解释，用户需要时再提供脱敏技术细节 |

**禁止的默认表达：**不能只回复接口错误码、内部工具名、节点 ID、请求结构或未解释的术语；不能要求普通用户先“配置 DAG”“构建工作流”“传入 asset_id”才继续。需要定位画布对象时使用用户看得见的名称。

**话术示例（用于预设评审，不是固定脚本）：**

- 普通用户：“我想给新开的咖啡店做个宣传视频，但我不会剪辑。”Agent：“可以。我来帮你做画面、配上介绍声音，再合成视频。你最想展示店里的什么？”
- 专业用户：“做一条竖版 9:16 的产品视频，保留我选好的片段和旁白。”Agent：“按 9:16 组织成片，保留你已选的片段与旁白。我会先检查素材和模型支持范围，再继续后续画面。”
- 普通用户看到生成失败时：“这次图片没有生成成功，已经完成的内容都还在。图片服务的密钥可能无效，请到模型设置更新后再试。”只有明确的鉴权错误才使用这类原因，不能猜测失败原因。
- 用户接管后续作时：“我看到你换了封面画面，并把第二段放到了前面。接下来我会保留这些修改，继续完成旁白和成片。”这句话必须来自真实人工修改，不能臆造。

**可观察结果：**普通用户不必自行操作画布也能完成对话创作；有必要操作时知道点哪个入口、会发生什么。专业用户的明确参数与素材决策得到保留。用户表示不理解时，Agent 换一种更简单的解释并继续引导，不原样重复难懂的回复。

### FR-13 多模态 Agent 模型选择与资格校验

**[已确认] 目的：**无限画布助手需要理解媒体素材并帮助用户创作音频、图片和视频，必须使用多模态模型；在该助手的对话模型选择器中，用户只能选择合格的多模态模型。

**适用范围：**选择无限画布助手预设的新会话、已有助手会话的模型切换、默认模型继承、会话恢复与人工接管后的对话续作。该限制属于此预设的模型资格，不改写其他 Harness 预设的模型选择规则。

**模型资格：**

- 多模态资格指 Agent 对输入媒体的理解能力，须有已确认的能力依据；不能只凭模型名称、支持工具调用或能够生成图片判定。
- 图片、音频、视频的具体输入支持范围分别说明。任务需要的媒体理解能力不可用时，保留素材并说明缺少的能力，不把省略媒体后的文字推测当作已理解素材。
- 能力未确认的模型暂不可选，不能按“可能支持”放行。首批模型清单及各类媒体输入的确认口径见 D-07；禁止非多模态模型是已确认规则，不属于待评审建议。
- Agent 对话模型负责理解与规划；图片、视频、音频生成服务继续使用各自的媒体模型配置。两类模型各自校验能力。

**选择器与异常行为：**

| 情况 | 用户可见行为与处理 |
| --- | --- |
| 已配置且能力确认的多模态模型 | 允许选择，注明已确认的媒体输入支持范围 |
| 非多模态 / 纯文本模型 | 在选择器中禁用并说明原因；点击、搜索结果、键盘选择均不能选中 |
| 多模态能力未确认 | 禁用，说明“暂未确认媒体理解能力”，提供查看 / 配置能力的入口 |
| 没有可用多模态模型 | 不填入纯文本后备项；发送与继续创作不可用，提示选择或配置多模态模型；手动画布与已有成果保留 |
| 继承的默认模型或恢复的旧选择为纯文本模型 | 不沿用为有效选择；提示重新选择，保留会话、输入和画布，不自动改用另一模型或重新生成 |
| 用户切换到不合格模型 | 拒绝切换，保留此前仍合格的模型和已有内容；不因为拒绝选择而改变当前控制权 |
| 已用模型后续失去合格能力 | 阻止新的助手请求与创作操作，保留输入、已确认成果及原媒体任务；换成合格模型后按当前状态继续 |

**统一校验：**模型选择、发送助手消息、开始创作、会话恢复后的首次请求、模型切换和人工修改交回 Agent 前，使用同一资格规则。不能只在界面置灰而接受其他路径传入的非多模态选择；本轮暂时只有文字内容，也不解除该预设的资格限制。

**面向普通用户的提示示例：**“这个模型只能处理文字，无法看懂图片等素材。请换成多模态模型，再让画布助手继续。”没有合格模型时说明去哪里配置，不仅显示技术性的能力字段。

**结果：**助手会话始终以合格的多模态模型发起新请求；模型资格问题不造成画布、素材或人工修改丢失，也不能导致隐式回退到纯文本模型。

### FR-14 原生用户提问、选择与答案应用

**目的：**Agent 缺少必要信息、需要用户选择或决定时，使用 Harness 已有的 `ask_user_question`，在所属会话中收集结构化答案，再按真实结果继续。本节定义预设使用规则，不提前定义具体媒体工具。

**接入与模式：**

- 预设的子插件列表加入 `@deepseek-ai/dsh-tool-ask-user`；宿主须提供 `ctx.userQuestions`，Web 须加载 `@deepseek-ai/dsh-client-ui-user-questions`。工具、服务、应答界面缺少任一项时，报告不可用并阻止依赖答案的动作。
- **本版采用默认阻塞模式 `legacy`。**需要答案时等待用户提交或取消，不设置自动超时续作；普通工具参数不包含 `timeout`。
- 预设配置示意如下，属于该预设的子插件列表，不是独立顶层覆盖项；此示意不会修改当前 Harness 配置：

```yaml
- id: tool-ask-user
  name: '@deepseek-ai/dsh-tool-ask-user'
  config:
    mode: legacy
```

- Harness 的 `timed` 模式是可另行启用的能力，本版不默认启用。后续若采用，必须区分 `pending` 与已回答，明确迟到回复与接管规则；必要决定可无限等待，有限超时绝不表示批准。[来源 8]

**什么时候提问：**

- 用户未给出的信息会改变当前创作方向、目标项目、需要使用的能力或新增调用授权，且没有有效既定选择时。
- 用户明确要求自己选择模型或方案时，先取得实际候选，再请求选择。
- 信息已足够、用户已明确给定选项，或只需报告进度时直接处理，不增加重复确认。
- 只问当前最影响下一步的问题；相关的小组问题可以一次提出，避免普通用户面对冗长专业表单。
- 存活的子 Agent 不直接向用户提问；将未解决的决定交回主 Agent，由所属会话的主 Agent 统一发起。

**工具参数约定：**

| 字段 | 规则 |
| --- | --- |
| `questions` | 非空问题列表；本版预设不得发空调用 |
| `id` | 每个问题必填；同次调用内唯一，用于对应答案，不用问题顺序猜测 |
| `question` | 必填，说明要用户决定什么；符合 FR-12 的理解程度与语言 |
| `header` | 可选，简短标题，不放内部 ID 或接口字段 |
| `options` | 可选；有选项时使用可辨识的标签与说明，纯文本问题可以省略 |
| `options[].label` | 短标签；同一问题中保持不同，返回时按完整标签识别 |
| `options[].description` | 可选，解释选择的影响；只描述已确认能力，不虚构速度、费用或效果 |
| `multi_select` | 默认 `false`；只有可同时成立的选择才设为 `true` |

推荐选项放在首位，标签末尾可加 `(Recommended)`。推荐标记及界面预选只表示建议与草稿，**用户提交前不视为已选择或已授权**。不要另加未被工具声明的 `value`、回调或执行脚本来控制业务。

**调用示例：**以下 JSON 是 `ask_user_question` 的参数；Agent 必须发起真正的工具调用。把同样文本输出在普通回复或代码块中不会产生可回答卡片。例子仅说明协议，不指定具体创作功能。

```json
{
  "questions": [
    {
      "id": "creative_direction",
      "header": "创作方向",
      "question": "你希望这次内容更接近哪种风格？",
      "multi_select": false,
      "options": [
        { "label": "写实", "description": "画面接近真实拍摄。" },
        { "label": "插画", "description": "画面采用绘画风格。" }
      ]
    }
  ]
}
```

**界面与等待：**Harness 在聊天输入框旁展示提问卡片，支持选项、自定义文本与跳过；提交后返回答案，已结束问答可在对话记录中回看。此展示来自原生工具及应答界面，不要求插件另建问答窗口。问题与选项文字由 Agent 产生，外框文案由宿主负责。

默认阻塞提问期间，当前 Agent 不开始新的创作操作；依赖此答案的操作尚未执行。已接受的媒体任务仍按原生命周期追踪。等待不自动解除只读状态，也不自动取得人工控制画布的权利；接管入口始终可用。

**答案读取与业务执行：**

```json
{
  "answers": [
    { "id": "creative_direction", "selected": ["写实"] }
  ]
}
```

- 按 `id` 对应原问题。`selected` 是完整选项标签数组；`custom` 是可选的用户文本。单选自定义答案与选项互斥，多选允许同时有已选标签与补充文本。
- 跳过返回空 `selected` 且无 `custom`，表示没有决定。必要问题未回答时，不执行其依赖动作；保留已有内容并说明还缺什么，不能自动采用推荐项，也不能无休止重复同一提问。
- 回答确认后，先核对问题仍属于当前要求、目标和操作者，再读取最新业务状态。答案只是一份输入，服务仍负责能力、引用、任务和权限校验。
- 模型选择选项来自当前已配置、可用的候选，并保留提问时标签与真实模型身份的对应关系；回答后再次校验。候选被删除、配置改变或对应关系不明确时，不猜测、不静默换模型，说明情况并按需重新提问。
- 提问工具本身不切换模型、不提交生成、不创建画布。选择媒体生成模型仍由对应业务能力执行；涉及 Agent 对话模型时必须遵守 FR-13，不能借自定义答案绕过多模态限制。
- 一份已确认答案只应用一次；重复回执或跨窗口重复提交不引发重复生成。无法确认答案是否已提交或操作是否执行时先核对。

**关闭、取消与过期：**

| 情况 | 预设与插件的处理 |
| --- | --- |
| 预选、正在输入但未提交 | 没有确认答案，不执行依赖动作 |
| 用户跳过必要问题 | 保留已有成果，相关动作不执行；等待后续明确要求 |
| 用户关闭卡片 | 关闭不等于回答或同意；按宿主返回的隐藏 / 取消状态处理，不自行推进 |
| 用户停止或人工接管 | 取消本轮等待与后续动作，旧问题不再有继续创作的授权 |
| 提问工具失败或没有可用应答界面 | 解释缺口，可使用普通对话取得新的明确信息，但不能声称已收到卡片答案，也不能绕开程序校验 |
| 断线、重启或恢复旧会话 | 先核对原问题和控制状态；默认阻塞提问不承诺中断后可接受迟到答案，不自动重放 |
| 接管后出现迟到答案 | 不恢复旧 Agent、不重新取得写入权；只能作为新输入核对，需明确续作并执行交接规则 |

提问与回答不是通用升权机制。涉及实际新增调用或修改权限的决定，除明确答案外仍需遵守该业务的既定授权边界。答案草稿、跳过、超时、错误与取消均不形成授权。

**预设必须遵循的指导：**需要必要信息时调用 `ask_user_question`；问题通俗且尽量少；依据实际候选给选项；等待并按 `id` 读取答案；确认最新状态再应用；没有明确答案就不做依赖动作；发生停止或接管就结束旧等待；不得借回答绕过模型资格或控制权。

**实现核对场景：**应能在真实 Harness 中验证工具可见及卡片可回答、选项与自定义文本返回、跳过不推进必要动作、接管取消等待、晚到答案不续作、模型失效不切换、重复提交不重复执行。本文只定义这些要求，不把文档示意当作实际实现已通过。

## 5. 本版共同沿用的规则

以下规则影响两种入口，统一执行，不因调用者是 Agent 而放宽。

- **素材与输入一致性：**连线引用具体素材；新生成不会改变旧引用；无文件、格式不符、数量超限或依赖不合法时拒绝作为输入。
- **能力真实：**只显示已配置并已接入的生成能力，参数按对应模型支持范围提供；不以示例选项或模拟输出宣称可用。
- **Agent 模型资格：**无限画布助手遵守 FR-13，只能使用合格的多模态模型；选择器和实际请求入口采用相同限制。
- **提问与答案：**按 FR-14 使用原生工具；只对明确已提交且仍有效的答案执行相应动作，旧问题不能覆盖人工接管后的控制状态。
- **任务身份：**输入在提交时固定；不明是否提交成功时核对原任务；重试保存原结果不变成重新付费生成。
- **结果保留：**失败、接管或修改草稿不清空旧结果；删除节点不自动清理媒体或其他节点。
- **目录边界：**沿用一级文件夹；文件夹非空、画布存在未结束任务等管理限制按有效业务规则处理。
- **密钥边界：**配置写入与脱敏展示沿用当前设置；密钥和私有访问凭据不出现在节点、对话、摘要或常规错误详情。
- **加载与主题：**沿用既定节点加载与 Harness 主题规范。控制权提示放在画布级区域，任务详情负责解释状态，不重复增加节点状态文字。
- **保存兼容：**现有画布、媒体、结果与任务身份保留。新增会话关联与操作者记录的具体数据设计属于后续技术设计，本 PRD 不指定数据库表、接口或取消实现。
