# 节点与素材统一 # 引用方案 v0.1

文档类型：设计提案；负责人：项目维护者 / 开发执行者；最近核对：2026-11-03。

状态：已批准并按0.2.112实施；正式契约与边界见[ADR-0085](../adr/0085-node-and-media-chat-references.md)，检查及本机安装证据见112manifest与[验证记录](../verification.md)，用户手验401–407。可点击的产品说明仍为静态[交互方案](canvas-node-and-media-references-v0.1.html)，不代表实际插件运行。

## 1. 需求与推荐决定

用户要通过#明确本轮讨论或操作的节点，并让Agent了解这个节点的输入、输出与关联关系；“帮空节点编写提示词”是其中一个场景。聊天中的节点引用只显示节点名称。图片 / 视频 / 音频的精确引用、当前画布优先、分类层级和原生@文件入口继续保留。

推荐采用“按节点组织，两种引用身份”的统一目录：

| 引用对象 | 含义 | 读取时的内容 | 聊天标签 |
| --- | --- | --- | --- |
| 节点 | 讨论 / 操作的对象，按canvasId + nodeId定位 | 节点当前配置、当前输出摘要、直接上游的准确连线素材、直接下游摘要 | 仅节点名称，例如#镜头02 |
| 素材 | 确定的一份输入或生成结果，按assetId定位 | 原图片真实字节，或视频 / 音频的原元数据及用户反馈 | 保留名称、类型、结果区分，例如#镜头01 · 视频 2 |

节点引用以当前节点状态为准；素材引用固定那份原始结果。选择节点不会自动引用它所有历史素材，选择某张图也不会自动把其所属节点变成本轮修改目标。

## 2. 统一候选目录

保留现有“分类 → 画布”导航及当前 / 最近编辑排序。进入画布后按现有graph.nodes顺序组织候选，不另造节点编辑时间。

```text
当前分类 · 当前画布
  ◇ 人物设定                 图片生成 · 引用节点       › 素材
      图片：当前展示结果      引用素材
  ◇ 镜头01                   视频生成 · 引用节点       › 素材
      视频：当前展示结果      引用素材
  ◇ 镜头02                   视频生成 · 尚无结果
  ◇ 配音                     语音生成 · 引用节点       › 素材
      音频：当前展示结果      引用素材
其他分类                     点击进入
```

已批准的产品决定：

1. 节点名称行的点击 / Enter插入节点引用；右侧素材箭头 / Tab打开这个节点的素材目录。当前原生MenuView和InputTriggerController支持pick / drill双动作，可复用。
2. 有可用素材时，节点下面直接显示当前展示的那一份，可一步选择；避免把原来常用的当前素材引用藏到多级目录。没有结果时只有节点行，仍可引用。
3. 素材目录按“节点素材”组织：资源节点显示绑定的原素材；生成节点显示最近一个有结果批次的全部堆叠，再按任务分组显示历史批次。本次结果展开，历史批次默认收起；顺序沿任务 / resultIds定义，不用assets尾项推断。
4. 素材在一处标为当前展示，其余同批结果和历史结果明确区分。同一assetId在同节点素材目录去重。返回面包屑不丢当前画布偏好。
5. 关键词匹配当前展开画布的节点名称及素材标签 / 文件名。历史素材命中时直接给出准确素材行并保留所属节点，不能只返回父节点让用户再次猜结果。
6. 继续使用现有200条候选上限，但增加可继续浏览的入口和对应游标；不能截断后让后面的空节点或历史素材永久不可选。分页需保持分组与稳定顺序，图修订变化时重置游标、保留关键词。分类元数据保持完整。
7. 不回归工作区文件分组；@仍处理Harness文件 / 会话引用，画布节点prompt中的@仍由原图边和素材token支撑。

没有选择“节点 / 素材”两个互相独立的大列表，因为同一生成节点会被重复罗列，堆叠 / 历史归属不直观。也没有采用只显示节点并隐藏当前素材的方案，因为会增加原素材快捷选择的步骤。

## 3. 节点类型与结果规则

| 节点类型 / 状态 | 节点可引用 | 素材候选 |
| --- | --- | --- |
| 图片 / 视频 / 音频资源节点 | 是 | 绑定的实际assetId；待上传或不可用时不提供虚构素材 |
| 图片 / 视频生成节点，尚无结果 | 是 | 无素材，不阻挡讨论、改名、配置、提示词等现有操作 |
| 图片 / 视频生成节点，单个结果 | 是 | 当前展示素材直接可选 |
| 图片 / 视频生成节点，一批多个结果 | 是 | 当前展示一份直接可选；素材目录包含该批全部结果 |
| 图片 / 视频生成节点，有历史 | 是 | 最近有结果批次及按任务组织的原历史，不替换旧assetId |
| 语音生成节点 | 是 | 同样按实际任务结果显示音频；不增加输入连线 |
| 生成中 / 失败 / 保存失败 | 是 | 节点状态可读；只展示实际已可用结果，不产生占位assetId |

“当前展示”必须复用画布现有预览规则：资源节点assetId；生成节点在nodeResults结果内匹配selectedResultId，找不到则取该批第一份。当前候选实现的assets.at(-1)不能当新方案真源。新任务未产生结果时保留既有可用批次，结果目录按真实任务身份组织。

## 4. Agent应获得的上下文

聊天界面保持短标签，Agent读取时获得以下结构化上下文：

| 内容 | 范围与用途 |
| --- | --- |
| 目标节点 | 实际canvasId / nodeId、当前名称、类型、prompt、参数、公开模型信息、最新graphRevision |
| 当前输出 | 当前展示assetId、可用同批结果 / 历史数量、任务阶段摘要；不是全部历史二进制 |
| 直接上游 | 每条edgeId / sourceNodeId / assetId，源节点名称 / 类型、素材类型及可用性；视频输入用途沿现有参数解释 |
| 直接下游 | 每条edgeId / targetNodeId / assetId，目标节点名称 / 类型；说明下游实际使用本节点哪份结果 |
| 关联变化 | 以本次读取的修订为准，写入前重新核对；不可把历史读取当成当前授权 |

**上游素材以edge.assetId为准。** 上游节点显示v2但连线绑定v1时，Agent应知道输入仍是v1；用户更新节点输出不自动重连下游。下游也按其原edge.assetId解释，不能把“改了提示词”说成“下游已更新”。

默认返回直接上下游。更远的依赖按任务需要继续读取，不自动递归加载整张图、不自动下载全部素材。图片理解按需求进入现有真实多模态附件通道；视频 / 音频继续提供元数据与用户反馈，不声称已观看或聆听。

## 5. 意图与操作范围

节点引用明确对象，用户自然语言明确动作。Agent应先读取节点引用，再结合本轮文字识别操作、目标和参考对象。

| 用户输入示例 | 默认处理 |
| --- | --- |
| #镜头02，改成5秒并保留人物一致性 | 镜头02为编辑目标，核对其上游原人物素材和现有模型能力，修改允许的参数 |
| #镜头02，帮我补完整提示词 | 读取节点现有配置与上游真实素材，默认中文；保留本轮未要求改变的配置 |
| #镜头01，解释它现在用了哪些参考 | 只读该节点输入关系与确切素材，不修改图 |
| 参照#人物设定，把#镜头02改得更统一 | 依据措辞把人物设定作为参考、镜头02作为目标；不自动改人物设定 |
| #镜头02，按这个准备生成 | 按原模型选择 / 参考校验 / 人工生成交接流程准备，图片 / 视频不由#触发付费生成 |
| 多个引用，仅说“改一下” | 当动作或目标仍有实质歧义时简短澄清，不凭引用顺序猜目标 |

默认写入范围仅明确要求操作的节点。上下游用于理解影响，用户明确要求联动修改时才扩展范围；逐个节点仍须独立校验权限和图修订。引用不增加新的节点编辑能力，操作通过现有工具完成。

引用选择、发送和只读解析不隐式委托、导航或获得写权限。真正修改前核对目标画布和既有控制权。已有会话正在操作另一画布时，保持现有AGENT_SESSION_BUSY / AGENT_CANVAS_BUSY规则，引导完成必要的接管 / 委托；不为#静默撤销另一张画布控制。任何写工具都不能把引用B的nodeId提交到受控画布A。

## 6. 生命周期与异常

| 情况 | 行为 |
| --- | --- |
| 节点改名 / 移动 | 按稳定ID继续定位；历史标签不改写，Agent上下文提供当前名称 |
| 节点配置或连线在发送前变化 | 节点引用读取最新已保存状态；引用本身不锁住旧配置 |
| 用户有未保存草稿 | 发送前等待已有保存流程完成；保存冲突保留草稿并处理冲突，不让Agent操作旧版本 |
| 读取后、写入前图变化 | 使用现有revision冲突检查，重新读取并核对，不能盲目重放旧patch |
| 所选节点或画布被删除 | 明确提示重新选择，阻止对应节点引用提交 / 操作，保留输入文字 |
| 上游素材不可用 | 指明缺失输入；不自动换最新结果。依赖该素材的理解 / 生成准备停止，独立改名等操作可继续 |
| 切到另一画布 | 菜单取消旧请求并重新排序；已选有效节点引用保留其原画布身份 |
| 跨会话粘贴 | 沿现有同会话校验拒绝，不扩大访问或写权限 |
| 旧素材 / 文件引用 | 保持原协议与行为，不迁移数据库或历史消息 |

## 7. 契约与实现建议

以下保留已批准的技术契约，消费方为同包浏览器菜单、引用codec / 历史展示、Host解析、主Agent上下文及读取工具；0.2.112实际接口和错误边界以正式ADR与API参考为准。

```json
{
  "version": 2,
  "kind": "node",
  "sessionId": "实际根会话",
  "canvasId": "实际画布UUID",
  "nodeId": "实际节点UUID",
  "label": "镜头02"
}
```

node引用不要求assetId，也不把prompt / 图 / 上下游二进制塞进短标签或剪贴板。version1 media / legacy file标记保持原样；新增node变体单独标version2，旧插件不理解它时应明确不可用，不能转成素材或节点名称猜测。宿主与客户端必须同包升级，旧包回退不改写新历史。

| 表面 | 提议变化 | 兼容性 |
| --- | --- | --- |
| ChatReferenceSchema | 新node变体，原media / file不重定义 | 对旧引用兼容；新node要求新客户端与Host |
| choices | 新items / cursor / truncated；保留旧media投影供旧调用，显式请求新目录形态 | 加法；新目录同包消费 |
| browse | 可选nodeId与结果批次 / 游标分支；图修订与查询绑定游标 | 加法，strict输入校验继续 |
| resolve / codec | node按稳定ID验证，仅标记身份；提交后读取上下文 | node只读可重试；素材保持精确assetId |
| canvas_read_reference | node返回目标 + 直接邻接 + 输出摘要；相关图片按已提交节点的准确边做受控读取 | 主级读取，不使child获得任意素材访问 |
| canvas_update_node等写工具 | 复用既有能力；对节点引用目标额外核对canvasId / nodeId / revision | 不改变owner / epoch / 操作ID规则 |
| 控制权与图Schema | 无新增持久图字段、边字段或任务格式 | 保持 |

建议读取工具形态：`canvas_read_reference({referenceId})`读取节点及邻接摘要；`canvas_read_reference({referenceId,assetId})`在node引用下按需读取某份相关素材。assetId只允许属于该节点的实际输出 / 绑定素材，或当前直接上游edge.assetId；再次核验关系与可用性后才沿原附件通道读取。下游节点的其他输入 / 输出不因此获得读取资格，需另行选择节点或素材。media / file引用不接受借assetId切换对象，child权限不扩大。

新目录建议由显式的`view=node-media`请求启用，旧请求保持media投影；新browse增加可选nodeId / taskId，分别进入节点素材和历史批次。items统一区分node / media / directory行，nextCursor与truncated表达是否还有下一段。游标必须绑定session、canvas、query、browse及graphRevision；分类和媒体ID保持真实UUID、query与browse继续沿原长度限制。服务端校验游标后输出最多200行，不能跨会话或跨搜索复用游标。

读取节点上下文的一组数据来自同一已保存snapshot。列表懒读一个展开画布；详情懒读一个节点与直接邻接。node当前状态可变化，不应靠长期缓存判断；素材缓存身份仍按assetId。

错误沿现有400 INVALID_REQUEST、403 REFERENCE_SESSION / REFERENCE_FORBIDDEN、409 REFERENCE_STALE / GRAPH_CONFLICT / 控制权错误。GET / resolve / read无图写入、不会提交任务，可安全重试；写入继续用既有operationId与revision，不以重复#提交重放操作。未知kind / version失败保留草稿。分页游标失效应返回明确的重选 / 重查提示，不污染其他会话候选。

## 8. 实施核对范围

需要覆盖：空节点与六类节点；名称重复 / 改名 / 删除；原生点击 / Enter节点与箭头 / Tab素材；当前预览 / 同批堆叠 / 历史；关键词找到历史；大量候选继续浏览；上游绑定旧结果 / 多类型输入；直接下游影响；发送前保存 / 修订冲突；跨画布读写权限分离；真实图片上下文 / 视频音频诚实边界；旧media / file历史与@保持。

实施维护正式ADR、API文档和手验条目，运行现有全量检查、双构建、原生SDK、包身份、本机web3080安装 / 重启 / 加载与数据保留核验。真实交付以正式文档和112manifest为准，静态交互示意保留设计说明用途。
