## 背景与驱动因素

1. 画布高频编辑需要自动保存，又不能每次拖动都并发写文件。
2. 多窗口可能修改同一工作区，最后写入覆盖会让用户无感丢失草稿。
3. 生成任务持续更新结果，旧图保存不能回写旧资产 / 任务；生成必须使用确定的已保存输入。

## 决策

客户端保留本地图草稿，debounce 后通过串行 flush 保存 graph + revision；宿主乐观校验并递增图修订。生成与工作区切换前等待 flush；任务 / 素材由宿主独立更新，不由浏览器回写。

无本地改动时跟进外部图更新；有草稿冲突时阻止覆盖，支持导出图 JSON 后重新载入。离开面板尽力保存，关闭页面提示未保存；不承诺退出请求成功。精确时间与流程见[业务参考](../business.md)。

## 备选方案

| 方案 | 未选择的原因 |
| --- | --- |
| 最后写入胜出 | 多窗口可能静默覆盖，无法保留冲突草稿 |
| 只允许手动保存 | 容易遗漏且不适合持续画布编辑 |
| 全量 WorkspaceState 由客户端保存 | 旧响应可能清空运行中任务和新结果 |
| CRDT / OT 多人协作合并 | 超出单机 owner 场景，图合并和任务权限未定义 |

## 后果

正面：高频编辑合并保存；冲突明确；任务结果不被旧图覆盖；生成快照可对应已保存修订。

负面：不自动合并冲突；用户需导出 / 重新载入；导出仅图且无导入 UI；浏览器关闭时仍可能留有未保存编辑。

## 可逆性与重审条件

可在 API 修订边界增加合并 / 协作，但需保留旧 graph 契约及任务隔离。明确多人协作、离线编辑或跨设备同步需求时重审；先定义冲突与权限，不直接改为最后写入胜出。
