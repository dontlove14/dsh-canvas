# ADR-0040：画布仅展示已配置的模型与供应商组合

状态：已采纳

设置概览布局与无行内入口条款由[ADR-0057](0057-provider-cards-and-direct-model-editing.md)替代；画布组合过滤保持。

文档类型：解释；负责人：项目维护者 / 开发执行者；最近核对：2026-10-29。
记录日期：2026-10-27。配置可见性或供应商选择规则变化时复核。

## 背景与驱动因素

1. 用户明确要求未配置的供应商也不显示；先前仅过滤整组未配置模型，仍把组内未配置渠道展示出来，未满足要求。
2. 模型分组与供应商配置是两个层级，必须按具体“模型＋供应商”组合的Key判断可见性，不能用另一个渠道的配置资格替代。
3. 隐藏渠道不得改写旧节点、删除凭据版本、切换已接受任务供应商或触发重新生成。

## 决策

画布选择器**先过滤具体模型与供应商组合，再按模型分组**。只有该组合具有非空API Key且属于真实模型才显示；`has_api_key=false`的渠道始终隐藏，即使同模型的其他渠道已配置。没有剩余渠道的模型组不显示，不渲染灰色未配置选项或“未配置”提示项。

例如只配置GPT Image 2.5 Flare的Model Link时，菜单只显示Flare下的Model Link，不显示OpenAI；只配置OpenAI时，只显示OpenAI；两者配置后才同时展示。已配置的Model Link优先，没有Model Link配置时不能保留或默认选入它。

配置表单继续提供完整支持目录，以便通过右上角“配置模型”入口新增供应商Key；这是配置入口，不能与画布实际生成选择器混用筛选策略。原配置概览只汇总已配置内容、不新增行内入口的决定已由ADR-0057替代。

清除某个Key后仅移除对应渠道，其他已配置渠道继续显示；清除最后一个Key后移除模型组。当前类型无可用组合时显示“请前往设置页面配置模型”并禁用空选择器，不注入Mock或占位模型。不自动改写已有节点modelId，不自动选择其他渠道；已接受任务继续使用原快照与凭据版本。

共享筛选同时用于画布候选、节点默认模型与选择器渲染。新节点从已配置组合中选择默认值，优先Model Link；无配置时modelId / params为空。历史Mock定义、任务恢复、媒体与图数据保留，画布不提供Mock后备项或调用Mock生成。

本决策替代[ADR-0039](0039-configured-only-canvas-model-picker.md)，并更新[ADR-0037](0037-fixed-provider-image-models.md)原“未配置渠道可选”的画布显示规则；固定目录、接口、尺寸、原数据和恢复规则保持。GET models仍返回用于配置的完整目录，HTTP / DTO / SQLite DDL不变；不在Host篡改或删除未配置记录。

## 备选方案

| 方案 | 评估 |
| --- | --- |
| 有一个渠道配置就展示同模型全部渠道 | 已被用户明确否定，不采用 |
| 未配置渠道置灰或添加未配置说明 | 不符合“不显示”，不采用 |
| 配置接口也隐藏未配置渠道 | 会阻止用户新增配置，不采用 |
| 生成选择器只展示已配置组合，配置表单保留完整目录 | 满足要求并保留配置能力，采用 |

## 后果

正面：菜单准确反映每个组合的实际配置，不会显示用户无法使用的渠道，空态与配置流程明确。

负面：清除当前渠道Key后，旧节点需由用户重新选择已配置渠道；不会为用户自动换供应商。

## 可逆性与重审条件

新增供应商沿用组合级筛选，不能回退为模型组级放行。若未来要显示尚未配置渠道，须由用户明确改变规则并新建ADR。恢复旧界面按已核验包 / profile规则进行，不能删除或重写原任务以恢复显示。
