# ADR-0021：每轮开发自动更新本地插件与压缩包保留规则

状态：已采纳

文档类型：解释；负责人：项目维护者 / 开发执行者；最近核对：2026-10-26。
记录日期：2026-10-26。每轮开发交付时复核；目标 profile、端口、构建或清理规则变化时更新。

## 背景与驱动因素

1. 用户明确要求后续开发沿用当前流程：每次修改完成后，自动把本地 DeepSeek Harness 插件更新到最新版，而不是仅修改源码或要求用户再次手动安装。
2. 根目录累积多份过期 tgz，容易误装旧版本，也不利于确认当前可用包。用户要求删除过期包。
3. Vite 热更新不能替代 Harness 的插件安装和宿主重启。源码版本、压缩包和实际运行版本必须建立明确对应关系。
4. 自动更新需要保留已有画布、模型、凭据和任务，并只操作已授权的本机实例；检查失败时不能把不可用候选交给用户。

## 决策

### 触发与授权

每轮修改完成、准备向用户交付时，由开发执行者主动串行执行下面流程。当前“自动更新”由开发助理完成这些操作，不表示 `npm run check` 自身包含安装 / 重启，也不把逐次保存文件当作交付触发点。

当前目标为本机 `web` profile、端口3080，访问地址 `http://127.0.0.1:3080`；profile 通常位于 `~/.dsh/profiles/web/`。在用户已经授权的同一环境中，无需每轮重复请求安装或重启许可。目标变化时核对实际配置和进程；不得把此授权扩大为远端发布或初始化 / 覆盖其他 profile。

### 交付流程

1. 完成本轮修改和相关文档，递增插件版本并同步 package-lock；同一版本的已交付 tgz 不静默覆盖。
2. 执行必要检查：文档、类型、现有测试和构建；失败先修复。发布前按现有产物管线核对两次清理构建的 lib hash、编译后 Host / Worker / schema 隔离启动以及包内版本 / 文件 / hash。
3. 用核验过的同一 tgz 安装。更新前在受限临时目录备份目标 profile 配置，记录原版本、实际监听PID和公开API基线；只有涉及存储变化时才按运行指南追加完整停机数据备份。
4. 正常停止已核实的3080目标进程，等待退出，再执行 `dsh plugin --profile web add <已核验包的绝对路径>`；沿用既有配置，随后启动相同 profile / 端口。日常更新不重复 `--from-default-profile`，不操作5173开发实例。
5. 核对安装版本与全部 lib hash，认证访问宿主根页、插件 API 和根页声明的实际 client preload；确认加载本轮新代码，并按改动范围核对目录、模型、存储和任务状态。认证链接、密钥和私有配置不输出到用户可见日志。
6. 核验成功后清理过期 tgz，并告知实际安装版本、访问入口和待用户验收事项。浏览器视觉、交互和真实模型效果继续由用户手动验收；不能把HTTP200或静态检查称为视觉通过。

更新前的代码 / profile / 包检查未通过时保持原实例；安装或启动失败则停止失败候选并恢复上一可用包和 profile。保留错误证据，修复后重新核验。停宿主不改变已接受任务身份；不得为恢复执行而重复提交生成任务。

### 包与证据保留

- 根目录最终只保留一个最新版、已安装且已核验的 `dsh-canvas-<version>.tgz`。
- 新候选安装 / 启动 / 核验成功前，上一可用包仍是本轮失败回退来源；成功后删除过期 tgz，避免在根目录长期累积。
- 清理限定为本插件根目录的过期压缩包，不删除数据库、媒体、模型、凭据、任务、源码或其他项目的文件。
- 源码、ADR和必要的版本 manifest 保留作为身份与历史证据；历史记录中的版本号 / hash不代表对应旧tgz仍可用。临时脚本、启动日志、调试回执和 profile 备份存于工作区外的受限临时目录。
- 已删除包不再列为可用的长期回退来源。若以后确有长期版本归档需求，再指定独立归档位置和保留期限。

### 权威与维护

本 ADR 是交付 / 清理规则的唯一权威说明；根目录 [AGENTS](../../AGENTS.md) 作为开发执行者入口，[运行指南](../operations.md)维护命令与环境事实，[README](../../README.md)提供导航。其他文档通过引用同步规则，不维护互相冲突的保留策略。

## 备选方案

| 方案 | 评估 |
| --- | --- |
| 只修改源码，用户手动打包安装 | 容易继续测试旧代码，也不符合用户要求，不采用 |
| 每次保存文件立即安装并重启 | 交付尚未完成，检查和运行状态不稳定，不采用 |
| 所有历史tgz永久放根目录 | 当前已造成积累和误装风险，不采用 |
| 每轮检查后自动更新，成功后只留最新包 | 当前流程可执行，实际运行与交付一致，采用 |

## 后果

正面：用户每轮收到的是已经更新的本地插件；开发执行者不用等待重复安装许可；根目录最新版明确，流程与身份检查可追溯。

负面：每轮交付需要构建、安装和短暂重启，不能仅依赖热更新。过期包清理后不能假定有任意历史版本可回退；人工视觉验收仍需用户完成。

## 可逆性与重审条件

这是开发交付策略，不改变运行时业务或数据契约。用户更换 profile / 端口、要求暂停自动更新、引入新的构建管线或指定长期归档时重审，并同步入口文档。

本规则更新此前“根目录保留旧包”的默认做法。旧ADR中回退原则继续有效，但实际回退以仍可用的包 / 完整备份为前提；本轮更新核验成功后的过期压缩包不再承诺保留。
