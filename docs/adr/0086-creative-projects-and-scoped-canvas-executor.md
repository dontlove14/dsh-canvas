# ADR-0086：持久创作项目与独立画布执行子 Agent

文档类型：架构决策记录；负责人：项目维护者 / 开发执行者；最近核对：2026-11-05。

状态：已采纳
记录日期：2026-11-05
实施版本：0.2.115；部分替代[ADR-0071](0071-shared-canvas-agent-preset-and-control.md)中“主级直接写入、专业结果仅临时草稿”的分工。媒体任务、控制权、原生方案审阅、模型选择和人工点击规则保持。

## 背景与驱动因素

如何让主 Agent 统筹通用创作，让专业角色处理长资料和内容，让同级执行角色操作画布，并使成果跨轮可续、来源可追溯？

1. 通用创作需要协调、专业内容与画布执行各自承担明确责任，不能以小说改编专用流程替代架构。
2. 原文和成果需要按版本、位置和依赖持久保存，既支持长文续作，也保持旧画布与任务身份。

| 驱动因素 | 理由与约束 |
| --- | --- |
| 通用媒体创作 | 小说改编是检验场景；单图、广告、教程、已有节点修改也必须使用同一能力，不固化小说管线或特定模型片段长度 |
| 人机接力 | 主级协调目标、用户决定和证据；专业角色创作，执行角色落地，用户仍掌控素材认可与图片/视频点击 |
| 长文与续作 | 上传附件和原生@工作区路径都需实际读取；正文不全部进入主级上下文，分段成果、已读范围与中断状态需持久保存 |
| 存量兼容 | 不改变已存 CanvasGraph、边、主库和任务库DDL，不重提存量任务，不扩散凭据 |
| 权限与成本 | 每批次明确授权；写入清单、CAS、epoch、幂等和付费任务归宿主，独立上下文不能成为越权入口 |

不新增剪辑、字幕、混音或成片编辑器，不保证真实模型创作质量，不把离线校验当作人工视觉验收。

## 决策

采用同一宿主中的模块化边界。专业预设仍是story/assets/shots/audio/review；新增隐藏预设canvas-executor。主预设不注册节点写工具。canvas_execute按批次启动一层同级执行子 Agent，最多100项明确工具与参数。宿主保留main身份作为控制、模型选择、任务归属与呈现sessionId。

| 上下文 | 负责人 / 检查入口 | 数据模型 | 上游 → 下游与关系 | 翻译面 |
| --- | --- | --- | --- | --- |
| 主级协调 | preset / delegation，agent.test | 用户目标、项目目录、授权清单 | 用户 → 专业 / 执行（客户/供应商） | 用户决定转为批次目标与明确commands；子级自报由宿主回执核对 |
| 专业创作 | creativeTools / methods，agent.test | 来源ID、已读范围、成果依赖 | 主级 → 创作项目（共享契约） | 分页原文转为带引用的成果；实际素材仍使用assetId |
| 画布执行 | preset / execution / coordinator，agent.test | 精确工具意图与当前CAS revision | 主级 → CanvasService（遵从现有服务） | 只允许更新revision与note，其他参数逐项匹配授权清单 |
| 创作项目 | creative / shared creative，agent.test | 原文快照、成果、版本、认可、批次进度 | 专业 / 主级 → 工作区文档（共享契约） | 原文UTF-8/BOM UTF-16转为统一UTF-16引用偏移，宿主生成Markdown路径 |
| 媒体服务 | CanvasService / Store / Runtime，既有check | CanvasGraph、任务、素材、凭据 | 执行 → 持久任务 / 客户端呈现（遵从既有约束） | 继续现有图校验、对象存储与任务身份，不新建协议 |

依赖方向：共享契约不依赖宿主；创作资料不依赖数据库DDL；preset组织工具，delegation组织批次，coordinator负责根身份/权限。源文内容只作为数据，不能成为工具或授权指令。

## 来源与成果

当前支持32 MiB以内TXT/Markdown、UTF-8与带BOM UTF-16。上传仅接受当前root用户事件内的attachmentId；工作区路径只能位于root实际工作区，拒绝路径穿越、符号链接、非普通文件和其他格式。原生@提供路径不等于已读正文。PDF / Word需先转文本，不能声称已解析。

原文保存在宿主私有creative-sources目录，统一UTF-16字节快照与SHA-256；章节正则只产生候选索引，无章节文本保留全文入口。每页最多12000单位，返回start/end/next与引用单位，正文不返回给主级。实际读取范围持久并合并；专业成果不能引用本批次未读范围。

creative-projects.json是独立v1原子sidecar，文件0600、快照目录0700，由既有单宿主Store进程锁拥有。项目按实际工作区和画布复用；创建画布前按root会话存储，随后绑定画布。成果保留来源、任务、作者、版本、依赖、真实素材、文件哈希及draft/approved/rejected；新版本或来源变化使依赖链needsReview，不覆盖旧认可成果。原有agent-ledger.json v1草稿与回执继续读取。

目录分页默认50、最多100；成果正文仍最多32000，长文通过多个成果组织，不能扩大单条草稿伪装项目。专业角色按批次保存检查点和最终结果；运行中的批次重启转interrupted，已有成果保留。

## 执行、并发与恢复

选择原生spawn + caller同步批次，保持现有工具等待与呈现；检查点持久保存，目录按需投影。拒绝每节点spawn的额外上下文成本，也不引入无人值守后台自动推进：下一批取决于用户决定、实际素材和上一批证据。

原生startActivation支持预留childId。宿主在agent/created前准备精确绑定，使首个工具调用即处于正确授权范围。子级不可再次委派。单委派命名空间最多2个活动批次，写入仍走全局串行队列。

执行角色只拥有create/update/connect/import/generate，每次对工具名和除revision/note以外参数做哈希比对；模型选择来自root，图片/视频的新生成依旧硬拒绝，FishTTS还需allowTts。本批次完成与否只看宿主每项操作的实际回执，structured_output自报不能证明完成。root负责最终图片/视频handoff，避免执行子撤权时丢失根回复。

普通图操作可按同一意图取回回执而不重写；生成操作仍绑定原始任务快照修订。批次开始回执先持久，失败、结果未知或重启不自动再spawn。后续读取进度和操作回执，用新批次ID续作，复用已完成的实际操作ID；未知/失败付费任务只能查询原任务。人工接管同步增epoch并取消root及子运行，提交前再次核验，迟到结果不能恢复授权。

## 备选方案

| 方案 | 结论 | 代价 / 拒绝原因 |
| --- | --- | --- |
| 维持主级直接写图、子级只给一份草稿 | 不采用 | 主级承担大量创作与执行上下文，长文无法可靠分段续作，角色隔离仅靠叙述 |
| 小说改编专用服务、分布式流水线 | 不采用 | 单图与已有节点无法复用；引入部署、协议与运维成本，当前没有独立扩缩容需求 |
| 同宿主项目模块与精确批次执行子级 | 采用 | 增加独立记录和一个子上下文；需要维护来源快照容量与授权契约 |
| 主级提交自由指令、执行子自行补参数 | 不采用 | 难以核对创作意图、模型渠道与授权，不能以prompt替代权限边界 |

## 后果

正面：主级上下文更可控、过程和来源可追溯、成果可跨轮/同画布跨会话复用、执行和创作各有权限。
负面：批次新增原生子 Agent 开销；原文首次解码/索引与分页快照哈希有宿主成本；sidecar按次原子保存，容量有限，无自动清理原文。

## 可逆性与重审条件

| 风险 | 可能性 / 影响 | 缓解与记录 |
| --- | --- | --- |
| 长文消耗宿主内存/磁盘 | 中 / 中 | 有限首次读取、页大小、目录/记录上限；记录SOURCE_TOO_LARGE / CREATIVE_STATE_FULL；不自动清理用户素材 |
| 模型虚构已读或已完成 | 中 / 高 | 持久已读范围、SOURCE_UNREAD、逐项宿主回执；真实创作质量留人工验收 |
| 接管或启动竞态扩大授权 | 低 / 高 | 预留childId绑定、root epoch与提交前校验；失败保留批次状态 |
| sidecar损坏或来源快照改变 | 低 / 高 | schema解析、原子0600写、快照哈希；CREATIVE_STATE_INVALID / SOURCE_STALE阻止使用，恢复外部备份 |
| 工作区成果被修改 | 中 / 中 | 原生发布目录、拒绝覆盖、读取校验文件哈希；FILE_COLLISION提示核对 |

使用现有SDK和Store锁，调试入口是任务目录、宿主错误码及私有日志；不输出源文全文或凭据。发布按运行指南备份和冷更新。回退保留0.2.114包及profile备份；新sidecar与快照不参与旧画布解析，旧版可忽略它们。重新设计时需迁移创作项目记录与工具契约，成本中等，属于可逆模块决策。

重审触发：资料格式需PDF/Word原生提取、项目记录量超过当前容量、真实测得分页哈希/全sidecar保存成为瓶颈、需要跨设备多人协作或独立调度服务。先测量并替换原文适配器/项目仓储，再评估分布式服务，不改变已有画布数据结构。
