# ADR-0003：本地单写者文件存储与版本化契约

状态：已替代

文档类型：解释；负责人：项目维护者；最近核对：2026-10-26。
补录日期：2026-10-26；原决策日期未单独留档。复核规则见[ADR 索引](index.md)。

## 背景与驱动因素

1. 用户要求配置、画布与媒体保存到本机，首版不需要云账户或数据库部署。
2. 图保存、任务更新和上传登记并发发生，必须避免同进程互相覆盖及多进程同时写文件。
3. 可读文件便于调试和完整备份；未来修改格式必须保持已有画布可恢复。

## 决策

Store 统一管理本地 JSON 与 UUID 媒体文件，工作区文件名用 ID 的 SHA-256；公开模型、密钥、工作区和私有任务分开。图 / 工作区契约 version 1，启动时 Schema 校验公开元数据并载入内存。

用单个串行队列更新元数据，单文件采用临时写入、文件 fsync、rename；PID 目录锁排除第二写者，只确认旧 PID 不存在时回收。当前无目录 fsync、跨文件事务或自动迁移。布局和限制维护在[数据参考](../data-api.md)。

## 备选方案

| 方案 | 未选择的原因 |
| --- | --- |
| 浏览器 localStorage / IndexedDB | 宿主任务不可直接共享，页面数据和宿主媒体生命周期分离 |
| 本机 SQLite | 可提供事务和查询，但首版引入存储驱动 / 迁移与运行依赖成本 |
| 远端数据库 / 对象存储 | 违背本机存储目标，增加运维和跨设备权限需求 |

## 后果

正面：无需独立数据库；文件可离线备份；串行更新与单文件替换降低常规覆盖 / 半写风险；锁可阻止常见第二实例误用。

负面：多个文件不组成事务，崩溃可能不一致；PID 锁不适用于多机共享目录；所有状态载入内存且无 GC / 总量上限；没有自动坏文件修复和私有任务 Schema 校验。

## 可逆性与重审条件

可通过 Store 边界迁移到其他本机存储，须提供 version 1 读取 / 迁移验证与备份回退。多写者、事务一致性、大量历史检索或内存负载要求出现时重审；不能靠扩大并发来规避文件存储约束。
