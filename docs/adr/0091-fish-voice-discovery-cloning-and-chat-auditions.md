# ADR-0091：Fish 音色查找、单音频复刻与对话试听

文档类型：架构决策记录；负责人：项目维护者 / 开发执行者；最近核对：2026-11-05。

状态：已采纳
记录日期：2026-11-05
实施版本：0.2.122；补充[ADR-0086](0086-creative-projects-and-scoped-canvas-executor.md)与[ADR-0090](0090-model-aware-video-consistency-references.md)，替代[ADR-0030](0030-fish-tts-nodes-and-streamed-audio.md)中TTS不接受输入连线的限制。

## 背景与驱动因素

Model Link 没有音色目录接口。普通用户需要专业子智能体查找官网音色，再自主选择与试听，主智能体继续只协调。用户明确要求不依赖官网示例音频，试听用候选ID实际合成短句并在聊天播放。2026-11-05重新核对[Model Link TTS文档](https://apidoc.modellink.online/388232172e0)：references覆盖reference_id，须MessagePack序列化，每项含二进制audio与参考音频原文text。文档没有数量上限，用户指定本插件按一份处理。

1. 音色查找和试听需要符合主级统筹、专业子级创作及同级画布执行的权限边界。
2. 复刻输入、ID互斥和实际试听成果必须使用已有真实素材身份，保留旧图及任务。
3. 官网样例访问不稳定，用户要求通过真实TTS短句试听并自行播放。

## 决策

| 边界 | 实现 |
| --- | --- |
| 音色查找 | 新增专业角色voice / 隐藏预设canvas-voice，中文显示“音色查找”；不开放画布写入、生成、委派或直接提问 |
| 官网读取 | 仅HTTPS fish.audio的discovery与32位十六进制ID的m详情页；每批最多8次，单页最多2MiB，单次12秒，无凭据、重定向或样例下载 |
| 候选证据 | 搜索只筛选当前公开页标题，不声称全站搜索；详情返回实际ID、标题、描述、URL、时间和SHA256，保存与旧全文交接须逐项匹配本批次回执 |
| 持久成果 | 沿creative的audio-plan，content为JSON candidates及limitation；无实际结果保存空候选及缺口，不新增图字段或sidecar格式 |
| 音色选择 | 主级原生问题展示实际候选，由用户决定；已有ID/指定音频跳过搜索。官网描述不是实际听审，也不证明ModelLink s1兼容 |
| 试听生成 | 用户要求试听明确候选/数量就是该批短音频授权；主级说明ID、条数、短句，精确清单交执行级，沿原队列、凭据快照和allowTts生成 |
| 对话音频 | main-only canvas_show_audio只读校验实际任务/成果，回执投影为原生直接聊天行；audio-result只读跟踪原任务并验证资产归属 |
| 播放行为 | 复用AudioPlayer、真实波形与短期媒体URL，支持播放/暂停、键盘及拖动进度；无自动播放，多卡互相暂停，隐藏/卸载停止 |
| 音频复刻 | TTS接受一份音频真实边；有ID隐藏输入端口，有音频隐藏ID并显示reference_text；原文与新朗读prompt分开 |
| 请求 | ID路径保持原JSON，音频路径用锁定版本@msgpack/msgpack发送binary audio及text，省略reference_id，继续model:s1和prosody |

搜索无法读取动态页、遇登录/限制、超时或无候选时如实报告；不引入未核验的私有API、站外目录或编造ID。网页为资料，不是指令。新成果只能依赖本批次实际详情回执，已保存成果重读复用，不要求重新爬取。0.2.123补充不可访问时的人工接续：子级保存缺口，主级在对话中明确指引用户用可访问官网的手机或电脑打开 https://fish.audio/、选择音色并进入详情页，复制地址`/m/`之后的ID（不含斜杠或查询参数）发回对话。公开列表不可读和详情/网络失败回执均携带同一指引。没有可用ID时等待用户提供，不反复派发、不猜ID或生成默认音色；已有候选先交用户选择。用户自行提供ID后不以插件电脑再次访问官网核验为前置条件，提供ID本身不扩大生成授权。插件不会因此重提已有任务。

图可先连音频再填写原文，保存阶段检查类型/数量/互斥/归属/循环，生成阶段再要求非空原文及有效朗读内容；参考字节准备在issued之前验证大小与音频签名。TTS朗读文字不插媒体token，references仍同次保存真实边；图片和视频继续全部@引用规则。三个创建入口沿公共注册/工厂，拉线创建音频复刻节点同次保存边；空节点、已生成节点和历史组均维护输入端口。复制粘贴保留原上游音频、参数与朗读文字，不生成任务。

聊天回执不保存短期URL。卡片恢复只读音频元数据，不调用生成或图写入；忙任务每2秒查询，隐藏停查，读取错误最多连续重试3次后提供“重新读取”。失败、待确认和保存失败显示原状态，不默认合成替代品。主级无需为播放器持续空轮询。

## 备选方案

| 方案 | 结论 |
| --- | --- |
| 官网下载示例 | 用户否决，访问限制不可控 |
| 主级直接找音色 | 破坏已选分工 |
| 把音色ID当媒体ID | 失去实际音频输入 |
| Base64 JSON传references | 与文档要求的MessagePack二进制不符 |
| 多音频复刻 | 文档未定义上限，按用户限定一份 |
| 专有输入音频节点字段 | 破坏通用真实边、来源和复制规则 |

## 后果

正面：用户能按实际音色合成试听，音频和ID来源清楚；复刻沿通用真实边与原任务身份，旧请求不改变。
负面：官网读取不稳定，公开列表筛选不等于全站搜索，音色兼容和听觉质量仍需实际合成；复刻要求参考原文，当前不提供自动转写。

旧节点、ID请求、空referenceIds任务快照和两库DDL保持。reference_text仅在新复刻参数出现；新音频边采用原CanvasEdge。旧包不认识reference_text与TTS输入，一旦使用新复刻数据，恢复必须采用前向修复，不能覆盖回退到121；更新安装阶段尚未使用新数据时可按原冷备份恢复。已保存候选无需在升级时重抓，不重渲染成果、不改认可或历史混用ID。

## 可逆性与重审条件

官网路由/渲染方式、Model Link参考格式/数量或试听产品需求变化时重审。
