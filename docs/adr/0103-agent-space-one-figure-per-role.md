# ADR-0103：Agent 空间同角色共用一个形象

文档类型：架构决策记录；负责人：项目维护者 / 开发执行者；最近核对：2026-11-12。

状态：已采纳
记录日期：2026-11-12。
部分替代：[ADR-0100](0100-agent-space-upper-left-card-and-working-podiums.md)与[ADR-0101](0101-parallel-canvas-executors-and-observed-cursors.md)中同角色多个 childId 分别显示人物的规则。真实调度、日志、画布光标和原动作素材保持。

## 背景与驱动因素

1. 同角色并行实例原先各生成一个人物，展开办公室右侧出现重复重叠，缩小站台也随实例数变宽。用户明确要求 Agent 空间中无论并行多少实例都只显示一个。

2. 实例仍需独立执行、记录回执及结束自身画布光标。显示合并不能将某个实例的完成误认为整个角色完成，也不能丢失其他实例的真实交接。

## 决策

展开办公室和缩小站台均按角色显示一个形象，不同角色各自保留。每个角色在当前 root 内使用稳定的展示身份与固定原工位，临时 childIds 集合保留本轮真实成员；展示身份不充当原生子会话 ID。

root 运行且任意本轮成员实际 running 时，该角色保持工作。dispatched 不算工作；部分成员完成或 blocked 不覆盖剩余成员工作。没有 running 成员且存在 blocked 时，展开保留失败动作；缩小仅显示工作角色，没有工作者仍用主级 M09 正面待机 1.0 倍。原生 root 完成、异常、未知与历史过滤规则保持。

动作队列继续按实际 taskId / childId 观察公开派发与回收，将成员交接映射到同一角色形象；不新增聚合任务、不猜专业间交接，初次加载和恢复不重播历史。成员变动且动作未变时复用原视频元素，避免部分完成重启剩余工作循环。

仅客户端只读展示汇总；宿主并发预算、精确授权、真实实例、日志、成果认可和每实例画布光标均保持，CanvasGraph / DDL / sidecar 无迁移。

## 备选方案

| 方案 | 判断 |
| --- | --- |
| 按实例继续显示并缩小人物 | 仍会重复拥挤，不满足一个形象的要求 |
| 只显示列表中第一个实例 | 第一个完成会掩盖其他实例工作与回收，采用全成员汇总 |
| 合并宿主实例与日志 | 会改变执行及回执身份，限于客户端展示 |

## 后果

正面：同角色并行不增加人物或站台宽度，剩余实例工作保持连续，真实回执和画布光标不受影响。

负面：人物数量不表达同角色并发实例数；详细实例状态继续通过原公开协作记录核对，交接动作仍使用原队列顺序。

## 可逆性与重审条件

沿已授权 web / 3080 安装重启，成功前保留 0.2.142 回退包；失败不清数据或重提任务。若要显示实例计数、汇总文本或修改真实调度，另行评估，本次不增加这些入口。
