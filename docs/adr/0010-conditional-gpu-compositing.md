# ADR-0010：保守检测后的视口 GPU 合成提示

状态：已采纳（补录）

文档类型：解释；负责人：项目维护者；最近核对：2026-10-26。
补录日期：2026-10-26；原决策日期未单独留档。复核规则见[ADR 索引](index.md)。

## 背景与驱动因素

1. 用户要求画布 transform 加速，但开启前必须确认当前设备具备可用 GPU 条件。
2. 浏览器可能使用软件渲染或隐藏硬件信息，仅 CSS 支持 / 成功创建 WebGL 不能证明硬件后端。
3. 节点、边和浮动面板依赖 React Flow transform，不应被额外 transform 覆盖；按节点强制图层会增加资源负担。
4. 目标是合成提示，不是把 React / 布局转为 GPU 计算，必须保留正确回退与明确测量边界。

## 决策

0.2.20合成提示生命周期由[ADR-0032](0032-scale-aware-viewport-compositing.md)更新：仅确认硬件的固定倍率平移暂时提示；缩放 / 停止时释放，并移除零位移三维translate。以下硬件检测与隐私原则保持，永久提示不再是当前实现。

浏览器每页共享一次保守探测，先确认独立三维 translate CSS 支持，再尝试 WebGL 2 / 1。使用 failIfMajorPerformanceCaveat、低功耗偏好，识别已知硬件 / 软件标识并释放临时上下文；信息隐藏时可用 WebGPU adapter 的明确非软件回退标记补充。

WebGPU 等待最多 1500ms，不创建 device。检测失败、软件、未知或 CSS 不支持保留默认方式；探测中也不添加额外提示。显卡标识仅函数内临时判断，不记录或上传。

通过时仅为共享 viewport 添加 will-change transform 和独立零位移三维 translate，保留 React Flow 原 transform。开发与 Harness 共用此实现；dataset 只报告是否请求合成，实际图层由浏览器决定。诊断步骤维护在[运行指南](../operations.md)。

## 备选方案

| 方案 | 未选择的原因 |
| --- | --- |
| 所有浏览器无条件 translateZ / will-change | 软件环境也会启用，不能满足用户条件检查要求 |
| 只检查 CSS.supports 或 WebGL 是否创建成功 | 不区分软件后端 / 隐藏硬件信息 |
| 每个节点强制独立合成图层 | 增加图层 / 显存压力，尚无实测收益依据 |
| 重写成 WebGL / WebGPU 场景 | 需要重做文字、控件和播放器交互，超出 transform 合成范围 |

## 后果

正面：硬件可确认才添加提示；默认回退稳定；不覆盖节点定位 transform；不持久记录硬件标识。

负面：保守识别可能漏掉可用但信息隐藏 / 未知的硬件；浏览器最终可能不创建预期图层；CPU 业务开销仍在；没有自动设备变化后的重新探测。

## 可逆性与重审条件

可移除 CSS 提示而不改图 / 任务数据。出现位置错乱、播放异常或持续资源增长时优先撤销提示；有固定负载下真实帧时间 / 图层 / 内存证据后再重审策略。不能仅靠自动化探测通过扩大性能承诺。
