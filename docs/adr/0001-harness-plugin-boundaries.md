# ADR-0001：使用 Harness 公开扩展边界与 owner 认证

状态：已采纳（补录）

文档类型：解释；负责人：项目维护者；最近核对：2026-10-26。
补录日期：2026-10-26；原决策日期未单独留档。复核规则见[ADR 索引](index.md)。

## 背景与驱动因素

1. 用户要求在 DeepSeek Harness 中使用无限画布，不能要求修改宿主核心或另开一套产品。
2. 生成需要宿主持续持有任务和本机数据，浏览器只负责编辑；模型调用必须经过受认证接口。
3. 生成模型协议区别于聊天模型，复用聊天配置会混淆能力和密钥用途；本地开发还需要可独立启动的验证入口。

## 决策

2026-10-26 更新：公开插件 / owner 认证原则继续有效；画布目录改为自有目录，见 [ADR-0014](0014-canvas-catalog-and-upload-nodes.md)。官方契约与反例见 [ADR-0017](0017-harness-official-cases-and-badcases.md)。下段的工作区订阅描述为旧实现。

采用宿主 `apply(ctx, config)` 与浏览器 `dsh.client` 双入口，通过 main / sidebar.panellist / settings.section 插槽和工作区 observable 集成。仅注册有限的 owner 认证 HTTP 路由；生成配置单独维护，不修改 Harness 聊天模型。

开发载体复用客户端和 CanvasService，提供回环地址 / 同源 / 会话 Cookie 保护。当前工作区 ID 只用于分区存储，不额外校验 Harness 工作区 ACL；具体边界见[架构](../architecture.md)和[接口](../data-api.md)。

## 备选方案

| 方案 | 未选择的原因 |
| --- | --- |
| 修改 Harness 核心页面与聊天模型 | 升级耦合，媒体协议和聊天能力语义不一致 |
| 独立网站加远端服务 | 增加部署与账号链路，不能直接满足宿主内工作区体验 |
| 浏览器插件直接请求供应商 | CORS / 密钥暴露与页面生命周期无法统一保证 |

## 后果

正面：宿主入口和认证保持一致；本地开发与插件共用核心逻辑；宿主卸载可以释放路由与服务。

负面：依赖特定 Harness 扩展契约；目前是整个实例的 owner 范围，不是多租户 ACL；根路径 URL 未验证子路径代理。

## 可逆性与重审条件

UI 与服务通过 API 分离，可替换运行载体；迁移成本集中在注册 / 认证 / 工作区来源。Harness API 变化、多用户权限或远程公开部署需求出现时必须重审，保持持久数据可读，不直接扩大访问范围。
