# ADR-0028：真实音频波形节点与紧凑提示词卡片

状态：已采纳

文档类型：解释；负责人：项目维护者 / 开发执行者；最近核对：2026-10-27。
记录日期：2026-10-26。音频播放、波形算法或编辑卡片布局变化时复核。

## 背景与驱动因素

1. 用户希望音频资源采用参考图中的圆角卡片，显示基于实际音频的波形、播放位置及自定义控制，替换原生audio控件与大图标。
2. 提示词与参考图间的空白影响点击输入，原100px最小高度过大；需要随内容自动增长并限制最大高度。
3. @徽章与正文高度不一致，生成卡片底部任务成功信息冗余；最终一排需要固定为模型、参数与生成按钮。

## 决策

音频资源使用360×180圆角卡片，浮动名称复用双击改名。中间波形来自实际PCM能量，已播放条高亮并显示红色游标，底部仅当前时间、播放 / 暂停和总时长；选中顶部提供原音频下载，只保留输出端点。已有音频素材不显示下方旧资源编辑面板。音频原文件预览复用自定义播放器。

波形与图片封面同为派生缓存，不增加数据库字段 / 表。复用认证media路由，`variant=waveform&v=1` 返回96项归一化RMS幅度与实际解码时长；GET / HEAD均可用，仅允许音频、当前画布归属与安全原文件路径。缓存位于dataDir/previews/waveforms，按原hash、mtime、size及版本识别，权限0600，坏缓存重建，符号链接拒绝。

Host复用现有ffmpeg，22.05kHz双声道PCM流式计算能量，避免反相立体声抵消。逐块统计并压缩为最多8192个中间点，不在浏览器完整解码大音频。独立串行队列最多16个待处理身份；单次20秒解码超时、最多2小时采样，失败冷却30秒。Host停止时取消并等待波形队列；失败不更改原文件或任务，可继续尝试原音频播放 / 下载。波形说明声音强弱，不表示音高、剪辑或模型推理结果。

播放器复用音视频共享媒体事件控制器，不写图状态；底部文字由原生媒体事件更新，游标与波形高亮由独立帧循环同步。点击 / 拖动波形跳转、方向键前后5秒、Home / End定位、空格 / Enter播放；控件与画布键盘隔离。节点音视频使用同一当前播放身份，切换其他播放器、离开可见区、页面隐藏和卸载时停止原播放；音频不自动循环或自动开始。

0.2.15修正播放与选择的状态衔接：点击节点内部播放按钮时，同一更新先选中该节点、清除旧边选择，再设当前播放身份。否则控件隔离了节点点击，而“未选中即停止”的既有规则会立即暂停刚开始的音频。选择和播放仍只在页面内，不更新保存的图；不移除离屏、空白点击或切换节点后的暂停规则。

0.2.16修正timeupdate低频触发造成的游标跳动。requestAnimationFrame逐帧读取音频currentTime，只改当前SVG游标和新跨过的幅度条，不每帧更新React / 画布状态，也不使用墙钟推算虚假进度。暂停、缓冲、错误、结束或隐藏时取消帧；seek与媒体事件立即同步，恢复播放重新领取单个帧。React更新底部时间时按当前媒体时间同步，不回写旧游标坐标；卸载清理事件与待执行帧。功能性进度显示不添加缓动 / 过渡。

0.2.27修正底部时间行不能拖动节点：整个AudioPlayer去掉nodrag，也不对整个controls行拦截pointerdown或普通click。只在波形和播放按钮保留节点拖拽 / 点击隔离；时间文字、底部留白以及加载空白恢复正常节点拖动和点击选择。整个播放器保留nopan，由原生XYFlow过滤器保持原鼠标画布平移 / 双击缩放边界；普通wheel仍按既有专用处理透传，不能只依赖React双击冒泡拦截。按钮仍只播放 / 暂停，波形仍只定位；节点底部普通区域显示抓取光标。普通音频与TTS结果复用同一实现，原媒体、播放身份、轮滚平移和存储结构保持。

生图 / 生视频共用提示词保持contenteditable的自然高度：一行起步28px，最大220px，超过后内部滚动。参考图到正文缩短为4px外间距；20px行高与20px徽章一致，缩略图16px且不参与文字基线，不新增固定占位空白。保留原有输入法 / 撤销 / UUID标签语义。校验说明放在底部控制行上方，生成卡片不显示任务详情；任务状态、失败处理和成功输入仍可从顶部“任务”查看。

## 备选方案

| 方案 | 评估 |
| --- | --- |
| 随机波形装饰 | 不反映实际音频，不采用 |
| 浏览器WebAudio完整解码 | 长音频重复占用页面内存，不采用 |
| Host流式统计与小JSON缓存 | 实际幅度、有限内存并复用已有解码器，采用 |
| 固定大输入框与任务页脚 | 空白难点击、卡片冗余，不采用 |

## 后果

正面：波形与原音频一致，自定义控制保持样式统一；可无数据迁移展示旧素材，输入卡片更紧凑，底部操作位置明确。

负面：首次提取占用Host CPU，受解码时间 / 时长限制；归一化幅度仅表达文件内部强弱，不用于跨文件音量比较。缓存当前不自动GC；真实格式、播放、输入高度和基线效果仍需用户手动验收。

## 可逆性与重审条件

缓存可停机删除重建，原媒体 / 任务 / 图不改变；恢复旧UI不需要数据迁移。增加音频剪辑、频谱 / 音高分析、超长音频或其他输入协议时重审，不将本次样式需求扩大为音频编辑工具。
