# ADR-0052：节点位置与内容更新隔离

状态：已采纳

文档类型：解释；负责人：项目维护者 / 开发执行者；最近核对：2026-10-28。
记录日期：2026-10-28。拖拽、节点输出、轮询投影或编辑器写入方式变化时重审。

## 背景与驱动因素

1. 用户反馈拖拽节点断续；原15节点拓扑替身中，单节点60次位置更新导致900次节点内容更新、480次端点测量请求和60次提示词DOM同步。每2秒无变化读取也刷新全部节点。
2. 问题来自派生数组、节点data和Context引用每次重建；仅添加memo不足以隔离这些变化，反复强制测量增加布局开销。
3. 当前历史只读 / 最新编辑、固定素材引用、实际连线移动、缩放Loading与存量图格式必须保持。不能用旧坐标的显示投影覆盖最新图。

## 决策

- 客户端按全字段递归比较JSON快照，以ID复用不变记录、保持数组顺序。任务进度 / 更新时间、资产尺寸 / 元信息、字段移除、图修订与hash均参与，不用“图修订相同”代替任务或素材比较。
- 按任务所属节点、资产ID和输出连线建立一次索引，复用未变化的results / cards / connectedAssets。各FlowNode与data按字段复用；移动只更换所属节点的实际position和data.node。
- 仅不读取坐标的MediaNode内容比较忽略node.position，React Flow包装层仍使用实时坐标更新平移和连线。选择及Loading环境Context保持稳定；任务或主题实际变化继续更新。
- 坐标未变化的事件不写草稿；纯移动保留图边引用。原650ms保存、2秒轮询、冲突与待接受任务身份保持。
- 生成与历史节点用几何签名触发端点测量，包含尺寸、展开、主图、结果端点顺序及收起隐藏锚点。进度、标题与数组重建不测量；输出 / 主图 / 展开 / 尺寸变化继续测量。
- 浮动编辑器定位包装层使用实时坐标 / 视口；逻辑内容memo使用只读显示投影。引用候选插入必须从实时graph getter构建新图，不能把显示投影中的旧坐标写回。原提示词、IME、引用UUID和历史恢复流程不改。
- 缓存只在当前Workspace内存中，按当前节点 / 任务集合替换，卸载释放。不改变Host、数据库、存储契约、调度并发或动画依赖。

## 备选方案

| 方案 | 评估 |
| --- | --- |
| 固定低帧率或只在松手后写位置 | 改变拖动 / 连线与实时图行为，不采用 |
| 单独增加memo但继续重建data和Context | 仍绕过缓存并测量全部节点，不采用 |
| 位置 / 内容隔离与精确结构共享 | 降低无关扇出且保持实时位置，采用 |

## 后果

正面：同一15节点 / 60移动替身变为60次所属节点data更新，节点内容、测量和提示词DOM同步均0；相同轮询也均0。真实XYFlow测试确认原固定素材连线随新坐标更新。

负面：仍需遍历节点生成轻量位置投影、比较快照；所有图和历史仍常驻，尚无大画布容量、主线程p95 / p99帧时间、GPU饱和点或实际FPS测量。客户端优化不构成60 / 120FPS承诺。

## 可逆性与重审条件

可恢复客户端投影方式，无DDL或图迁移。节点组件未来读取位置、输出端点布局改变、API增加字段或编辑器写入方式变化时，更新比较 / 几何签名并跑回归；发现真实浏览器拖动仍断续，基于实际Performance证据继续定位，不能用DOM更新数替代绘制耗时。
