# ADR-0101：按需并行画布执行与只读操作光标

文档类型：架构决策记录；负责人：项目维护者 / 开发执行者；最近核对：2026-11-12。

状态：已采纳
独立新建的默认派发与光标形状由 [ADR-0102](0102-independent-create-default-dispatch-and-small-cursors.md)部分替代；其余边界保持。
Agent 空间同角色多个 childId 分别显示人物由[ADR-0103](0103-agent-space-one-figure-per-role.md)部分替代；每实例画布光标、真实身份与调度继续独立。
记录日期：2026-11-12。
部分替代：[ADR-0086](0086-creative-projects-and-scoped-canvas-executor.md)的单次同步派发与两个活动批次上限。主级决策、专业草稿、精确执行授权、独立成果和人工生成边界保持。

## 背景与驱动因素

1. 用户要求多个互不相关节点可由主级并行交给多个画布操作子 Agent，并在画布内看到各实例实际操作的位置。是否并行由用户问题决定，简单任务仍用单实例。其他专业角色不使用画布光标。

2. Harness 对原委派工具使用 exclusive 调度；仅提示主级同时调用工具不能确保并行。单值呈现意图又会导致多个实例争抢镜头，全图修订也会误拒绝彼此独立的提交。

## 决策

### 调度与授权

主级新增 `canvas_execute_parallel`，内部派发 2–16 个实际 `canvas-executor` 子会话，每个子任务保留独立 operationId、childId、commands、artifactIds、allowTts 和 dependsOn。任务及依赖不得重复、悬空或成环。保留 `canvas_execute`；没有引入通用专业角色批量入口。

每个画布作用域（未打开画布时为根会话）共用模型预算，`maxConcurrentAgents` 默认 4、范围 1–4，专业与执行委派共享。任务组本身、等待容量和前置依赖的任务不占模型名额。活动实例的资源范围在整批完成前持有，独立任务可越过资源等待者启动。同节点写入、目标的上游节点写入和素材依赖冲突排队；只读依赖可共享。导入与 FishTTS 提交保守占全画布资源，远端媒体任务仍受原任务队列管理。

开始前持久保留原批次身份，授权在原生 `agent/created` 前绑定。批次失败不自动再次 spawn；已保存操作回执保留。失败只阻塞依赖分支，独立成功仍返回。任务排队与光标均为内存派生，不新增持久格式；重启沿原 ledger / creative 记录恢复为人工控制和中断状态，不续发未完成批次。

### 短事务与修订

模型等待、附件读取和上传准备在图提交锁外进行。最终修改仍使用原宿主串行队列和 Store 事务；事务内重新核验根身份、epoch、精确意图及相关资源指纹。

普通编辑的原始修订必须来自主级派发时的快照。同组后续任务可沿用该快照；宿主只在获授节点、入边和素材未变化时调整当前 CAS 修订，不用旧整图覆盖新提交。同一批的自身写入后刷新自身写资源指纹。新节点自动布局在提交内以最新节点集合确定。付费生成仍绑定原始修订、任务与输入，不通过重基变成新生成。

### 光标与镜头

真实 executor 工具开始、提交、失败与结束投影为 `CursorActivity`。创建 / 导入仅在已知实际落点时发布，避免把预估位置当作已落地节点。首版位置来自真实节点 / 提交布局的画布坐标和固定节点锚点；箭头、文本形状与短按压表示操作，不派发 DOM 输入事件，也不模拟逐字打字。

现有 `agent-presentation` GET / SSE 增加可忽略的 `cursors`：进程 streamId、单调 sequence、有限缓冲 floor、当前 active 和最近最多 128 个事件。不返回提示词、原文、凭据或隐藏推理；没有新增 HTTP 路由或 CanvasGraph / DDL 字段。

共用 `CanvasWorkspace` 的 `ViewportPortal` 内显示光标，完整画布和侧栏都使用同一实现。每个实际 childId 独立编号，跟随画布平移 / 缩放且保持屏幕字号；pointer-events 为 none。订阅独立于图快照，每帧动画不刷新节点。自行绘制 SVG 和 Web Animations 短弧线 / 按压，仅借鉴 swarm-cursors 的视觉思路，不复制无许可源码。

仅一个实际执行实例持有自动镜头，其他光标在各自落点出现，避免多个实例来回抢焦点。用户自主浏览、写权接管、原跟随策略保持。

结束、异常、取消、卸载只清理对应实例；根停止、关闭或接管清理所属光标。晚到事件不得复活已结束实例。首次读取、重连、缓冲缺口只展示最新事实，不重演点击；事件的动作每次只消费一次。后台、不可见、减少动态时停止局部动画，恢复不补播。可见性沿 [ADR-0096](0096-latest-element-visibility-notifications.md)，不新增布局测量。

专业角色继续由 [Agent 空间](0100-agent-space-upper-left-card-and-working-podiums.md)表达；同角色多个真实 childId 原路径分别展示，光标不改变角色动作或认可状态。

## 备选方案

| 方案 | 判断 |
| --- | --- |
| 所有工具声明 concurrency safe | 扩大并发权限且依赖模型输出顺序，使用有限批量入口内部派发 |
| 忽略全图修订 | 会覆盖相关修改，使用相关资源指纹与提交前复核 |
| 每个实例单独聚焦镜头 | 造成抢焦点，仅一个活动实例提供镜头 |
| 预制鼠标表演或重连重播 | 不能证明实际操作，只读真实状态 |
| 引入通用专业角色 DAG 与持久队列 | 超出本轮范围，保留为提案后续项 |

## 后果

正面：独立节点同时进行模型工作，最终提交仍受控；光标状态与成果、实际回执及用户认可隔离。

负面：并行增加模型上下文和限流压力，不能保证更快或更便宜；设为 1 可回到串行预算。资源等待没有新增用户排队界面，排队期间不虚构光标或工作者。
