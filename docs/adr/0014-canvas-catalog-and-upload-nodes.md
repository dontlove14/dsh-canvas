# ADR-0014：自有画布目录与上传自动资源节点

状态：已采纳

文档类型：解释；负责人：项目维护者；最近核对：2026-10-26。
记录日期：2026-10-26。更新 [ADR-0001](0001-harness-plugin-boundaries.md) 的目录来源，替代 [ADR-0005](0005-immutable-asset-references.md) 中重新导入替换出边的行为；具体引用身份规则继续保留。

## 背景与驱动因素

1. 用户要求一张画布就是一个项目、一级文件夹管理，不与 Harness 会话工作区绑定。
2. 添加菜单只需要生成节点，上传图片 / 视频 / 音频应直接显示对应资源节点。
3. 上传需要区分接收与后台发布，不能把未收完的文件显示成可用素材。

## 决策

文件夹只有一层，目录支持画布 CRUD 和移动；没有额外 projects 表。目录使用 meta_revision / 内容 hash 和持久请求回执，名称在同一目录唯一。画布软删除保留历史；未结束任务 / 上传阻止删除，非空文件夹阻止删除。

目录页面与画布编辑器的导航在 [ADR-0018](0018-project-list-before-canvas-editor.md) 补充：进入插件先显示项目列表，点击项目进入编辑器，目录管理不放在编辑器顶部。

添加菜单只列图片生成、视频生成。点击上传 / 拖拽自动建资源占位节点；完整字节流落盘后同一 SQL 事务登记 import 目录、详情、upload session。导入完成才把 asset_id 绑定节点。任务列表从目录分页读，详情按需读。

所有上传都创建新资源节点；原素材与连线保持不变。面板参考图上传完成后尝试建立新连线，较慢导入可手动连线。只收到占位或部分字节的上传不能当作已接受后台导入；重启把 receiving 会话标为失败。

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| Harness Workspace = 画布 | 混淆会话目录与创作项目，不满足独立管理 |
| 手动添加资源节点再选文件 | 用户明确取消该步骤 |
| 上传替换旧节点所有出边 | 隐式改变已有输入；当前以新节点表达新素材 |
| 多级文件夹 / 项目层 | 未请求，增加层级与约束 |

## 后果

正面：上传即出现资源节点；目录与会话解耦；重复 upload-start 不重复建节点；后台导入状态可查看。

负面：再上传需主动重新连接；中断上传留失败占位，可删除后重新上传；引用自动连线等待有时间边界；目录和图冲突需用户处理草稿。

## 可逆性与重审条件

目录交互可替换而不改 ID。真正需要替换资源、多级目录或批量导入恢复时另立决策，明确连线 / 已提交快照语义；不自动变更历史输入。
