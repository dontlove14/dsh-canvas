# ADR-0107：精确失败任务诊断与全新会话入口

状态：已采纳

文档类型：解释；负责人：项目维护者 / 开发执行者；最近核对：2026-11-13。
记录日期：2026-11-13；交付版本：0.2.151，自动发送修正：0.2.152。

## 背景与驱动因素

1. 任务中心已有失败正文和实际接口记录，用户需要 Agent 用普通语言解释原因。诊断需要读取特定历史任务，却不能因此接管画布、获得通用日志/凭据权限或重新生成。
2. 入口不能覆盖用户正在进行的旧对话和草稿；不能由成功或状态未确定的任务误触新诊断会话。

## 决策

- 列表操作列和详情的“询问 Agent”只对 failed / save_failed 显示，成功、正常执行、unknown、abandoned 不显示。共用点击保护；打开前及发送前核对该任务当前可访问且仍失败。
- 点击按宿主 mainView 只读归属继承当前工作区；没有当前工作区时沿原生 startSession 的最近成员活动 / 空组创建时间 / 宿主顺序选择已有工作区。未准备好或没有工作区时在任务中心提示，不创建无工作区的空对话。使用 sessions.create({workspaceId, agentPreset: 'canvas-creator'})，不传旧 sessionId，不复用空会话，不暂存或改旧预设/草稿。资源沿 Agent 空间原加载与真实进度准备，该按钮已明确授权新预设。新会话 ready 后核验 agentPreset 和真实 cwd，通过原生 requestDraftInitialization 为精确新 binding 准备问题；关闭任务中心、原生 uiWorkspace.openSession 导航，向新 Session 发送包含完整任务 ID 的真实用户消息。
- 原生 openSession 会以 selectPanel(null) 取消导航前的信号；正常打开后为发送获取新的导航信号，始终保留调用取消、插件生命周期和超时约束。后续真实导航阻止迟到发送，不将自身正常导航当成取消。发送前核对输入修订与内容，原生 beginSubmission / prompt 共用同一 requestId，只发送一次；发送时清空已提交问题，失败时仅在新输入未被用户修改时恢复，通过新会话原生 input.notify / promptError 提示，不自动再建、重发或补发0.2.151已创建的空对话。
- 主级新增 canvas-task-failure-diagnosis，工作表随包按需读取；共29个方法、25份工作表。诊断触发和 canvas_task_diagnose 调用加载该方法；专业角色和执行角色不获得该工具/正文权限，restrict 与 guard 均沿原角色精确清单。
- 工具仅接受 `{taskId: 完整UUID}`。宿主从真实根 Agent 最新 source=user 消息匹配精确 ID，再以 owner / 未删除画布关联查询任务。工具读取前后重验真实角色、根身份、用户消息、取消及任务状态；过期、非失败任务和不可访问任务拒绝。此查询独立于画布编辑委托，诊断轮次不自动恢复人工画布为 Agent 控制。
- 模型输入只含状态、模型/供应商标识、失败摘录和有限尝试/通信证据。真实通信记录生成精简 evidence sidecar；旧记录只在256KB内回读，失败正文上限24KB。文件拒绝符号链接，输入不完整有标记。请求正文、完整提示词、URL、认证头、二进制及媒体不进入模型；已知密钥与敏感字段再次脱敏。不读私密任务 key / vault，不联网重新查询供应商。
- 结论为“模型服务返回的原因 / 插件程序问题 / 原因暂无法确定”。明确响应错误或原 provider 阶段原因可解释余额、密钥和实际审核文字；程序问题由宿主捕获真实本地TypeError / ReferenceError及相符程序异常文字的 programError sidecar依据支持，保存聚合保留第一条异常的来源。旧错误文字没有该依据时保持未知，不凭供应商字符串出现TypeError判责。PROVIDER_ERROR、裸403、超时、下载或保存阶段不单独判责。区分部分成果不足与生成完成后的保存失败，保留实际成果。
- canvas_task_diagnose 的成功回执只读投影成诊断卡，插件程序问题显示“反馈给插件作者”，地址固定为 `https://github.com/dontlove14/dsh-canvas/issues`，不用模型给出的地址，不自动打开或提交 issue。重放卡片不运行工具；正文与最终回复以脱敏证据为资料，不执行供应商文本指令。
- 不改 CanvasGraph、DDL、原任务/成果身份、配置或凭据；诊断不自动生成、恢复查询或重试保存。后续处理需要独立用户授权和原工具权限。原 canvas_task 查询语义保持。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 改旧会话预设并把问题写进输入框 | 会覆盖旧流程/草稿且可能误发，不采用 |
| 给主级通用文件/日志/终端工具 | 无法保证精确任务资料授权，不采用 |
| 精确只读任务工具、独立会话和宿主回执卡 | 复用真实证据且保持原任务与权限边界，采用 |

## 后果

正面：诊断可在没有画布委托时进行，旧任务缺证据会得到诚实的未知结论；独立会话保留用户原工作和草稿。

负面：增加一份精简sidecar和会话创建流程；方法不等于真实观看/试听或供应商在线核验，旧大记录无法补造。

## 可逆性与重审条件

可以撤回工具/入口/卡片，新增精简sidecar不参与执行或图持久化。若未来支持其他状态、自动处理、共享任务或额外证据来源，须重审资源授权和治理。
