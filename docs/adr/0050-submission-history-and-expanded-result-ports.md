# ADR-0050：按提交堆叠生成历史与展开逐素材端点

状态：已采纳

多次提交展开编辑条款由[ADR-0051](0051-readonly-submission-inspection.md)替代，其余保持。

文档类型：解释；负责人：项目维护者 / 开发执行者；最近核对：2026-10-28。
记录日期：2026-10-28。提交、结果分组、端点或任务并发规则变化时复核。

## 背景与驱动因素

1. 用户要求图片、视频和TTS在同节点再次提交时立即增加卡片，最新提交在顶部显示Loading，原结果留在下方；连续提交不能覆盖历史或按完成时间重排。
2. 多次生成的各素材都可能被下游引用，不适用单次批量的“设为主图”。用户要求展开后逐素材连接，收起时不显示输出端点。
3. 旧Service和SQLite唯一部分索引都限制同节点仅一个未结束任务；需要同时解除提交限制，保留删除保护、去重、固定快照和全局并发上限。

## 决策

- 从既有tasks和resultIds派生历史，不向节点或图保存卡片字段。一个任务对应一张卡片，createdAt降序、同时间按接受顺序；完成时间不影响位置。失败 / 待确认任务也保留卡片。
- 点击生成先创建临时提交卡片，再保存草稿和POST。同步请求锁阻止同一派发重复点击，收到回执后可继续编辑 / 提交，即使旧任务仍执行。每次输入、模型、Key、引用和存储目标固定为该任务快照。
- 临时卡片使用本次requestId；202回执和GET摘要提供可选requestId，来自已有task_details.request_id，无新持久字段。按确切ID替换和去重；保存失败 / 明确4xx拒绝移除未接受卡片，不确定响应保留待确认。接受后GET失败保留回执，不自动重提。
- 同节点第二次提交起使用历史展示：收起显示最新卡片与既有叠层样式；展开按提交顺序展示各任务，其多个输出在该任务内成组。历史中没有设主图入口，每个已保存素材有独立输出；待生成卡片没有输出。
- 逐素材端点ID为仅界面使用的result:assetId。收起禁止新连接，仅为已有边保留不可见、不可操作的几何锚点。存储边仍为source / target / assetId，新提交和主图旧值均不能改绑旧边。图片 / 视频保留节点输入，TTS无输入。
- 未连接的历史素材不进入@自动连线候选；用户先展开连接，之后可按具体UUID引用。原资源和单次批量主图候选保持。
- 每张任务卡片独立使用既有Beam / Thinking Orbs边界，任务完成后继续等待自身媒体就绪；阶段无可见状态文字。主题、缩放密度、离屏暂停及单媒体播放规则保持。
- 单次提交多输出仍沿用[ADR-0026](0026-primary-only-group-interaction.md)主图分组。该ADR在多次提交场景由本决策替代；多次提交的展开只读查看 / 收起最新编辑以[ADR-0051](0051-readonly-submission-inspection.md)为准。
- SQLite仅将task_active_node从UNIQUE部分索引改为同列、同谓词的非唯一查询索引。Worker启动事务内检测旧唯一索引并替换；user_version=3、23表、39显式索引身份、所有列和业务行保持。更新前完整停机备份，不清理历史。

## 备选方案

| 方案 | 评估 |
| --- | --- |
| 继续覆盖最新批次 | 无法看到各次提交和独立引用，不采用 |
| 创建新节点或持久卡片表 | 改变用户的同节点语义及存量格式，不采用 |
| 收起端点绑定最新结果 | 错误暗示旧边引用跟随最新结果，不采用 |
| 仅去掉Service忙碌校验 | SQLite仍拒绝第二个活动任务，不可用 |
| 派生历史与界面端点、最小索引升级 | 满足交互并保持图与任务身份，采用 |

## 后果

正面：再次提交立即可见，完成不跳位，各结果可独立引用；旧数据直接派生历史，不复制媒体、不重新生成。

负面：历史随任务积累，仍按当前全量快照加载，无分页 / 清理或大图容量承诺。多个卡片共享节点位置，展开后需用户平移查看；同节点也受全局队列1000与maxConcurrentTasks限制。

## 可逆性与重审条件

旧0.2.43仍可读取相同业务格式，其Service恢复单节点提交限制；非唯一索引不会被旧CREATE IF NOT EXISTS改回。候选失败优先恢复旧包 / profile，不能删除更新后接受的任务。确需恢复唯一索引时，先完成 / 处理该节点全部活动任务并备份，禁止用全库覆盖丢弃新数据。历史分页、节点拆分或改变引用方式时重审。
