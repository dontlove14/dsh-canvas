# ADR-0008：媒体复制、限额流保存与按需播放

状态：已替代

2026-10-26 由 [ADR-0015](0015-named-media-and-durable-moves.md) 替代。限额流与按需播放保留，文件布局改为名称路径和持久清单。

文档类型：解释；负责人：项目维护者；最近核对：2026-10-26。
补录日期：2026-10-26；原决策日期未单独留档。复核规则见[ADR 索引](index.md)。

## 背景与驱动因素

1. 本地原文件或供应商结果链接可能删除 / 过期，画布需要自己保存媒体字节。
2. 视频等大文件不能无限缓冲；声明 Content-Type / 长度不可信，需要按实际流限制。
3. 浏览器播放器需要 Range / HEAD，可见媒体才加载，以控制画布资源消耗。

## 决策

导入与生成结果复制到 UUID 本地文件；流累计限额、采集前缀签名、检查预期种类、临时文件 fsync / rename，失败清理临时文件。元数据 best effort，上传可由浏览器探测，不完整解码媒体。

认证媒体接口验证工作区资产归属，提供单段 Range / HEAD、私有不可变缓存、下载头；界面按可见区域挂载媒体，视频 / 音频默认暂停。参考输入和 Base64 响应仍会整体缓冲，不能声称全程流式或恒定峰值内存。格式见[模型协议](../providers.md)，限额见[运行配置](../operations.md)。

## 备选方案

| 方案 | 未选择的原因 |
| --- | --- |
| 只保存用户文件路径 / 远端 URL | 移动文件、链接过期或跨机器恢复会丢失 |
| 将媒体 Base64 内嵌 graph JSON | 图膨胀、全量序列化和修订冲突成本高 |
| 整体缓冲所有上传 / 下载后写盘 | 大视频内存峰值随文件增长 |
| 引入转码 / 完整媒体解码验证 | 首版增加外部程序和 CPU 成本，当前没有转码需求定义 |

## 后果

正面：本地拥有结果文件；流中字节检查避免无界上传；播放器可按需读取；视口外不持续播放。

负面：磁盘持续增长；签名不是完整格式 / 编码保证；部分尺寸 / 时长缺失；JSON / 参考图仍占内存；媒体与 Asset 登记不构成事务；媒体错误 JSON 边界存在已记录缺口。

## 可逆性与重审条件

可在媒体保存 / 读取边界引入校验器、转码或其他本机存储；必须保留 assetId 与旧文件可读性。目标编码需求、内存峰值、大媒体或磁盘清理需求明确时重审，基于实际负载取舍。
