# ADR-0004：宿主持有密钥与任务凭据快照

文档类型：解释；负责人：项目维护者；最近核对：2026-10-26。
补录日期：2026-10-26；原决策日期未单独留档。复核规则见[ADR 索引](index.md)。

## 背景与驱动因素

1. 用户要求本地保存 API Key 并脱敏显示；仅掩码输入框不能防止响应原文泄露。
2. 任务跨页面 / 重启运行，编辑模型 Key 或地址不能改变已提交任务的查询身份。
3. 密钥编辑要区分保留和清除；错误消息、备份与私有任务文件也可能包含敏感内容。

## 决策

原密钥由宿主 credentials 文件管理，公开 DTO 仅返回 has_api_key 和固定掩码；浏览器只在用户输入新密钥的提交请求中携带它。编辑缺省 api_key 保留，空串清除，非空替换。

任务单独保存提交时 key，公开 snapshot 不含 Key；终态完成 / 明确失败 / abandon 清理私有文件。新目录和文件限制 OS 权限，错误替换已知 Key / Bearer / URL。当前采用权限保护的明文存储，未接入加密或 Keychain。

## 备选方案

| 方案 | 未选择的原因 |
| --- | --- |
| 浏览器持久 Key 并直接调用模型 | 扩大浏览器持久暴露面，CORS 与任务恢复困难 |
| 从接口返回原 Key，只在 UI 隐藏 | 网络响应和浏览器状态仍持有原文，不满足隔离目标 |
| 所有任务总是读取最新 Key | 配置变化会影响已提交任务，无法保证原身份恢复 |
| OS Keychain / 加密凭据库 | 首版未引入平台适配和密钥解锁 / 备份恢复机制，可后续重审 |

## 后果

正面：常规读取不回显原密钥；保留 / 清除语义明确；旧任务配置编辑后仍按原身份处理。

负面：磁盘与备份持有明文；任务 Key 失效后没有 UI 更新旧任务凭据入口；脱敏不是全局安全边界；多文件写入并非事务。

## 可逆性与重审条件

可在 Store 凭据边界改用本机安全存储，保留公开 DTO 和编辑语义；迁移要同时处理运行中任务快照。共享机器、加密备份、密钥轮换或平台安全需求出现时重审。
