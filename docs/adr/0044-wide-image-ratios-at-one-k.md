# ADR-0044：图片1K档位补齐宽屏比例

状态：已采纳

比例显示顺序由[ADR-0045](0045-same-origin-waveforms-and-ratio-order.md)补充，原尺寸规则保留。

文档类型：解释；负责人：项目维护者 / 模型接入执行者；最近核对：2026-10-28。
记录日期：2026-10-28。更新[ADR-0037](0037-fixed-provider-image-models.md)的1K固定长边与超宽比例显示规则；其他目录、参数与请求原则保留。

## 背景与驱动因素

1. 用户截图的1K参数菜单缺少16:9、9:16、21:9，希望两款GPT Image 2.5模型均可选择。
2. 旧1K映射固定长边1024，使宽屏总像素低于655,360而被过滤；这不表示模型不支持该比例。
3. 原超宽标签7:3与用户需要的21:9数学等价，应统一标签并保留已有尺寸与任务身份。

## 决策

1K作为界面小尺寸档位，保留原七种尺寸，新增16:9=1280x720、9:16=720x1280、21:9=1344x576。这三个预设实际比例准确，宽高均为16倍数，总像素满足下限。尺寸仍通过原模型限制过滤，不把1024x576之类不足像素的请求放开。

2K / 4K保留原所有尺寸；超宽标签7:3改为21:9，尺寸仍为2048x880 / 3840x1648。16像素对齐使这些历史尺寸的实际比例略有取整，标签表示名义比例。悬停按钮继续显示实际WIDTHxHEIGHT。

共23个合法组合：1K十种、2K十种、4K三种。Sunburst / Flare的Model Link / OpenAI组合共用此表，分辨率切换按标签保留比例；参数摘要显示21:9。客户端控件读取能力表，不新增持久ratio字段，不修改已有节点size、任务快照或数据库。

GET models只增加能力预设 / 更新显示标签，POST生成仍发送既有size字符串。纯文本JSON和参考图multipart使用完全相同尺寸；原认证、请求ID幂等、错误分类、不明确提交不重提、已接受任务配置和OSS发布流程保持。非法size继续按原400校验拒绝。

## 备选方案

| 方案 | 评估 |
| --- | --- |
| 继续隐藏1K宽屏，让用户先切2K | 模型支持合法小尺寸，不能满足用户截图场景 |
| 直接提交1024x576 / 1024x432 | 不满足最低像素限制，可能被模型拒绝，不采用 |
| 改写全部旧尺寸或按面积重算所有档位 | 超出新增比例范围并改变历史参数，不采用 |
| 补三个合法1K预设、统一21:9标签 | 请求合法，保留其他尺寸与历史身份，采用 |

## 后果

正面：1K即可选择三种目标比例，两个模型与供应商行为一致，切档保留比例；旧节点、图与任务无需迁移。

负面：1K宽屏长边并非固定1024，实际尺寸须以按钮悬停值为准；2K / 4K超宽仍保留16对齐近似比例。真实供应商账户输出需人工验收，文档支持与协议替身不等于真实生成成功。

## 可逆性与重审条件

供应商改变最低像素、16对齐或边长限制时重审表；未来比例改动仍保持旧size可读。回退使用上一已核验包与配置备份，不重写任务或触发新生成。

## 验证与证据

2026-10-28核对[OpenAI生成接口](https://developers.openai.com/api/reference/resources/images/methods/generate?site_locale=en)：两款2.5模型支持自定义WIDTHxHEIGHT、16对齐、比例1:3至3:1。像素范围与边长由[fal Flare文档](https://fal.ai/models/openai/gpt-image-2.5/flare/text-to-image/api)和[Pixapi Sunburst文档](https://pixapi.ai/docs/models/gpt-image-2.5-sunburst/)交叉核对；只采用共同尺寸约束，不引入其他渠道的数量 / 引用 / 计费规则。无需增加第三方厂商。
