# ADR-0074：Agent 参考素材、归档、过程说明与工作区交付

文档类型：解释；负责人：项目维护者 / 开发执行者；最近核对：2026-10-30。

状态：已采纳
记录日期：2026-10-30

本轮按用户四项反馈执行；以下是实施边界，自动化和本机加载完成后更新状态与证据。补充 [ADR-0071](0071-shared-canvas-agent-preset-and-control.md)、[ADR-0072](0072-agent-presentation-navigation-and-readonly-inspection.md)，保持原 CanvasGraph、两库 Schema、媒体任务身份和真实 Agent 控制机制。

## 背景与驱动因素

1. 用户在产品宣传需求中上传了保温杯图片并要求对应产品，Agent 却只描述外观，没有把真实图片导入为生成参考。必须让已提供媒体进入实际引用链；风格灵感、问题截图等是否导入由 Agent 按用途评估，不自动导入所有附件。
2. 用户要求 Agent 新建画布归入「Agent 创作」，缺少文件夹时先创建并简短告知。当前 `canvas_open` 没有 folderId；创作记录只在 sidecar 保存，未交付到当前工作区。
3. 当前画布已有操作呈现回执，但对话中可能直到完成整批操作才有正文。关键步骤应在执行时简短可见，同时不能伪造模型输出或方案批准。
4. 用户要求全部创作文档保存到当前工作区；生成媒体默认留在现有存储，仅按用户要求下载，并按项目、文档、图片、视频、音频分类。不能扩大为通用文件系统权限。

## 决策

采用单插件内的受控附件与工作区模块，共享现有 CanvasService、原生会话身份与持久台账。主 Agent 负责导入、文件保存和交付，子 Agent 仍只读必要事实并返回草稿。

| 上下文 / 负责人 | 模型与职责 | 上下游及关系 | 失败边界 |
| --- | --- | --- | --- |
| 原生会话附件 / 原生 SDK | 用户消息中的 image / file durable ref | 上游用户消息；插件按既有附件模型读取（conformist） | 不接受任意附件 ID、路径或 URL；只匹配真实当前根会话用户附件 |
| Agent 附件模块 / 执行者及专项 | 已提供素材、用途、导入 taskId / nodeId / assetId | 翻译原生 ref 到既有 Uploads 输入（anti-corruption layer） | 校验大小 / 类型 / 取消；导入未完成不假报可引用，不以文字替代失败素材 |
| CanvasService / 既有服务专项 | 画布目录、素材、引用、持久任务 | 与控制服务共享内核（shared kernel） | 当前 revision、真实 assetId、模型能力及接管 guard 继续生效 |
| Agent 工作区模块 / 执行者及路径专项 | 文档版本、媒体导出、文件回执 | 上游原生 workingDirectory；下游当前工作区受限项目目录（customer / supplier） | 非工作区路径、符号链接越界、碰撞、取消或根目录变化均拒绝 |
| 对话过程说明 / 执行者及原生 Chat 专项 | tool/call 开始、tool/result 完成或失败 | 从原生事件投影到插件自有 Chat 节点（conformist） | 不插入假 assistant/message，不占用原生工具、计划或模型选择组件 |

### 附件与一致性

读取根 Agent 会话日志里真实 `user/message` 的 image / file 引用，排除插件自行追加的图片理解上下文。检查 attachmentId 归属后，通过 `ctx.attachments.readImage` 或 `readFileStream` 读取；普通文件需要识别支持的媒体格式。内联图片使用 Harness 已持久化的用户图片，不使用模型请求缩略版本；Harness 入库时可能已经规范化，不能声称还原丢失的原始编码。file 类型附件保留其已提交字节。

导入复用 `Uploads.start / accept` 与现有任务发布流程，得到实际资源节点和持久任务。沿既有 referenceConnection 校验建立真实引用；有产品、人物、服装等身份一致性要求时优先采用提供的素材。模型不支持该参考类型时明确说明并选择受支持路径，不静默退化为纯提示词。所有新入口复用操作 ID、取消信号、控制 epoch 与提交前复核。已接受导入的结果保存仍由 Host 持有。

### 归档与存量

Agent 创建入口串行创建或复用唯一名称「Agent 创作」文件夹，再用现有 catalogCommand 创建画布。返回文件夹名称和是否本次创建，提示中要求告知实际结果；同一操作重试沿真实目录回执，不因名称或目录变动重建画布。

记录可核实的 Agent 创建身份。已有未归档画布只在实际工具调用 / 创建回执能够证明由 Agent 新建时整理；人工画布不按名称猜测。存量整理使用原目录移动操作，保留画布、节点、素材、模型、任务与生成快照身份，并单独核验用户授权的目录元数据变化。

### 实时简短说明

主级关键工具接受有界步骤说明，缺少时使用与真实动作相符的短句。客户端观察实际 `tool/call`，在原生 `conversation.chat.node` 注册插件自有种类，立即显示这步将做什么；观察关联 `tool/result` 更新失败或已提交状态。新节点不独占原生事件，不改变工具结果、会话历史或模型流。

结合主提示词要求每个语义步骤简短说明，等待实际呈现回执后继续；不能到完成整批后才第一次告知。说明意图不代表生成成功，最终回复仍以 taskId 和实际产物为准。按原生 Chat 可见与分组契约核验，不能把短说明全部折叠进最终答复前的过程面板。

### 当前工作区与交付结构

当前目录从真实根 Agent 的 `ctx.workingDirectory.ensure(agent, signal)` 取得，每次写入和落盘前复核；不能固定为插件仓库、启动目录或 Agent 提供的任意绝对路径。

建议结构为 `Agent 创作/<项目名及短ID>/文档/<分类>/...md` 与 `Agent 创作/<项目名及短ID>/媒体/图片|视频|音频/...`。项目尚未创建时以当前会话身份命名临时项目目录；已产生文件的项目位置需有回执，切换工作区不重放到旧目录。文件命名使用安全显示名、版本和实际 ID，已存在的同内容可幂等返回，不覆盖用户修改或同名其他内容。

`canvas_review_plan`、`canvas_draft` 和主级取得的专业草稿均将完整 Markdown 保存并返回实际文件位置；额外文档由受控文档工具保存。写入失败明确返回，不把内部草稿存在当作已交付到工作区。

媒体导出只在用户要求下载时使用主级受控工具。读取当前画布真实素材的原始 locator，流式下载并验证大小与摘要，成功后发布到对应媒体目录；不默认导出所有生成结果。失败或取消清理未发布的临时文件，不覆盖既有文件，不重新生成媒体。

## 备选方案

| 方案 | 未采用原因 |
| --- | --- |
| 只补提示词，继续用文字描绘用户原图 | 工具缺失仍使模型无法把真实附件连接到生成请求 |
| 向 Agent 开放通用终端 / 文件系统 / SQL | 扩大身份与路径权限，绕过当前素材和任务校验 |
| 再建素材库、任务系统或修改 CanvasGraph | 不需要独立扩容，增加数据与费用状态不一致风险 |
| 直接伪造 assistant/message 来显示过程 | 混淆实际模型输出、流记录和会话历史，原生工具事件已有可靠来源 |

## 后果

正面：真实参考能进入生成链，画布有固定归档位置，过程可见，创作文档交付到当前工作区；复用现有媒体和权限服务。

负面：增加附件归属、受限路径、文件幂等与原生 Chat 节点适配；跨工作区 / 目录重命名和 SDK 变化需要复核。原生图片规范化无法由插件逆向恢复原始编码。

## 可逆性与重审条件

保持模块化的可逆边界；移除新增主级工具与 Chat 组件即可恢复原行为，旧画布和媒体任务继续可读。回退保留已交付文档和新增台账回执，不删除用户文件，不重提交生成。

SDK 提供稳定的自定义过程说明或附件原始文件入口时重审适配；多用户共享工作区或需要任意文件编辑时另立权限决定。执行者负责路径、身份、原生事件和安装专项；用户负责参考一致性、聊天节奏和浏览器视觉验收。
