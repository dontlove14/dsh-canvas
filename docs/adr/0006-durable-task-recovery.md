# ADR-0006：持久任务恢复与未知提交不重提

文档类型：解释；负责人：项目维护者；最近核对：2026-10-26。
补录日期：2026-10-26；原决策日期未单独留档。复核规则见[ADR 索引](index.md)。

## 背景与驱动因素

1. 视频任务持续时间长，刷新 / 宿主重启不能丢失原供应商任务或重新产生付费提交。
2. 网络错误不能证明供应商没有接受请求；本地必须保留“不确定”而不是盲目重试。
3. 生成成功与下载保存成功不同，保存失败应恢复同次结果，不重新调用生成。

## 决策

先持久登记任务快照与私有凭据，再在发送前持久设置 issued。保存供应商 ID / 输出描述后继续查询 / 保存；已发出且无可恢复 ID / 输出的任务进入 unknown，不自动重提。

tracked 状态锁定节点与模型。明确失败解锁；unknown 有 ID 时允许恢复查询；save_failed 使用原输出描述 / ID 重存。用户可明确 abandon，但不会调用供应商取消，下一次生成提示重复计费可能。状态 / 动作详见[业务参考](../business.md)。

## 备选方案

| 方案 | 未选择的原因 |
| --- | --- |
| 页面内 Promise 持有整个任务 | 刷新丢失状态，任务身份无法恢复 |
| 网络错误一律自动重提 | 无幂等保证时可能重复生成和计费 |
| 错误一律 failed 并允许直接重试 | 抹去提交已被接受的可能，无法提示风险 |
| 按供应商幂等键实现可靠重试 | 当前协议适配未提供可统一依赖的幂等 / 对账能力 |

## 后果

正面：原视频 ID 和凭据可恢复；不明确提交不盲目重提；保存重试复用输出，已存部分跳过。

负面：保守 unknown 可能需要人工核对；不能取消远端任务或保证 exactly-once；跨文件崩溃窗口、私有文件损坏和 URL 过期仍会阻断恢复；查询不设最大次数。

## 可逆性与重审条件

持久任务与适配器边界可增加幂等、取消、对账或链接刷新；必须保证旧任务按原身份恢复且不因迁移再提交。真实供应商具备可靠能力、任务量增长或需要独立 worker 时重审。
