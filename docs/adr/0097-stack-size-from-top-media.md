# ADR-0097：堆叠卡片尺寸跟随最上层媒体

状态：已采纳

文档类型：解释；负责人：项目维护者 / 开发执行者；最近核对：2026-11-11。
记录日期：2026-11-11。用户要求相同图片 / 视频在单张和堆叠时尺寸一致。补充[ADR-0050](0050-submission-history-and-expanded-result-ports.md)的展示几何，保留[ADR-0051](0051-readonly-submission-inspection.md)的历史输入与引用规则。

## 背景与驱动因素

1. 单张生成结果会按已读取封面的实际宽高更新mediaFrame。历史堆叠原先忽略解码尺寸，元数据缺失时一直保持320×180横图框，导致相同竖图 / 视频在堆叠中明显缩小。
2. 历史节点外层强制最小320宽，即使顶层媒体已是270×480，节点与背后叠层仍会宽于首张卡片。展开历史和只读编辑锚点也需要使用相同几何，避免尺寸修复后端点与编辑框错位。

## 决策

1. 收起时historyFrame使用最新提交的首份结果，按现有mediaFrame规则计算尺寸，与单张展示共用320宽 / 480高的显示上限；外层宽高与首张卡片一致，取消额外320最小宽限制。不按旧卡片、历史最大尺寸或完成顺序决定收起尺寸。
2. 解码得到有效宽高后，仅记录当前节点 / assetId的显示尺寸。HistoryNode可本地记录，CanvasWorkspace按节点共享测量；无效、重复测量不更新。无结果 / 尚未读取时沿用原占位，音频仍为360×180。
3. 展开时每次提交的首份结果决定该卡片和组内格子尺寸，保留原两列布局与间距。只读历史编辑锚点使用相同测量计算前置卡片高度、行列偏移和当前格子大小。
4. Canvas节点尺寸缓存身份包含历史首份媒体的尺寸；测量后同步React Flow边界和端点，仅所属节点改变数据 / 内容 / 几何。测量按assetId隔离，最新媒体切换时不复用旧素材尺寸。
5. 测量只存在浏览器状态，不改Asset、CanvasGraph、SQLite、模型参数或任务快照。不重排历史、不改写引用、不重新生成媒体，叠层偏移 / 旋转和Loading效果保持。

## 备选方案

| 方案 | 评估 |
| --- | --- |
| 所有堆叠固定横图尺寸 | 竖图 / 方图被缩进横框，不采用 |
| 按历史最大卡片尺寸统一收起 | 当前最上层素材仍可能留白或缩小，不采用 |
| 将解码尺寸写回数据库 | 显示信息侵入持久资产与历史，未采用 |
| 首份媒体尺寸与按节点临时测量 | 单张 / 堆叠一致，展开与锚点同步，采用 |

## 后果

正面：相同宽高比素材在单张和堆叠中按相同上限展示，竖图不会停在横图框；节点边界、叠层和历史编辑位置一致。

负面：元数据缺失时需等封面加载取得尺寸；测量缓存随当前画布生命周期存在，重新进入可能先显示占位。异形批量输出仍沿用本次提交首份结果的格子规则，不扩展为独立拼贴布局。

## 可逆性与重审条件

可独立调整显示上限或展开布局，不迁移存量数据。增加任意比例批量拼贴、动态旋转或历史分页时重审；保持实际素材与显示测量的独立身份。
