# ADR-0065：画布文件拖放与宿主附件互斥

状态：已采纳

文档类型：解释；负责人：项目维护者 / 开发执行者；最近核对：2026-10-29。
记录日期：2026-10-29。宿主拖放监听、画布挂载或命中范围变化时复核。

## 背景与驱动因素

1. 对话页右侧画布的React drop仅阻止默认动作，事件仍冒泡至Harness附件组件的document监听。同一文件进入画布和Agent输入框，用户要求以松手位置决定唯一接收方。
2. 画布拖入时显示Agent的图片数量 / 大小限制蒙版；这些限制与画布无关，需要隔离直接拖入及左右跨区的状态。

已核对Harness附件包0.2.1-rc.2：installDocumentDropEvents在document冒泡阶段监听文件dragenter / dragover / dragleave / drop，window dragend清空深度和蒙版；蒙版pointer-events:none，不影响底层命中。不能用宿主生成的CSS类名隐藏蒙版，也不修改已安装宿主包。

## 决策

[canvasFileDrop](../../src/client/canvasFileDrop.ts)在window捕获文件拖放；每次检查画布仍挂载、页面可见、正尺寸矩形与视口相交、鼠标位于该范围，并由elementFromPoint确认顶层命中属于画布。没有命中API时才回退事件目标，同时保留坐标 / 可见范围检查。header、项目列表、隐藏侧栏及画布上方独立弹窗不属于接收区域。

命中时preventDefault / stopImmediatePropagation并设copy，阻止事件到达宿主附件监听。第一次接管通过无载荷的window dragend调用原宿主清理路径，清掉从Agent区域移入时已出现的蒙版；后续dragover不重复清理。drop同步复制原File列表和屏幕坐标，直接调用一次当前工作区上传回调；原screenToFlowPosition、350px间隔、格式报错、缓存 / UUID、五路续传和胶囊保持。移除旧React文件drop处理，不复制或重放drop事件。

最终drop重新校验坐标，不能仅相信旧事件目标。画布外不添加到画布，保留宿主原处理；画布内不支持的文件仍由画布报错，不回退加入Agent。非文件文字、节点和编辑器拖动不被接管。

跨区时浏览器先发新区域dragenter，再发旧区域dragleave。画布内部目标发出的文件dragleave必须隔离，即使当前坐标已在Agent；否则宿主从未计入的画布enter对应leave会减掉Agent刚新增的深度。画布外来源的leave仍交给宿主。

hook通过已提交回调引用读取当前工作区 / 图和上传逻辑，不随进度重订阅。active / 页面隐藏和卸载移除本绑定的全部监听。多个挂载画布按顶层命中选择唯一拥有者，无全局CSS或宿主实例改写。

## 备选方案

| 方案 | 评估 |
| --- | --- |
| 仅React drop停止冒泡 | 不能阻止此前dragenter产生的宿主蒙版 |
| 全局禁用宿主文件拖放 / 隐藏其蒙版 | 会破坏画布外Agent行为，并依赖私有CSS |
| 拦截后重放drop | 增加重复上传和原File / 坐标丢失风险 |
| 按可见画布命中捕获并直接调用 | 接收方互斥，保持原上传与宿主外部行为，采用 |

## 后果

正面：侧栏与全页画布文件只进入当前落点对应接收方；Agent限制不显示在画布；原接口、两库结构、媒体和任务不变。

负面：与已核实宿主原生监听阶段及dragend清理契约相关。宿主若改为更早的window捕获或改变清理语义，升级时须重新做集成验证。真实系统拖放次序与蒙版观感仍由用户验收，不以DOM / HTTP测试替代。

## 可逆性与重审条件

仅Client监听与回调装配，可回退0.2.66且保留相同缓存 / 上传身份和用户数据；回退会恢复原重复附件问题。宿主监听阶段、dragend清理语义、画布挂载或命中范围变化时重审。

## 验证与证据

[专项](../../tests/canvasFileDrop.test.tsx)覆盖唯一原文件 / 坐标回调、直接拖入无Agent蒙版、左右跨区次序、最终坐标、无效文件 / 文字、隐藏 / 空尺寸 / 视口 / 弹窗、fallback / 清理、多个画布及最新回调 / tab隐藏。[真实工作区回归](../../tests/canvasPerformance.test.tsx)验证按钮和拖放可追加同一续传管理器，媒体内容不随进度刷新。独立离线烟测提取实际宿主的两个纯函数，在jsdom与本绑定共存，核对双方蒙版 / 上传回调；不加载浏览器、不接触真实云端。全量、双构建、同包安装 / 实际preload与两库身份见0.2.67 manifest，人工272–275。
