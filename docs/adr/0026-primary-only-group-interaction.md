# ADR-0026：媒体本身作为生成节点与主图专属分组交互

状态：已采纳

2026-10-28更新：本规则继续用于单次批量；多次提交历史改按[ADR-0050](0050-submission-history-and-expanded-result-ports.md)展开逐素材端点且无主图选择，收起无可见输出，存储边assetId保持。

文档类型：解释；负责人：项目维护者 / 开发执行者；最近核对：2026-10-26。
记录日期：2026-10-26。结果分组、端点或编辑面板规则变化时复核。

## 背景与驱动因素

1. 用户验收0.2.10时指出生成媒体后方仍有父卡片边框，端点不圆且字体加号偏心，要求媒体展示与资源节点一致。
2. 用户明确多结果是“抽卡”：只有主图连接下游，展开时不显示编辑卡片；收起按钮固定在左下结果右上角，不随主图变化移动。

## 决策

更新[ADR-0025](0025-generation-groups-and-local-mock.md)的分组交互部分，Mock执行、任务 / 媒体持久化和主图保存原则继续使用。

有生成结果时父容器不画背景、边框或阴影；选中轮廓只作用于实际媒体画面。空占位保留简单媒体图标。所有端点用正方形SVG画圆和中心十字，不依赖字体基线。

展开分组只在当前主图上渲染默认输入 / 输出端点，无组级或非主图端点。新连接只绑定主图，旧边的assetId保持；切换主图后旧边的显示位置跟随当前主图，但历史实际引用不改绑。移除逐结果sourceHandle显示映射，不改变图 / 边DTO、数据库结构或存量引用。

展开时隐藏下方编辑卡片，选择任何结果或切换主图也不出现；收起后按原选择逻辑恢复。收起按钮固定在最后一行左侧结果右上角：4份第3份，2份第1份，部分保存3份为第3份。每份下载和非主图的设主图入口保留。图片 / 视频采用同一规则。

## 备选方案

| 方案 | 评估 |
| --- | --- |
| 只用CSS隐藏非主图端点与编辑卡片 | 留下不可见的可连接目标或编辑控件，不采用 |
| 切换主图时改写全部旧边assetId | 会改变既有下游输入，不采用 |
| 重建独立子节点或迁移分组表 | 本轮无此需求且破坏存量边界，不采用 |
| 只渲染主图端点，保留具体旧引用 | 满足抽卡交互和数据兼容，采用 |

## 后果

正面：媒体没有额外外框，端点形状与居中明确；展开专用于挑选结果，收起入口固定，主图连线规则清晰。

负面：新UI不能从非主图结果直接拖出连线，需先设为主图；旧边显示端点可能与其实际引用的历史结果不同，但既有任务输入不会被静默替换。

## 可逆性与重审条件

若以后要求同时使用多个候选结果，应另立交互决定；不得自动改写存量边。此轮没有存储迁移，恢复旧展示可通过版本回退，既有媒体和任务身份保留。
