# ADR-0095：长时间停留画布的媒体换签与失败恢复

状态：已采纳

文档类型：解释；负责人：项目维护者 / 开发执行者；最近核对：2026-11-11。
记录日期：2026-11-11。用户批准补齐刷新机制。补充[ADR-0043](0043-object-storage-and-expiring-media-access.md)的Client恢复生命周期，保留对象定位、签名时限、鉴权、Host缓存和任务参考规则。

可见性通知的目标、时间与观察清理由[ADR-0096](0096-latest-element-visibility-notifications.md)补充，原换签和失败恢复策略保持。

## 背景与驱动因素

1. 页面预签名GET链接保持1小时有效。已解码图片通常不会因链接过期立即消失，但移动画布重新挂载、恢复标签页、播放或seek会发起新请求。原实现虽然提前5分钟检查，但节点终态媒体错误会移除图片组件，导致共享刷新订阅随之丢失；组件生命周期只有一次重试，也不能覆盖后续独立故障。

2. 刷新需要覆盖资源节点、生成结果、历史素材与原文件预览。大画布不能全量签名或持续重新下载；临时故障必须可恢复，持续权限或文件错误不能形成无限换签。

## 决策

1. 沿用`assetId / variant`与现有数据库、CanvasGraph。共享Client缓存以`canvas / assetId / variant`隔离，URL、过期时间与内部换签revision只在内存中存在；revision不进入HTTP DTO或持久数据。
2. 可见资源每分钟检查，剩余不足5分钟更新。离屏资源暂停订阅，进入视口检查旧缓存；`visibilitychange`、`focus`、`pageshow`和`online`对当前订阅资源立即检查，隐藏或离线时暂停检查。
3. 同素材节点共享请求和每轮强制换签额度；普通读取必须等待在途换签，不能返回已知失败的旧缓存。每批仍最多100项，缓存仍最多2048项；更新只通知对应资源，有效缓存不产生无效React状态更新。
4. 图片加载 / 解码或音视频加载失败，每轮最多强制换签一次。新URL取得本身不重置额度，确认新媒体成功加载后才重置；正常到期更新、恢复页面 / 网络或资源重新进入视口可以开始新轮次。持续失败停止强制换签，保留错误和订阅；后续到期检查仍有界执行，不永久移除媒体组件。
5. 换签期间保留同素材的已解码图片，后台预加载和解码新地址，成功后切换。新图失败保留旧图并显示错误；换素材或API实例立即隔离旧源，取消旧预加载 / 解码回调。同秒签名得到相同URL时按内部revision重新加载，不擅自追加签名查询参数。
6. 播放和seek先核对URL，新地址和元数据准备完成后再执行；连续动作以最后一次为准，卸载 / 切素材后的旧动作失效。源更新恢复播放位置、播放状态、音量、静音和倍速；换签等待期间暂停或音频停用不会被旧回调再次播放。媒体换签可能仍有正常缓冲，不承诺零中断。

## 备选方案

| 方案 | 评估 |
| --- | --- |
| 延长所有页面URL时限 | 故障仅延后，不能覆盖长时间停留，未采用 |
| 每小时刷新整个页面或全图资源 | 破坏操作状态、增加大画布请求，未采用 |
| 每次失败无限换签 | 权限 / 文件错误会形成请求风暴，未采用 |
| 保留共享缓存，按可见性与恢复轮次换签 | 兼顾长时使用、恢复与请求上限，采用 |

## 后果

正面：长时间停留、移动视口和暂时断网后资源可恢复，失败状态保留订阅，重复素材共享换签。无需重提生成任务、修改素材与任务身份、迁移数据或替换Loading效果。

负面：额外内存包括共享恢复状态和换签期间可见图片的短暂预加载；URL更新可能需要重新下载媒体，音视频可能短暂缓冲。真实Bucket权限、浏览器缓存和自动播放限制仍需人工验收。

## 可逆性与重审条件

可单独调整Client恢复轮次与可见订阅，不迁移持久数据。签名服务增加STS、媒体下载成本或缓存驱逐出现实测问题时重审；不得通过无限换签或自动重生成掩盖权限与资源身份错误。
