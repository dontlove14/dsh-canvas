# ADR-0105：经核验创作方法与角色内按需工作表

文档类型：架构决策记录；负责人：项目维护者 / 开发执行者；最近核对：2026-11-13。

状态：已采纳
记录日期：2026-11-13。
补充[ADR-0104](0104-agent-skills-and-host-authority.md)，用户先选择完善分镜、编剧、音频和审查，后选择视觉资产3项、主Agent4项与共享4项；共享准备阶段明确“先不要自己重启服务。先改完再说”，检查完成后另行授权“现在可以重启服务了”。

## 背景与驱动因素

1. 初版28个Skill已具备加载与权限控制，但13个创作方法正文较短，镜头动机、因果、对白估时、声画衔接与证据审查需要可操作的细节和正反例。
2. 用户已审阅ClawHub候选。其方法与本项目部分契合，项目目录、REF/PLAN身份、英文默认、角色分工、外部生成/混音/转写和静音策略则不能直接移植。
3. 专业方法变长后仍须按任务读取；工作表不能只存在源码目录或成为跨角色读取入口，来源及更新需要可核对。

## 决策

保持8角色、28个稳定Skill名称、原最小必备组合与工具权限。0.2.145更新shots的4份、story的3份、audio的3份、review的3份正文；每份提供一份角色内随包只读工作表，共13份（扩展原序列模板，新建12份）。

0.2.146追加assets的3份正文与3份按需工作表，累计16份已完善方法与16份资源。资产设计按证据判定复用/变体/新身份/未决，区分身份、持续状态、固定地理与镜头瞬态；一致性方法记录可见不变量、变化范围和真实历史依赖；生图规格按用途选择视图，写参考控制范围、文字约束及局部编辑的目标/变化/保持/连续性影响。其余25份正文与宿主权限实现保持原内容；这些工作表不是新的图字段、自动检查器或图像清理能力。

0.2.147追加main的4份正文与4份工作表，累计20份已完善方法与20份资源。统筹按本轮终点、可复用成果、最小缺口和真实依赖派工；方案区分已有授权、必要决定、节点准备及原任务结果；执行清单沿现有`{tool,input}`、稳定ID、CAS/epoch和回执，未来节点/素材ID必须等待实际回执；音色方法区分稳定声音与单句表演，已有ID直接使用，真实试听仅依原TTS任务和用户反馈。主级required仍为空，正文/资源按任务读取，专业角色不能读取新增main工作表；其余24份正文/资源、8角色与宿主权限实现保持0.2.146内容。

2026-11-13基于已安装0.2.148，仅完善common的4份正文与4份按需工作表，源码累计24份已完善方法/24份资源。原文读取区分目录游标、UTF-16半开citation/正文next、本批已读与旧成果依赖；模型参考按实际模式预算、生成当时依赖及每份控制用途核对；提示词区分静态瞬间、动作预算、声画与局部修订；成果交接沿独立ID、完全相同请求复用、真实保存回执与部分失败证据。其余24份正文和既有20份资源保持，8角色的capabilities/required、宿主授权与工具契约不变。

“共享”按原角色矩阵读取，不是八角色全量开放：main/assets/shots可读4份；story/audio/review可读来源、参考、成果3份；voice可读来源、成果2份；executor仅可读成果1份。主级仍不读原文或调用专业保存接口，executor仍不保存创作草稿；工作表不自动进入正文上下文。

源码准备阶段保持package/lock为0.2.148，不打包、不安装、不停止或重启web / 3080。产物核验显式使用`CANVAS_ARTIFACT_SOURCE_ONLY=1`，将`.source-only.manifest.json`写入受限临时checkDir，并标`verificationMode: source-only`、`installed: false`；原发布命令输出位置不变，已安装0.2.148根manifest和tgz不覆盖。

用户随后授权重启，共享内容以0.2.149发布；package/lock同次更新、按原管线重新核验、打包、安装和正常重启web / 3080。发布核验使用默认manifest输出，source-only准备证据保留为历史阶段；实际安装须比对同一包全部文件/Skill身份及HTTP真实preload，核对原配置、数据和任务，不能只重启旧插件或把准备阶段核验当安装证据。

正文是how-to，保留输入、步骤、专业判断、交付、检查与阻塞；工作表是reference，包含填写骨架和具体正反例，仅按正文触发由canvas_skill_resource取用。不在每次上下文加载全部参考资料，不运行其模板或脚本，不赋予新的观看/试听/剪辑能力。

来源按[身份记录](../agent-skill-content-sources.json)保留公开URL、核对日期、正文SHA-256、原页面/内容许可与用途；[NOTICE](../../NOTICE.md)记署名与许可。内容为本项目重新整理的工作方法，原套件命令、自动spawn、生成器、外部音频判断、混音/转写、缓存绕过及恢复删除流程不进入插件。

保留默认中文、视频原生声音开启、用户已有Fish ID直接使用、TTS单参考/ID互斥、真实边/token、独立成果ID、人工生成与精确任务回执。用户只要求无音乐不扩大成整镜无声；旧false任务和旧认可成果不迁移。估时、示例和外部实验均不作为当前模型实测结论。

## 备选方案

| 方案 | 判断 |
| --- | --- |
| 整体安装外部套件并放开工具 | 与角色、真实数据身份和生成授权不一致，不采用 |
| 将所有专业资料写入每次提示词 | 会重复堆积上下文，采用短正文与按需工作表 |
| 只加文字、资源不打包 | 离开源码不可用，正文/工作表同次编译并核验 |
| 审阅后按当前接口重新整理 | 采用；保留来源身份且不把方法当权限 |

## 后果

正面：主级得到具体派工、续作、方案/节点交接与音色协调方法，专业角色得到因果、导演、镜头状态、声音预算、TTS与证据审查方法；共享内容统一真实阅读范围、参考控制、提示词和保存交接，示例可直接帮助理解输入/交付，角色和历史状态保持。

负面：更多工作表需要持续维护与资源清单核验；静态方法和替身模型检查不能证明真实创作质量，最终画面、声音与表演仍需用户观看/试听。

## 可逆性与重审条件

0.2.145沿既有web/3080交付，成功前保留0.2.144包；0.2.146成功前保留已安装0.2.145包；0.2.147成功前保留已安装0.2.146包。失败恢复旧插件/profile，不清数据、不撤销已存成果、不重提任务。未来新增Provider、生成/转写/混音/视频理解、角色或权限须按0104重新评估，本次仅完善第二层方法与只读资源。

共享源码准备阶段保留0.2.148、原包、发布manifest与监听进程；0.2.149发布成功前保留0.2.148可用包回退，成功后按ADR-0021清理根目录过期包并保留历史manifest。原数据、来源、成果、认可与媒体任务不回退或重提；source-only核验不能当安装或用户手验。
