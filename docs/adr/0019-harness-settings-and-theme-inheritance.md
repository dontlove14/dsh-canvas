# ADR-0019：原生设置样式与宿主主题继承

状态：已采纳

文档类型：解释；负责人：项目维护者；最近核对：2026-10-26。
记录日期：2026-10-26

## 背景与驱动因素

1. 原“生成模型”名称无法区分 Harness 原生模型设置与画布生成协议，用户要求改为“无限画布 模型设置”。
2. 用户截图显示浅色宿主设置窗口内嵌固定深色矩形；标题、列表、表单与原生设置页面的间距和材质不一致。
3. Harness 已拥有浅色、深色、跟随系统和第三方别名覆盖机制。插件另存主题或直接监听系统会使宿主固定浅色与系统深色发生冲突。

## 决策

- 保留 `settings.section` 的稳定 ID `canvas-models`，只更改显示名称；画布快捷弹窗继续复用同一模型配置组件。
- 按用户参考图的版式使用原生字号、分段标签、圆角模型卡片、柔和表单底色和按钮；保留已有模型字段与增删改逻辑。
- `--dc-*` 绑定 Harness 的 `--dsw-alias-*`。背景、文字、边框、按钮和状态读取语义色；设置卡片读取 `--dsw-alias-settings-card-fill/stroke`。
- 同时覆盖项目列表、画布节点与编辑器、网格、连线、控件、小地图、存储 / 任务 / 媒体弹窗。SVG 与媒体像素不改色。
- 继承宿主 `color-scheme` 与字体。插件不新增主题状态、偏好存储、DOM 观察器或逐节点主题订阅；CSS 在宿主变量改变时更新。
- 缺少宿主主题变量时使用深色兜底，开发入口单独声明深色 `color-scheme`，不改宿主文档属性。

## 备选方案

| 方案 | 评估 |
| --- | --- |
| 保留固定深色，只把设置页改白 | 画布与弹窗仍脱离宿主，宿主深色时设置页又不一致，不采用 |
| 插件自己保存主题并监听系统 | 产生两个主题权威，无法正确遵循宿主固定偏好，不采用 |
| 通过 React 订阅主题并给每个组件传颜色 | 此次仅有样式需求，增加状态更新与颜色复制；保留给未来确有非 CSS 行为的场景 |
| 消费宿主语义变量 | 使用官方颜色权威，覆盖自定义别名与即时切换，采用 |

## 后果

正面：宿主切换主题即改变插件配色，表单与图状态不重置；两处模型设置样式一致，不增加用户配置。

负面：主题变量名称属于目标 Harness SDK 的接入契约，SDK 变更时需复核。主题缺失只能使用兜底，不承诺独立开发页具备宿主的主题设置功能。

## 可逆性与重审条件

本次不改变 API、数据库、媒体布局或凭据。拥有可用的旧包时可停止实例后回退；压缩包保留遵循 [ADR-0021](0021-local-update-and-package-retention.md)，不能假定已清理的0.2.1包仍在根目录。若 Harness 更改语义变量或未来需要程序化主题行为，再评估 `ctx.theme` 快照订阅。

## 验证与证据

- 已核对已安装 Harness `0.2.1-rc.2` 的 `@deepseek-ai/dsh-client-ui-theme` README / bundle：官方要求功能插件使用 `--dsw-*`，主题使用 `body[data-ds-dark-theme]` 选择色板。
- 同版本 `@deepseek-ai/dsh-client-ui-layout` 的 ThemePresenter 将解析后的主题应用到根 `color-scheme`、body 色板属性和别名覆盖，跟随系统由宿主解析。

- 编译与包检查见[验证记录](../verification.md)。真实设置窗口宽度、切换主题与输入保持由用户按[手动清单](../manual-tests.md)65–67执行，静态检查不代替浏览器视觉验收。
