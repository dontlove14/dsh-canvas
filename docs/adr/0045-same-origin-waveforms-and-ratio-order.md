# ADR-0045：同源波形读取与比例菜单排序

状态：已采纳

文档类型：解释；负责人：项目维护者 / 开发执行者；最近核对：2026-10-28。
记录日期：2026-10-28。部分替代[ADR-0043](0043-object-storage-and-expiring-media-access.md)的波形307读取，补充[ADR-0044](0044-wide-image-ratios-at-one-k.md)的比例显示顺序；媒体持久位置、旧尺寸与任务规则保留。

## 背景与驱动因素

1. 用户在接入OSS后看到“波形暂不可用，仍可播放”。两份音频的云端波形均为有效96项JSON，但OSS响应没有允许当前来源的CORS头；音频元素可播放，浏览器fetch读取JSON被拦截。
2. 用户要求所有生图模型按1:1、2:3、3:2、3:4、4:3、4:5、5:4、9:16、16:9、21:9顺序显示，只显示参数允许的项；明确纠正不需要25:9或9:25。
3. 波形只有少量幅度数据，适合通过认证Host返回；不能为修复波形而公开Bucket、持久保存原媒体或重提TTS任务。

## 决策

认证media接口的waveform GET直接返回200与原云端JSON，HEAD返回同样的Content-Type / Content-Length且无正文；均no-store、nosniff，不跳转到OSS。读取前校验当前画布素材归属，云端对象定位来自DB；读取字节数 / SHA与定位一致，JSON通过WaveformSchema校验。原文件与preview仍307，持久媒体和派生对象仍在OSS；客户端waveform接口地址与DTO不变。

Host波形内存缓存最多2048项，每项最多8192字节，固定有效期1小时，命中提升LRU顺序。身份包含providerId / objectKey / versionId / ETag / SHA / bytes；搬移或派生替换自然使用新身份。并发相同身份合并，最多32个不同身份读取，失败冷却30秒、失败表最多128项；关闭取消活动流并等待未完成读取，不写永久本地波形。冷缓存校验对象内容，命中不再次访问OSS。字节身份变化返回OBJECT_CHANGED，损坏 / 超限返回WAVEFORM_UNAVAILABLE；失败不阻塞原音频播放 / 下载。

比例显示按名义宽高的较小数、较大数、宽数依次升序，竖向在相应横向之前。所有生图模型共用排序；两款GPT Image的1K / 2K顺序为1:1、2:3、3:2、3:4、4:3、4:5、5:4、9:16、16:9、21:9；4K只显示合法的9:16、16:9、21:9。排序仅作用于当前档位菜单，不改变能力表原顺序、默认1:1或不支持当前比例时的分辨率回退。

保留21:9和原23种尺寸（1K十种 / 2K十种 / 4K三种），不增加25:9或9:25。Sunburst / Flare四个供应商组合共用；切档优先保留比例，JSON / multipart均发送实际size，无ratio持久字段或schema变化。

## 备选方案

| 方案 | 评估 |
| --- | --- |
| 要求用户先修改Bucket CORS才能显示波形 | 小JSON可通过既有认证接口读取，当前采用Host读取 |
| 全部音视频经Host代理 | 增加大文件带宽和Range负担，超出波形修复范围 |
| 永久落盘波形或每次读取OSS | 前者改变存储策略，后者重复请求；采用有界内存缓存 |
| 排序能力表本身 | 会改变分辨率回退的首项，采用仅菜单排序 |
| 增加25:9或9:25 | 用户已明确不需要，保留到21:9 |

## 后果

正面：现有音频无需重生成即可读取波形，无需波形专用Bucket CORS配置；重复读取合并 / 缓存，菜单顺序明确，旧size与任务身份保持。

负面：冷波形读取经过Host、依赖OSS可用性；内存缓存最多约16MiB字节载荷及索引，不是全局内存上限。损坏云端JSON仍会明确失败；原媒体 / preview及未来跨域fetch仍需对应Bucket权限与CORS。

## 可逆性与重审条件

波形字节限额、算法版本、源对象可变语义或缓存成本变化时重审；目前不支持外部原地修改派生文件。用户要求其他比例或供应商尺寸约束变化时重审。回退使用本轮仍可用的上一核验包和配置备份，不重写图、媒体或任务。
