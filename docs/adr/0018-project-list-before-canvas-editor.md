# ADR-0018：项目列表先行与独立画布编辑器

状态：已采纳

文档类型：解释；负责人：项目维护者；最近核对：2026-10-26。
记录日期：2026-10-26。补充 [ADR-0014](0014-canvas-catalog-and-upload-nodes.md) 的目录交互；目录身份、约束与上传规则继续有效。

## 背景与驱动因素

1. 用户明确要求先显示画布（项目）列表，再点击进入某张画布。默认打开第一张画布、把目录管理按钮堆在编辑器顶部不符合该流程。
2. 文件夹与项目管理作用于目录，节点、任务与创作设置作用于编辑器；入口应能明确区分操作对象。
3. 返回列表会卸载编辑器，必须等未保存草稿落盘；接收文件或提交任务时也不能误离开。

## 决策

`CanvasApp` 默认没有活动画布，渲染 `ProjectList`。已有项目也不自动打开；新建成功后刷新列表，由用户点击项目进入编辑器。刷新页面或重新打开插件回到列表。当前页面内返回保留文件夹筛选；没有新增 URL 路由或跨次打开的默认项目。

列表显示一级文件夹、项目名称及归属、文件搬移状态。新建入口位于列表，画布改名 / 移动 / 删除放在对应项目操作菜单，文件夹管理放在当前文件夹菜单。移动窗口明确选择目标文件夹，不能由顶部筛选隐式决定目标。

2026-10-26，0.2.4 展示补充：按用户参考改为固定300px宽的项目卡片，间距20px，按实际内容区宽度自动排列 / 换行；取消原列表1120px上限。只有内容区不足300px时卡片收窄以避免横向溢出。卡片保留项目名称、归属、搬移状态和进入入口；右上角继续复用官方操作菜单，不增加缩略图、额外数据或目录请求。

编辑器顶部显示“项目列表”返回按钮、当前项目名称、保存状态、任务与设置；不提供项目下拉切换和目录管理条。返回前调用 `useCanvas.flush`，成功后才卸载；保存失败 / 冲突时保留当前编辑器和草稿。文件接收中或生成请求提交中暂停返回。尚未载入图时可返回，避免载入失败使用户困在编辑器。

列表只读取目录，串行轮询，隐藏页面暂停请求，卸载后丢弃旧响应。进入画布才挂载图、任务状态轮询与播放器。已接受的生成 / 导入由宿主 Runtime 继续，列表导航不改变任务生命周期、ID、数据库结构或 API 契约。

| 模块 / 本地维护责任 | 使用的模型与关系 |
| --- | --- |
| `CanvasApp` / 项目维护者 | 浏览器页面状态；组合列表与编辑器，保存目录筛选 |
| `ProjectList` / 项目维护者 | 遵循 `Catalog` / 目录命令；通过 `CanvasApi` 请求宿主，不依赖图草稿 |
| `CanvasWorkspace`、`useCanvas` / 项目维护者 | 图草稿与任务摘要；通过现有 API 保存，保存失败阻止返回 |
| 宿主目录 / Runtime / 项目维护者 | 继续作为目录约束和已接受任务的事实来源；页面只消费现有契约 |

## 备选方案

| 方案 | 不采用的原因 |
| --- | --- |
| 保留顶部目录条，自动打开第一张画布 | 用户明确指出入口流程不符合要求 |
| 列表与编辑器同时常驻 | 目录占用创作空间，也增加状态轮询和误操作入口 |
| 引入路由库和持久默认项目 | 当前只需要列表与编辑器两个页面；深链与恢复上次项目未请求 |

## 后果

正面：进入插件先看项目，再进入明确的创作对象；目录操作有对应上下文；编辑器更集中；离开前完成保存，不靠卸载时的尽力请求保证数据。

负面：跨项目创作需先返回列表再点击；刷新不能直接回到上次项目；原生名称提示框延续当前交互，视觉与菜单、移动窗口仍需用户验收。

## 可逆性与重审条件

这是可逆的客户端交互决定。更换页面组件或引入路由无需迁移画布 / 素材 / 任务数据。只有用户明确要求深链、浏览器返回键或恢复上次项目时重审导航；不能以优化入口为由自动打开其他项目。
