# ADR-0041：FishTTS 节点配置提示与提交校验

状态：已采纳

文档类型：解释；负责人：项目维护者 / 开发执行者；最近核对：2026-10-27。
记录日期：2026-10-27。TTS配置读取、密钥资格或任务接纳规则变化时复核。

## 背景与驱动因素

1. 用户发现没有配置FishTTS时，节点没有前往设置的提示。该节点使用独立配置，没有走图片 / 视频模型选择器的密钥资格检查。
2. 旧后台只判断TTS配置记录存在，记录里的Key为空或被清除时仍可接纳新任务，随后才在供应商鉴权时失败。
3. 新任务资格检查不能影响已接受任务的原凭据版本、草稿、历史音频或恢复流程。

## 决策

画布读取普通模型目录与FishTTS配置，两个读取独立执行；TTS是否可生成以`has_api_key`为准，不复用图片渠道Key，不把`configured`记录存在标记当作密钥资格。当前PublicTtsSettings DTO不改语义或结构。

FishTTS编辑卡片在未配置时明确显示“请前往设置页面配置模型”，即使朗读文字为空也显示该提示。读取中显示加载状态，读取失败显示刷新重试提示；上述状态都禁用生成。音色ID、语速、音量与文字仍可编辑准备草稿，原任务提交 / 追踪期间的锁定保持。不增加模型选择器、供应商选择器或独立Key输入。

进入或恢复画布、设置保存后重新读取TTS资格；使用请求序号忽略过时响应，失活或卸载时使旧读取失效。配置更新不覆盖草稿，读取失败不能沿用旧的已配置状态继续生成。

Host接纳新TTS任务时同时要求配置记录与非空Key，否则返回既有400 / TTS_NOT_CONFIGURED，不创建任务、不请求供应商。该校验仅用于新接纳；重复请求仍返回原任务，已接受任务继续使用原snapshot / credential_ref。清除当前Key不删除旧凭据版本，原任务重启恢复继续用旧Key。

固定端点、Bearer、model:s1 Header、音频流保存与异常 / 未知提交分类保持；无数据库DDL、图字段或任务快照迁移。本决策补充[ADR-0040](0040-configured-provider-combinations-only.md)的TTS独立配置路径。

## 备选方案

| 方案 | 评估 |
| --- | --- |
| 只在点击生成后依靠供应商401提醒 | 提示过晚并接纳无效任务，不采用 |
| 只判断配置记录存在 | 空Key与已清除Key被误认为可生成，不采用 |
| 从同供应商图片模型借用Key | 违背独立配置要求，不采用 |
| 前端读取独立Key资格并提示，Host接纳前再次校验 | 能准备草稿且不会接纳无Key新任务，采用 |

## 后果

正面：未配置原因在节点中直接可见，空密钥与清除后的资格一致，前端过时状态不能绕过Host校验；原任务和输入保持。

负面：画布增加一次本地TTS配置读取；短暂加载或读取失败期间不能生成，需等待读取完成或刷新重试。

## 可逆性与重审条件

配置资格或TTS多渠道扩展时重审，不能回退为“记录存在即可生成”。回退按包 / profile保留规则执行，不清空原Key、节点、音频或任务。
