# ADR-0011：宿主调度、状态轮询与操作并发

## 背景与驱动因素

1. 页面关闭后生成需要继续由宿主持有，不能由浏览器驱动供应商轮询。
2. 视频等待时间长，不能让一个远端任务在整个等待期间占住本地执行槽。
3. 媒体下载 / Base64 处理有网络和内存成本，首版需要有限并发，又不引入队列服务或独立 worker。

## 决策

CanvasService 在宿主定时扫描 busy 任务，active Map 限制同时执行的网络 / 保存步骤，due Map 控制视频查询间隔。远端等待间隔释放槽；一批结果下载保存占据同一执行步骤。每节点 tracked 任务防重复。

浏览器独立读取工作区状态，避免重叠读取，隐藏页面跳过轮询；不直接查询供应商。具体配置和时间维护在[运行指南](../operations.md)与[业务参考](../business.md)。

当前没有远端总任务数 / 队列数量上限、最大查询次数、优先级或队列公平性保证。此处记录现有策略，不声称完整背压或容量 SLA。

## 备选方案

| 方案 | 未选择的原因 |
| --- | --- |
| 浏览器直接驱动所有轮询 | 页面关闭会停止管理，暴露密钥与供应商状态 |
| 每个视频全程占一个并发槽 | 长等待阻塞其他节点的短操作 |
| WebSocket / SSE 推送状态 | 增加连接恢复和宿主集成复杂度；现阶段轮询足够表达状态 |
| 独立队列 / worker 进程 | 额外部署和多进程存储问题，首版容量需求未证明 |

## 后果

正面：宿主持续执行；等待不长期锁槽；有限活动操作减少同时下载 / 解码；浏览器隐藏时减少读取。

负面：状态存在轮询延迟；临时故障持续重查；队列 / 历史可无界增长；串行文件更新仍是瓶颈；固定扫描顺序没有公平性承诺。

## 可逆性与重审条件

持久任务不依赖轮询载体，可增加推送或独立 worker，但必须先解决单写者存储与任务归属。大量并发节点、长期查询、内存 / 延迟实测或公平性需求出现时重审，并定义队列上限、错误预算和取消规则。
