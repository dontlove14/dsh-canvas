# ADR-0106：任务失败原因与供应商原始通信复制

状态：已采纳

文档类型：解释；负责人：项目维护者 / 开发执行者；最近核对：2026-11-13。
记录日期：2026-11-13；交付版本：0.2.150。

## 背景与驱动因素

1. 用户需要直接看到可读的失败原因，并快速把实际接口内容发给供应商。提交快照不能代表供应商最终收到的参数；原有错误摘要不包含响应头、原始正文，且限制为1000字符。
2. 失败节点缺少通向准确历史任务的入口；新增记录必须保持存量图、DDL和任务身份，不能为了查看或复制重新提交任务。

## 决策

- 详情移除提交内容展示。失败块标题为“失败原因”，只呈现错误正文，去掉阶段、错误码和步骤前缀。供应商 JSON 优先提取 error.message / message / 字符串 error；纯文本及其他错误正文也保留。插件准备、网络、下载和保存错误同样可读，缺记录时给出明确提示。成功和正常进行中的任务继续显示执行结果。
- “复制原始请求”与“复制原始响应”使用真实通信记录。请求包含方法、地址、时间、阶段、请求头和请求体；响应包含 HTTP 状态、响应头和响应体。首次 submit 保留，poll / publish 各保留最近一次，两个复制结果按同样阶段顺序组合，避免把初始请求与失败查询混称为同一次通信。
- 只在宿主实际 submit / poll / publish 作用域记录，实例之间不共享当前任务变量。记录读取和复制不提交、重试或重生成任何任务。参考准备失败、模拟生成和历史任务可能没有通信；不从当前配置、快照或现有凭据伪造原始请求。
- Request 完成 multipart 序列化后，将相同边界和字节交给 fetch；JSON / msgpack 不改变原内容。请求鉴权头以及响应中的鉴权、cookie等敏感头保存前隐藏中间，首尾最多各4字符，短值全隐藏；正文和地址若回显本次密钥也脱敏。完整鉴权只用于原网络调用。
- 头信息来自 Fetch Request / Response；不声称捕获 TLS 或代理层、底层自动添加且未暴露的线缆头。二进制正文保留原字节的 Base64，并明确编码，不把 msgpack / multipart / 音频当作 JSON 重建。
- 响应沿同一个消费流记录，保持音频下载流式。记录上限沿最大媒体响应预算，超限或中途取消标为内容不完整。正文文件只在点击复制时读取，详情查询仅检查可用性；记录写入失败不改变原任务结果。
- 通信及完整脱敏原因使用宿主私有 dataDir/task-http 的独立 JSON sidecar，目录0700、文件0600；不改 CanvasGraph、任务快照、DDL、任务凭据或成果身份。旧摘要保留兼容，详情有完整失败记录时优先使用。
- 沿既有 GET task 路由追加 exchange=request|response，只读返回 `{text}`；沿原画布读取权限并核对 canvasId / taskId 归属。TaskDetail 追加可选 providerExchange 可用性。无记录返回404；非法选择返回原参数校验错误。复制按钮有成功/失败反馈，沿公共剪切板与模态内备用复制路径。
- 失败图标使用用户提供的四路径 SVG。公共导航上下文覆盖图片、视频、TTS、素材和历史卡片；点击传递该卡片真实 taskId / canvasId，直接打开同一个任务弹窗。按钮支持键盘、阻止节点拖拽/点击冒泡，图标之外不新增整节点点击行为。列表返回保持原筛选分页；正常任务入口仍打开列表。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 复制提交快照并重新拼接当前鉴权和参数 | 不是原始通信，无法定位网关错误和请求ID，不采用 |
| 修改任务表存储整份请求/响应 | 改变DDL且大正文影响常规查询，不采用 |
| 精确任务通信sidecar，复制时按需读取 | 保持现有数据契约和任务身份，能够保留实际正文，采用 |

## 后果

正面：用户可直接读取失败正文，复制真实通信给供应商；旧图/DDL/任务和凭据不迁移，复制无需重复请求。

负面：原始通信额外占用本机私有存储，响应捕获需要有界缓冲；超限、中断和写盘失败可能无法留下完整记录。旧任务原始通信不可追溯补造，更新后新任务开始记录。本次不引入自动清理历史证据或网络重试。

## 可逆性与重审条件

可撤回界面及记录入口，已有sidecar不参与图和任务执行；不删除旧证据。当保留期限、记录预算、供应商二进制格式或宿主读取权限变化时重审。
