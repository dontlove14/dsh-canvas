# ADR-0078：人工接管后的新消息与空闲自动委托

文档类型：解释；负责人：项目维护者 / 开发执行者；最近核对：2026-11-02。

状态：已采纳
记录日期：2026-11-02

## 背景与驱动因素

1. 用户实测人工接管后继续对话报“画布已由人工接管，请重新委托”。97只恢复视角，不恢复实际控制权；与用户希望继续通过对话操作画布不符。
2. 原10秒计时依赖有效呈现意图和agent模式；接管会使意图失效，手势监听也被卸载，所以人工状态无法自动恢复。
3. 自动委托必须保存真实人工修改，不能覆盖草稿、复活旧epoch操作或重提已接受的生成任务。用户同时要求水印至少缩小一半。

补充 [ADR-0077](0077-automatic-agent-follow-and-manual-idle.md)，按用户澄清替代0071中“人工接管后只能点击重新委托”的交互；原接管的同步撤权、取消旧执行与付费幂等仍有效。

## 决策

当前会话当前可见画布注册人工控制座位，包含session / canvas / epoch及真实flush / refresh。手势监听在人工和agent模式中持续保留，切换epoch不卸载同画布监听。10秒计时可由人工控制座位独立拥有，不依赖已失效意图。最后活动结束超过10000ms，先flush，再验证座位、会话、epoch、活动版本和可见状态，使用已保存revision委托；成功后刷新控制并恢复最新呈现。拖动 / 长按持有期间不计时，保存期间新操作、离开、切会话或卸载使旧恢复失效。没有活动回复时不显示水印，不制造新对话或生成任务。

借用公开SessionFace的prompt方法接入可撤销适配，发送前flush当前可见画布、恢复人工控制，再调用原方法；完整保留this、消息、queue / steer、signal和requestId。公开beginSubmission适配仅记录handle与退还回调，保存失败调用原handle.abandon，不发送消息，原生附件 / 输入草稿保留；成功按原生回调清理身份。适配随原会话绑定 / 重连 / 插件卸载恢复两个原方法，不修改SDK文件。

主Agent原生pre-step在组装和request校验前，对新的根用户消息补充恢复关联画布的控制权，覆盖冷恢复与非当前UI发送；子Agent和旧工具续步不能自动恢复。接管时记录原生历史与待处理队列的旧messageId；历史 / 接管前排队消息不当作新委托，首次恢复注册也建立原队列基线。原signal与epoch检查保持，新委托用最新图建立handoff。

`agent-control` delegate新增可选epoch。调用前和串行队列内均检查控制身份，旧自动恢复请求不能覆盖更新接管。旧客户端不传epoch继续原行为。无新的持久字段，AgentLedger版本1与两库DDL保持；旧生成提交沿原requestId / session / epoch，不因恢复自动重放。

水印字号25px改为12px，字距2px改为1px，保持原灰色混合和主题继承、背景层级及无指针事件。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 只恢复视角，继续要求点击委托 | 已被用户实测否定；不采用 |
| 放宽所有工具的epoch校验 | 允许晚到旧写入覆盖人工修改，不采用 |
| 新消息保存后恢复控制，人工空闲计时独立于意图 | 已采用；需原生发送适配与新消息基线，保留旧操作隔离 |

## 后果

正面：人工接管后可直接继续对话，真实修改先保存并交回Agent；人工状态自动恢复不被意图消失打断，水印明显缩小，原任务身份保持。

负面：发送需等待本地保存，冲突会阻止发送并保留草稿；公开原生prompt或生命周期契约变化时需重审适配。浏览器手势、保存与呈现仍须用户验收。

## 可逆性与重审条件

上一可用97包可回退读取全部图 / sidecar，无数据库迁移。新增epoch是可选请求字段；回退恢复点击委托行为。用户修改自动委托时长、要求禁用特定画布的自动恢复、原生发送 / pre-step时序变化时重审。不得用重提任务替代恢复。
