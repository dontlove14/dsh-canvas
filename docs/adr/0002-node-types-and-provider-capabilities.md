# ADR-0002：五种节点、协议能力与逐节点执行

状态：已采纳（补录）

文档类型：解释；负责人：项目维护者；最近核对：2026-10-26。
补录日期：2026-10-26；原决策日期未单独留档。复核规则见[ADR 索引](index.md)。

## 背景与驱动因素

1. 图片与视频的参数、异步状态和输入限制不同，需要可辨认的独立节点。
2. 本地资源要在画布可见并可播放；首批协议没有音频生成或视频 / 音频生成输入能力。
3. API Base 和 Key 不能完整描述任意厂商协议，必须显式选择可执行的请求 / 查询 / 输出适配器。
4. 用户按原型逐步创作，自动链路执行涉及额外计费、失败传播和调度语义，尚未定义。

## 决策

采用图片生成、视频生成、图片资源、视频资源、音频资源五类业务节点，共用呈现组件和任务骨架，保持业务 kind 区别。生成由用户逐节点发起；连线是素材输入，不触发执行。

模型以 kind + protocol + Model ID 配置，能力由 shared 显式定义，Providers 映射协议。模型创建后 kind 不变；新协议需要新增适配器和契约，不能仅换地址后声称兼容。精确能力维护在[模型协议](../providers.md)。

## 备选方案

| 方案 | 未选择的原因 |
| --- | --- |
| 单一任意模型节点和无约束参数 JSON | 用户难以判断能力，前后端校验不一致 |
| 按 Model ID 字符串猜厂商协议 | 自定义网关命名不可靠，不能推导 wire 格式 |
| 完整 Agent / DAG 自动执行 | 超出当前交互范围，缺少计费和失败传播规则 |

## 后果

正面：类别和参数清晰；资源可复用；前后端使用同一能力校验；协议增加有明确改动边界。

负面：选项是插件定义的有限集合，供应商可能另有限制；不支持任意厂商、音频生成或自动工作流；新增协议要同时更新契约、适配器和测试。

## 可逆性与重审条件

可在保持既有 kind 和 version 1 可读的前提下增加新节点 / 协议。只有明确用户需求、真实协议与执行 / 失败规则到位后才重审自动执行或更多媒体输入；不静默改变已有节点的语义。
