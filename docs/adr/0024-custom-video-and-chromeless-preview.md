# ADR-0024：自定义有声视频控制与无外框媒体预览

状态：已采纳

文档类型：解释；负责人：项目维护者 / 开发执行者；最近核对：2026-10-29。
记录日期：2026-10-26。播放器、预览样式、宿主Modal能力或媒体生命周期变化时复核。

## 背景与驱动因素

1. 浏览器原生视频控件在缩放画布中占用过大，用户要求参照单行细控制条自定义，仅保留播放、时间与进度。
2. 用户要求声音固定开启，不要静音、全屏或更多按钮；原图 / 原视频预览也不需要标题、另存和卡片外框。
3. 视频状态、拖拽进度、自动播放拒绝与关闭后的停止播放需要明确管理，不能为了样式更改媒体、图或任务。
4. 预览仍需要宿主的Esc关闭、模态焦点与返回入口行为，不能仅用普通固定div替代。

## 决策

新增共享`VideoPlayer`，节点和原视频预览使用相同播放 / 暂停、当前时间、range进度条、总时长；节点更紧凑，原文件预览使用适合屏幕的字号。不设置浏览器`controls`，没有静音 / 音量、全屏、更多、倍速或额外按钮。声音设置为`muted=false`、`volume=1`，保留循环和内联播放。

独立播放控制器从原生媒体事件更新局部React状态，监听元数据、播放、暂停、时间和错误，无定时轮询、无画布保存。拖进度限制在有效时长内；未得元数据时不允许定位。播放Promise拒绝由控制器接住：有声自动播放被阻止时显示主动播放提示，不自动静音；媒体不可解码单独显示失败。销毁先移除监听器再暂停，迟到的播放拒绝不更新已关闭组件。

原图 / 原视频使用官方Modal的`headless=true`，`title`仅作aria-label；禁用背景模糊，使用深色遮罩和透明、无边框 / 圆角 / 阴影的容器。媒体按原比例限制在可用空间，不加灰色填充区；只添加一个官方关闭按钮和视频必要的播放条。保留宿主焦点陷阱、初始关闭按钮焦点、Esc / 遮罩关闭与返回焦点；独立开发页使用原有原生dialog语义。音频预览与其他设置 / 任务弹窗不改变。

保持现有单节点播放、取消选择 / 隐藏 / 移出可见区卸载、原视频预览停止节点播放的生命周期。控制条隔离画布拖拽、滚轮、删除与空格快捷键；Tab和Esc继续交给弹窗。仅控制条双击不触发资源聚焦，画面 / 名称双击原规则保留。

0.2.61修正播放时整个节点被禁拖的问题：内联播放器画面、时间文字与控制行留白保留节点拖动，`nodrag`仅用于播放按钮和进度条；原视频模态预览仍整块禁拖。video显式禁止HTML原生拖放，节点移动沿用XYFlow / D3，不关闭播放器、不修改播放时间或重挂媒体。移动手势后的尾随点击由原拖拽引擎抑制，普通单击仍切换播放。

节点内播放器的普通双指平移、惯性与捏合 / Command / Ctrl缩放复用现有画布根手势转交，包含画面、时间、播放按钮SVG与进度条；沿用原生指针中心、边界和视口保存，不增加独立计算或新监听器。源事件非passive捕获并阻止默认浏览器缩放，转给真实renderer；编辑面板与原视频模态预览不在该节点作用域。上述规则替代本段历史的“播放器 / 控制条整块隔离拖拽与滚轮”描述。

内联播放控件聚焦后，Meta / Control按键继续交给实际画布缩放订阅；其他按键仍按原播放控件隔离，Tab / Escape及原视频模态预览保持原规则。测试直接驱动真实useKeyPress检查聚焦进度条时的Meta传递，不只模拟缩放标志。

本决定替换[ADR-0022](0022-media-covers-and-curved-edges.md)的静音 / 原生控件展示，封面、曲线、数据和原文件规则继续有效；节点顶部下载仍保留。

## 备选方案

| 方案 | 评估 |
| --- | --- |
| 仅用CSS缩小浏览器原生controls | 浏览器样式差异大，也不能可靠控制所有按钮，不采用 |
| 引入完整第三方播放器 | 增加依赖和用户未要求功能，不采用 |
| 自行创建普通固定层并隐藏原Modal标题 | 容易丢焦点管理，依赖内部CSS类，不采用 |
| 共享最小播放器 + 官方headless Modal | 控制范围明确，复用已有模态生命周期，采用 |

## 后果

正面：控制条不遮挡大块画面；原文件预览与参考图一致且界面简洁；声效、暂停、拖进度和关闭行为一致，不改存量身份。

负面：没有浏览器原生的全屏 / 更多能力；有声自动播放可能受浏览器限制，需主动点击播放。样式和原生媒体事件在实际编码 / 浏览器中仍需人工验收。

## 可逆性与重审条件

只修改客户端播放器和预览，不改数据库、API、原媒体、封面身份或任务。用户提出新的控制项、浏览器行为异常或官方headless契约变化时重审。
