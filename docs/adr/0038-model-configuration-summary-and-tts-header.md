# ADR-0038：已配置模型概览与 FishTTS s1 Header

状态：已采纳

文档类型：解释；负责人：项目维护者 / 模型接入执行者；最近核对：2026-10-27。
记录日期：2026-10-27。新增模型配置入口或调整TTS版本协议时复核。

## 背景与驱动因素

1. 设置页逐项罗列所有模型供应商组合会随模型数量增长占用过多空间，用户要求页面只展示已配置内容与配置入口。
2. FishTTS文档把model定义为Header，默认speech-1.5，只有s1支持情绪处理；现有请求遗漏该Header，无法保证情绪模型版本。

## 决策

设置页只按模型汇总具有非空密钥的内置配置，同一模型的渠道合并为一行；没有配置时显示空态。“配置模型”表单先选择模型，再选择其支持的供应商，最后填密钥。Model Link默认优先；新增、编辑与清除都从右上角唯一“配置模型”入口进入，概览行只展示内容，无操作按钮（0.2.32按用户补充收敛）。FishTTS作为单一模型进入相同入口，只提供Model Link；不常驻未配置TTS表单或视频占位说明。

切换模型或供应商清空尚未保存的密钥与清除标记，避免交叉提交。已有密钥输入留空保留，主动清除只影响该组合；清除最后一个渠道后模型从概览消失。保存复用models / tts-settings API和已有UUID / revision / Vault版本，不新建模型身份、不共享Key、不改写节点或任务。

FishTTS请求固定Header `model: s1`，与Content-Type和Authorization Bearer并列，Body仍为text、可选reference_id、prosody.speed / volume、format=mp3。文档核对确认语速1为正常、音量0为正常且允许负值；其他可选参数沿用供应商默认值。内部任务model_id仍fish-tts，s1是外部Header，不能因此迁移存量快照或数据库。未知提交不重提，原暂存输出恢复不再次调用TTS。

本次设置演进为Client展示 / 表单变化，HTTP路由和公开DTO不变；TTS只修正wire Header。全页、Harness设置、侧栏及独立开发页共用同一ModelSettings。界面状态不进入数据库。

## 备选方案

| 方案 | 评估 |
| --- | --- |
| 展示全部未配置模型与渠道 | 模型变多时页面冗长，不采用 |
| 单独保留TTS常驻配置表单 | 不符合页面只展示已配置概览的要求，不采用 |
| model放Body或继续使用默认版本 | 不符合文档Header契约，且默认版本不支持情绪，不采用 |
| 配置概览与统一表单，TTS固定s1 Header | 满足用户流程并保留数据身份，采用 |

## 后果

正面：概览大小由已配置模型数量决定，渠道选择与密钥保存明确；情绪TTS请求使用所需版本。

负面：新配置需要经过模型与供应商选择；真实s1音色情绪效果仍由用户人工联调，Header替身测试不能代替供应商验收。

## 可逆性与重审条件

本次不改存储结构，回退按既有包 / profile保留规则进行。新增供应商、凭据共享策略或TTS版本选择能力时重新评估；不得通过更改已接受任务或重复请求来伪造恢复。
