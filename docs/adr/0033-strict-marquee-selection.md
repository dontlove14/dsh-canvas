# ADR-0033：透明框选与严格节点几何选择

状态：已采纳

文档类型：解释；负责人：项目维护者 / 开发执行者；最近核对：2026-10-27。
记录日期：2026-10-27。

## 背景与驱动因素

1. 用户截图显示框选内部呈白色遮挡画布，小块空白矩形却选中了多个外部节点；矩形背景此前混入不透明surface。
2. 当前XYFlow的getNodesInside会将缺少handleBounds的节点直接加入候选，与位置无关。可见元素虚拟化使屏幕外节点可能未测量，单纯设置Full模式或提供尺寸不能消除这个旁路。
3. 资源 / 音频NodeToolbar显式isVisible=selected覆盖库的单选限制，生成结果操作DOM持续存在并由hover触发，编辑器也没有排除框选过程。

## 决策

保留原生Pane指针捕获、矩形绘制、自动平移与虚拟化。透明填充和主题色虚线边框同时适用于过程框及结束后的分组选区。

客户端订阅已提交矩形，按当前transform和节点主体矩形判断完整包含；隐藏 / 不可选 / 无有效尺寸节点不能进入候选。FlowNode提供临时展示尺寸作为未测量节点的几何依据，使用结果 / 旋转 / 分组身份隔离尺寸缓存，不新增持久字段。

框选时忽略原生select通知，重新设置完整选择，并修复库提前改写的internal.selected；连线只跟随严格选择的节点及既有Shift基线。矩形缩小、反向拖动与松手坐标变化均重新计算。普通框选替换旧选择，Shift保留开始前选择；取消 / 失焦恢复原状态，原生空结果分组标志也必须清理。

共享选择上下文控制Portal工具栏和生成结果操作DOM，框选时关闭浮动编辑器，多选不显示单节点操作。节点主体选中边框独立保留。选择只在浏览器内存更新，不保存图、不改变任务 / 媒体身份；自动平移后的视口保存不变。

0.2.78以[ADR-0068](0068-selection-output-and-reference-interactions.md)补充多选结束态：显示临时透明分组选框及原生输出端点，顶部只含下载；过程框、严格几何选择与原生分组拖动保持，临时节点不可选且不持久化。

## 备选方案

| 方案 | 评估 |
| --- | --- |
| 只换透明色并设置SelectionMode.Full | 能改善背景，但保留未测量节点旁路和浮动DOM问题 |
| 关闭onlyRenderVisibleElements并强制全图测量 | 增加大图DOM / 媒体成本，首轮未测量期间仍可能误选 |
| 修改node_modules的库选择算法 | 安装后易丢失且与包身份脱节，不采用 |
| 保留原生手势并在客户端严格重建选择 | 兼容现有平移 / 虚拟化，不改变持久格式，采用 |

## 后果

正面：空白框、缩小与屏幕外节点均按真实范围判断；透明区域不遮挡内容，选择期间没有悬浮操作干扰。

负面：每次矩形提交需要遍历节点 / 连线，增加少量客户端计算；未来库事件顺序或内部选择处理升级时需重新核对。未知尺寸使用对应展示框兜底，真实浏览器仍需人工验收。

## 可逆性与重审条件

纯客户端修复可回退，不涉及数据迁移。XYFlow升级修复未测量旁路、引入嵌套节点 / 自由尺寸节点或大图框选开销超预算时重审订阅边界与几何策略。
