# ADR-0104：Agent 角色、任务 Skill 与宿主权限分层

文档类型：架构决策记录；负责人：项目维护者 / 开发执行者；最近核对：2026-11-13。

状态：已采纳
记录日期：2026-11-12。
用户已授权按[三层方案](../proposals/agent-skills-three-layer-mounting-v0.1.md)实施并重启既有 web / 3080；本决定适用于以后新增子 Agent 或增加能力。

## 背景与驱动因素

1. 各角色专业技巧原先全部拼进提示词，不能按任务细分维护；导演、镜头序列与画面设计缺少独立方法与成果边界。
2. 主级曾以“后续FishTTS配音”为由主动将视频声音关闭。仅靠方法文字不能保证默认声音策略，需要宿主核验真实用户依据。
3. 原生Skill目录合并并不等于本项目角色授权；需要防止跨角色方法、同名外部内容、任意资源和迟到加载扩大能力。

## 决策

保留1主级+7类子级。第一层始终提供角色、协作与硬边界；第二层用28个随包Skill（4共享+24角色）提供专业步骤；第三层按AGENT_CAPABILITIES、原生restrict/guard、真实身份、批次binding、资源授权和原精确执行机制强制工具权限。

方法使用Harness原生SkillRegistry注册/查询，按真实Agent scope读取；不挂通用文件发现或终端工具。目录仅展示随包身份匹配项；正文加载核对provider/source/版本/正文哈希，资源仅精确清单内只读文本。同名覆盖失败，已加载定义固定于真实实例/本批binding，不受后续目录变动影响。取消、接管、binding或根轮变化后迟到结果不注入。

子级开始前加载角色最小必备方法及主级选择的可选skillNames，实例可继续加载本角色方法；执行者固定执行/回执方法，不增加创作选择。主级常驻目录，正文按工具动作/任务需要加载。方法内容嵌入编译包，并附可核验原始Markdown和资源清单，运行不依赖源码目录。

工具接口：

| 入口 | 输入/默认 | 权限与结果 |
| --- | --- | --- |
| canvas_skill | action=list，或action=load/name | 真实本角色目录或核验正文/version/sha256；无写入 |
| canvas_skill_resource | name/path | 本角色已列举辅助文本/version/sha256/executable=false；任意路径/URL拒绝 |
| canvas_specialist | 原字段加可选skillNames | 必备组合始终加载，选择必须属于真实role；原调用未提供字段时不改变旧inputHash |
| canvas_method | 保留旧role输入 | 只返回调用者本角色默认Skill兼容组合；主级查询其他专业角色改为委派 |
| canvas_confirm_video_mute | targets与可选messageId | 主级绑定本轮root/canvas/epoch/目标；不改图、不生成 |
0.2.148兼容性补充：模型工具参数根必须明确为`type: object`，不能直接发送Zod判别联合生成的根级`oneOf`。`canvas_skill`对外使用对象字段，list/load的条件必填与禁止字段继续由宿主校验；共用注册入口核对对象根，八角色检查实际wire schema。修复不改变能力清单、Skill内容、权限或历史会话数据。
| canvas_confirm_video_mute | targets与可选messageId | 主级绑定本轮root/canvas/epoch/目标；不改图、不生成 |

必备缺失/不可信用AGENT_SKILL_MISSING/UNTRUSTED阻塞本批；跨角色用AGENT_SKILL_FORBIDDEN；迟到用AGENT_SKILL_STALE；辅助缺失用AGENT_SKILL_RESOURCE_MISSING，只影响该读取，已加载正文保留。不无限重试、不重派旧任务。

导演意图、镜头序列、单镜画面和动态提示词由shots独立方法负责；编剧保留故事/剧本。主级统筹并指定阶段，audio分开规划原生声音、音频参考和独立TTS。无固定音色的项目跳过音色准备，声音设计与原生声音仍继续。

支持声音开关的新视频或显式参数修改默认true；false在精确批次接受和实际提交前都要核验用户无声授权。依据只允许最新真实用户完整且明确的无声请求（全体或实际提交节点引用），或针对精确目标的原生用户选择。模型自述、网页、引用文本、否定静音、历史用户消息不能授权。依据只在宿主内存绑定，人工接管/交还/会话结束失效；新批次不能跨epoch使用。无开关模型不塞字段。旧false节点的改名/位置等无关操作保持原参数，历史任务/素材/图不修补。

后续新增角色、Skill或工具必须一起维护角色边界、触发/必备方法、稳定随包身份、精确工具策略、宿主资源授权、正反检查和文档；只改提示词或Skill不会被视为新增能力已实现。治理流程见[项目Skill](../../.trae/skills/agent-capability-governance/SKILL.md)。

## 备选方案

| 方案 | 判断 |
| --- | --- |
| 继续全量提示词 | 无法独立触发与维护，保留硬边界而迁移专业步骤 |
| 所有角色开放通用Skill/文件/终端 | 会绕过角色和资料授权，不采用 |
| 原生注册+随包消费者+宿主权限 | 采用；复用原生接口并固定可信内容 |
| 增设导演/序列/剪辑角色 | 本轮不需要，现shots承担细分方法；剪辑须有真实工具后另行设计 |

## 后果

正面：专业方法可按任务读取，八角色边界保持；视频不再因固定音色缺失自动静音；新增能力有统一代码入口和长期规则。

负面：维护28份方法与清单会增加一致性成本；保守的无声依据识别遇到复杂自然语言时需具体原生确认。Skill能指导专业步骤，但不能证明真实模型质量或新增视听/剪辑能力。

## 可逆性与重审条件

0.2.144按现有check、双构建、编译smoke、包内/安装身份和HTTP preload核验后本地更新；成功前保留0.2.143包。失败回旧插件及profile，不清数据、不撤销已存成果、不重提媒体任务。未来外部Skill、角色增加、资源执行或权限扩展须重新评估；不修改CanvasGraph/DDL、任务快照与存量认可。
