# ADR-0096：可见性通知按目标元素与最新时间处理

状态：已采纳

文档类型：解释；负责人：项目维护者 / 开发执行者；最近核对：2026-11-11。
记录日期：2026-11-11。用户批准修复可见性判断与回归测试。补充[ADR-0095](0095-long-lived-media-url-recovery.md)的视口恢复规则，保留签名、媒体身份与播放策略。

## 背景与驱动因素

1. 一次IntersectionObserver回调可能包含同一元素的多条变化。原组件只读取第一条；当通知依次为离屏、入屏时，元素仍被标记为离屏，图片组件被移除或停止解析链接，留下Loading占位。现有组件的隔离复现中，整排10个节点的两轮通知造成不同的3个节点空白，资源链接仍有效。
2. 资源、生成结果、历史音频、图片与Loading分别维护可见性，重复写法容易遗漏相同问题。大画布不能靠额外布局测量或全图资源重载修正通知顺序；断开观察后的旧回调也不能影响新观察。

## 决策

1. Client统一使用[observeVisibility](../../src/client/observeVisibility.ts)。仅接受当前观察元素的记录，按`entry.time`选择最新一条；同一时间采用批次中靠后的记录。空批次和其他目标不改变当前状态。
2. 每次观察独立保存最近时间，忽略比已处理记录更早的后续批次。清理先标记观察无效再disconnect，忽略已排队的旧回调；重新观察使用独立时间与生命周期。
3. 沿用各入口的rootMargin与可见状态副作用。资源节点、生成结果、原文件、历史音频、SignedImage、Loading、对话音频和协作容器共用规则；不新增getBoundingClientRect或轮询。没有观察元素时不订阅；浏览器不提供IntersectionObserver时允许正常渲染。
4. 固定img-fx上游源码保持原哈希，其内部观察已逐项处理通知；宿主Loading的可见 / 暂停状态由统一函数提供，不替换动画、依赖或着色器。
5. 测试中的通知必须包含真实形状的target、time和isIntersecting。补充顺序 / 逆序时间、不同目标、旧批次、断开后的回调、内外两层入屏和整排反复移出的回归；不将可见性或观察时间写入CanvasGraph、数据库或任务。

## 备选方案

| 方案 | 评估 |
| --- | --- |
| 继续读取第一条 | 会将过时状态留在节点上，不采用 |
| 各组件只改成取最后一条 | 缺少目标与时间核对，仍有分散遗漏风险，不采用 |
| 每次移动都测量节点或重载全图 | 增加布局与资源成本，不采用 |
| 统一目标、时间与观察生命周期 | 复用现有可见策略，处理批次与清理边界，采用 |

## 后果

正面：批量离屏 / 入屏不会停留在第一条旧状态，节点与Loading采用相同规则；不增加媒体请求、布局测量或持久数据。

负面：回归仍需构造观察通知，真实Chrome批次、缓存和拖动效果由用户验收；不能据此声称所有图片加载异常都由同一原因引起。

## 可逆性与重审条件

共享函数可独立调整观察规则，无需迁移数据。将来增加多目标观察、替换浏览器可见性实现或发现新的通知时序时重审；保留按目标与最新状态处理的契约，不通过永久显示所有资源或重新生成媒体规避问题。

## 验证与证据

[可见性回归](../../tests/viewportVisibility.test.tsx)包含10项检查，沿用现有组件、加载边界、链接缓存与原生媒体事件，仅隔离GPU绘制。整排10节点三轮混合通知均重新入屏，已有链接只批量解析一次；内层图片复用有效缓存，入屏 / 离屏、旧回调与相同时间处理均检查。

既有[长时恢复](../../tests/mediaRecovery.test.tsx)、[Loading](../../tests/nodeLoading.test.tsx)、音频 / 历史 / 协作回归继续执行。按[ADR-0021](0021-local-update-and-package-retention.md)检查、双构建、同包安装、正常重启和认证加载核验0.2.133；实际身份以manifest为准。手动验收见[清单](../manual-tests.md)419–422。
