# ADR-0069：采用非商业使用与 Model Link 署名许可

状态：已采纳

文档类型：解释；负责人：项目维护者；最近核对：2026-10-30。
记录日期：2026-10-30。许可、署名或分发条件变化时复核。

## 背景与驱动因素

1. 用户明确要求本项目禁止商用，并必须带有文字为“Model Link”、
   目标为 `https://api.modellink.online` 的超链接。
2. 仓库此前没有项目主许可文件，包也没有许可声明；仅在介绍中
   提及 Model Link 不能形成完整的使用和再分发条件。
3. 非商业限制与标准开源许可的自由商业使用条件不一致，需要准确
   标为源码可用许可，并保留第三方组件自身的许可边界。

## 决策

- 根目录 [LICENSE](../../LICENSE) 是唯一正式许可文本，采用自定义
  “dsh-canvas 非商业使用与署名许可协议”1.0；中文完整条款为正式
  文本，英文仅作为非约束性摘要。
- 允许非商业使用、研究、修改和分发；禁止收费服务、商业集成、
  企业业务运营、商业内容生产以及通过免费服务取得间接商业收益。
  单纯为非商业使用支付模型 / 存储费用不自动构成商业使用，也不
  授予商用权。
- [NOTICE](../../NOTICE.md) 和 [README](../../README.md) 提供署名
  与许可入口。再分发保留完整许可、版权和声明；有界面的部署或
  修改版本在可访问的关于、设置、致谢页或页脚保留可点击链接。
- 修改版本保留非商业和署名限制，说明已修改；不要求公开未分发
  修改，不要求用户必须使用 Model Link 服务。
- 第三方内容适用自身许可；用户输入、画布数据和生成结果不会
  自动继承项目代码许可，但商业目的的生成仍是禁止的商业使用。
- package.json 使用 `SEE LICENSE IN LICENSE` 并将 LICENSE /
  NOTICE.md 纳入分发包。版本按既有流程递增至0.2.79，lock同步；
  许可文件加入产物身份的源码 hash 清单。

## 备选方案

| 方案 | 评估 |
| --- | --- |
| MIT / Apache-2.0 等标准开源许可 | 允许商用，不能满足用户约束 |
| 只在 README 写禁止商用和链接 | 缺少完整授权、商业边界与分发条件 |
| 自定义非商业与署名许可 | 能覆盖两项明确要求，采用；准确标为源码可用 |

## 后果

正面：使用者和再分发者能找到明确许可，署名目标和可见性条件清晰，
源码、包声明及身份核验覆盖同一许可文本。

负面：此项目不属于标准开源许可项目，与某些其他许可证的合并或
再分发可能不兼容；非商业边界与第三方权利仍需使用者具体核对。
许可文本不能代替界面署名或真实部署验收。

## 可逆性与重审条件

许可调整由有权授权的著作权人决定，不当然追溯撤销此前有效授予的
权利。用户改变商业边界、署名要求、第三方内容或分发渠道时重审，
同步 LICENSE、NOTICE、README、package及产物清单，不能静默替换
已交付版本中的许可。

## 验证与证据

- 用户明确要求“要求就是不可以商用，必须带上‘Model Link’”，并
  指定 `https://api.modellink.online`。
- 实现入口：[包声明](../../package.json)、[产物身份核验](../../scripts/verify-artifact.mjs)。
- 按既有 `npm run check` 和双次构建 / 包内容核验检查本轮产物；
  实际执行结果在本轮交付记录中填写，不将未执行检查写为通过。
