# ADR-0022：纯媒体节点、独立压缩封面与曲线连线

状态：已采纳

文档类型：解释；负责人：项目维护者 / 开发执行者；最近核对：2026-10-26。
记录日期：2026-10-26。节点交互、封面参数、媒体依赖或数据契约变化时复核。

## 背景与驱动因素

1. 用户要求图片 / 视频节点只呈现媒体，名称悬浮在左上方且可双击修改；顶部图片仅旋转 / 下载 / 放大，视频仅下载 / 放大，没有预留按钮。
2. 原图直接用于画布、视频默认加载播放器会放大网络和解码开销；上传与生成媒体都需要压缩封面，视频必须使用第一帧。
3. 放大、下载和模型引用需要原始字节；存量画布和数据库结构必须兼容，不能为了展示增加持久字段。
4. 用户要求折线改曲线，既有边的具体素材身份与业务校验需要保留。

## 决策

- 已有图片 / 视频素材（含生成结果）走纯媒体节点：按照封面自然宽高比布局，最大显示320×480，不裁切。名称位于左上方，双击或键盘 Enter / F2 编辑；Enter / 失焦提交，Escape 取消，空白保留原名称。使用现有 title 保存和命名搬移规则。
- 选中节点时在画面上方显示官方按钮组成的操作栏。图片顺时针90°旋转仅影响当前编辑页面显示；退出画布后复位，不改变原图或下游引用。视频不提供旋转。
- 双击图片 / 视频资源节点的画面，在画布内选中、居中并放大该节点，保留画布背景与连线；只适应目标节点，沿用0.1–2.5缩放边界，通常300ms过渡，减少动态效果偏好时直接切换。按当前测量尺寸适应横 / 竖图与旋转后形状；视口沿用既有自动保存。名称双击仍用于改名，顶部放大仍打开原文件模态，生成节点不新增此双击行为。
- 视频未点击只请求静态封面；点击当前节点后挂载原视频并循环播放。同一时刻只让一个节点播放；取消选择、点击空白、移出可见区域时卸载播放器，放大原视频时停止节点播放。0.2.9按[ADR-0024](0024-custom-video-and-chromeless-preview.md)将最初的静音 / 浏览器原生控件替换为有声 / 自定义细控制条，原文件预览改为无标题和卡片外框；本ADR的封面与生命周期规则继续有效。
- 生成参数、任务状态、多结果切换仍放在生成节点的浮动编辑面板；纯资源节点取消旧底部面板。音频和无素材占位节点沿用现有展示。
- 新增 Host `PreviewCache`，复用 owner 认证的 `GET/HEAD media?canvas=...&id=...&variant=preview&v=1`。第一次显示时按需生成，旧素材、上传、生成结果共用；不登记新资产、任务或数据库列。放大、下载、模型提交继续使用原 media 路径。
- 图片由固定版本 sharp 解码、自动纠正 EXIF 方向；长边最多960px，不放大小图，静态 WebP quality76 / effort3。GIF / 动态 WebP只取第一帧。视频由固定 ffmpeg 本机二进制读取第一帧（不 seek、不按内容择帧），缩小后再编码 WebP。原文件不重写。
- 缓存置于 `dataDir/previews/<sha256>.webp`，key含画布 / 素材ID、既有file_hash、封面版本、源size / mtime；源改名 / 迁移可重新生成。目录0700 / 文件0600，临时文件完整写入后 rename发布。缓存可在停机后单独删除并重建，不作为恢复来源；当前没有自动磁盘GC。
- 每个服务一个串行解码队列，最多64个待处理唯一封面，相同key复用Promise；失败短期缓存30秒、最多128条。图片解码最多1亿像素、12秒处理超时；视频单线程、15秒超时、输出上限8MiB并限制file/pipe协议，停止服务时取消并等待处理结束。此限制不等于全部原视频解码内存预算。
- 路由先验证画布归属、原媒体 realpath，再访问缓存；拒绝符号链接替换。原文件不可用不借缓存绕过检查。封面失败返回独立错误，不改变生成状态或重新生成；客户端说明封面不可用并保留原文件入口。缓存HTTP为private/max-age=3600，原媒体保持原缓存与Range契约。
- 已保存边在视图映射为 React Flow default Bezier；新连线拖动也使用 Bezier。持久 CanvasEdge 仍只有id/source/target/assetId。

## 备选方案

| 方案 | 评估 |
| --- | --- |
| 原媒体直接作为所有节点预览 | 大图和大量视频解码开销高，不满足封面要求 |
| 浏览器截帧并把封面写入资产 / 节点字段 | 依赖浏览器编码、刷新重复处理且需要变更持久契约，不采用 |
| 所有素材一次性离线迁移生成封面 | 启动会受历史媒体数量影响；当前采用首次展示按需缓存 |
| 独立派生缓存 + 原文件入口 | 覆盖所有来源、保留数据结构和原引用，采用 |

## 后果

正面：画布节点更贴近参考图，未点击视频不加载原播放器；封面和原文件明确分离，存量数据不需要迁移，现有连线身份保留。

负面：增加sharp和ffmpeg原生平台依赖及封面磁盘占用；首次展示等待解码，超大 / 损坏 / 不支持编码可能无封面。Node停机和处理超时不能保证底层OS调用固定时间内返回；大图 / 大视频并发的真实峰值与浏览器布局仍需人工测量。旋转是当前页面状态，不具有编辑原文件或跨次打开保存的含义。

## 可逆性与重审条件

回退不涉及DDL或资产 / 图字段迁移；上一可用包仅按ADR-0021保留到更新核验成功，成功后旧tgz清理。移除封面实现后原文件仍可直接使用；封面可安全重建。用户明确需要持久旋转、编辑原图、调整压缩预算、批量预生成或平台二进制不可用时重审；不预留新按钮。
