# ADR-0084：画布专用 # 与原生工作区 @ 引用

文档类型：解释；负责人：项目维护者 / 开发执行者；最近核对：2026-11-03。

状态：已采纳
记录日期：2026-11-03
实施版本：0.2.111；部分替代[ADR-0076](0076-native-hash-canvas-and-workspace-references.md)与[ADR-0083](0083-visible-canvas-reference-catalog.md)的工作区文件候选。

## 背景与驱动因素

1. 原#菜单同时展示画布和会话工作区文件，文件候选来自Harness原生fileReferences.list。Harness已有@文件引用，用户要求#只选择画布内容，避免重复入口。
2. 原文件RPC或工作目录失败还会阻挡无关的画布候选；候选应只依赖其实际需要的画布数据。

## 决策

1. #保留全部分类 / 画布 / 资源及0083排序、分级浏览、取消与身份规则；删除工作区行和目录分支，不查询文件RPC。新文件引用由Harness原生@处理，原生@ / /控制器不修改。
2. 输入适配只注入inputTriggers与sessions，不等待remote或remote.fileReferences。没有文件远程服务时画布候选仍可用；文件服务到达不改变#范围。
3. GET agent-reference-choices保持sessionId / query / browse和目录 / 媒体响应，停止查询workingDirectory及返回原可选cwd。菜单不再因工作目录变化而失效；Agent身份、owner和素材检查保持。不增加接口或持久字段。
4. 旧version1 file引用可能存在于未发送草稿、剪贴板和对话历史，因此保留codec、POST resolve、主级读取与原安全检查；不改写历史，也不把旧文件身份转成画布身份。新菜单只产生media引用，旧文件仍须同会话、真实工作区、普通文件与pin验证。
5. 保留Host的workingDirectory依赖供旧文件读取及原有文档交付使用，原生文件引用插件由Harness管理，不卸载或重配宿主模块。

## 兼容、错误与重试

| 表面 | 处理 |
| --- | --- |
| 新#候选 | 仅画布，空媒体不回退工作区文件 |
| GET可选cwd | 不再返回；旧客户端可展示media但不展示文件；新客户端不使用cwd |
| 旧file标记与POST resolve | 版本1及原400 / 403 / 409、安全检查不变 |
| 原生@文件 / 会话、/命令 | 继续使用原生源、输入范围、目录与codec |

GET无写入可重试，目录或素材变化仍要求重新选择。工作区文件失效只影响旧文件引用，不影响新的画布候选。没有图、数据库、AgentLedger、任务或历史迁移。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 保留重复入口 | 继续混淆选择范围，不采用 |
| 隐藏行但继续文件RPC | 文件故障仍可能阻挡画布候选，不采用 |
| 删除新文件选择、保留旧读取 | 单一文件入口且历史兼容，采用 |

## 后果

正面：职责清晰，减少RPC和候选依赖，文件服务失败不影响画布选择。

负面：旧文件读取暂留，不能以菜单已删除为由清理历史协议。

## 可逆性与重审条件

回退已核验110包可恢复原文件候选，所有图、素材、任务与旧标记保持。只有确认草稿 / 剪贴板 / 历史不再依赖旧file标记，或引入正式新版本迁移时，才重审旧读取路径。
