# ADR-0059：Seedance素材预审与固定生成引用

状态：已采纳

文档类型：解释；负责人：项目维护者 / 开发执行者；最近核对：2026-10-29。
记录日期：2026-10-29。预审协议、恢复、配置或生成引用变更时复核。

## 背景与驱动因素

1. 用户要求 Bytedance / BytePlus 的图片、视频、音频素材提前送审，三项配置默认脱敏；通过后以官方Asset ID参与视频生成。
2. 同一节点既有单次批量主图，也有多次历史输出；审核状态必须跟随原文件身份，不能写在节点上共享。
3. 原画布数据库DDL、Asset和TaskSnapshot结构必须保持；官方创建接口没有已确认的幂等保证，回执丢失不能自动重复创建。
4. 用户明确未送审、失败、审核中仍可生成并传URL；当次请求不能被后来审核结果修改或重提。

## 决策

在同一插件内新增ReviewStore / ReviewRuntime，使用同dataDir下独立`seedance-review.sqlite`，主库schema 3 / 23表不变。主库writer token与目录锁同时约束预审写入，停宿主同时停止独立队列。配置与接受的凭据版本沿用Vault，不让Client提交域名、签名区域、URL或Vault引用。

设置新增「Seedance 预审」标签，分别配置两家ProjectName / AK / SK，全部默认遮罩。编辑留空保留，AK/SK成对替换，版本CAS；眼睛只读取当前owner的单字段，no-store，隐藏 / 取消 / 切页取消迟到回包。更换密钥不能只凭AK文字继承资源域，只有新凭据可读取同项目原精确组时保留；其他情况隔离。

新画布同次本地创建登记两家已配置供应商的AIGC组，云端建组异步，不拖住创建。启动补齐配置启用后新画布的漏登记；旧画布首次送审补建。真人路径只选择官方已认证LivenessFace人物组，分页读取与送审前精确核对类型 / 项目 / 身份，不以AIGC替代认证。

预审对象为canvasId + assetId +原字节hash +供应商资源域 +组。每供应商最多2个网络步骤，全局最多1000个活动任务；原文件按预审合同重新检查，与模型输入限制分开。提交前持久issued；只有GetAsset.Status=Active显示通过。Processing不通过，明确拒绝为failed，结果不明为unknown。重启保留外部ID并继续查询，无ID已issued不重传；人工对账以稳定Name、项目、组和类型逐页精确匹配，唯一可信结果才恢复。

节点名称旁统一“审核中”，Active青蓝盾牌勾、Failed红盾牌叉，unknown为独立待确认。BD / B+分别标注。单次批量只对主图提供入口，换主图切换状态；多次历史展开后每个输出均可送审，收起只针对当前封面，空封面不挪用上一输出状态。Client每活跃画布合并读取，隐藏暂停，Host继续；状态只通知相关标记订阅者，不重挂媒体或测量几何。

0.2.55补充用户确认的入口条件：没有任一已保存预审配置时，媒体节点不显示预审按钮，后台也不创建组 / Group ID。进入画布先读取掩码配置；至少一家配置完成即启用入口，不要求云端建组完成；旧画布也可使用，首次送审时补组。配置读取尚未成功或失败时隐藏入口，设置保存 / 关闭及重新激活时刷新，同画布只有一份配置读取 / 可用性订阅。折叠历史的预审、下载与展开合并为一排，空输出只显示展开。节点操作栏的修饰键滚轮在画布根非passive捕获并转交原生XYFlow处理，保留指针坐标、倍率限制及按钮的nodrag / nopan，避免nowheel造成页面缩放；不影响编辑器内部滚动。

0.2.56将操作栏的普通wheel也交给同一原生处理器，补齐两轴双指平移、反向与惯性。只有操作栏受此桥接，编辑器滚动与按钮pointer保护保持，倍率依旧由普通平移 / 修饰缩放的原规则决定。

0.2.57细化送审界面：同一asset两家Active隐藏送审按钮，名称旁标记保留。已送审供应商与未配置项均禁用，分别悬停显示“当前素材已送审” / “当前供应商送审未配置”；优先选择已配置未送审项，全部禁用时不假选 / 自动提交，菜单仍可看原因。失败 / 待确认恢复操作独立指向原任务，不依赖禁用选项；切供应商清空人物组和路径。紧凑Modal移除重复标题 / 文件名、通过任务详情与底部生成说明，只保留失败原因和必要恢复操作。不改服务端幂等、Asset身份、预审组或生成引用。

新Seedance任务接受前以既有requestId固定每个referenceId的原hash与来源。当前供应商 / 项目 / 资源域匹配的Active传`asset://<官方ID>`；其他情况固定为URL，仍接受生成，允许混合。实际模型EP需要用户配置在对应预审项目下；不能从API Key推断账户。引用顺序和image_url / video_url / audio_url、帧 / 参考role保持，官方ID大小写保留。后来审核 / 配置变化仅影响下次生成。新任务缺绑定或hash不匹配停止派发；旧任务沿用旧URL逻辑。

签名采用固定官方`@volcengine/openapi@1.36.2`的签名模块，保留Apache许可证、原文件hash和修改说明；仅移除debug日志及无用注释，避免签名URL泄漏。依赖固定crypto-js 4.2.0 / form-data 4.0.6；两地区独立离线Node Crypto向量核对UTC与精确JSON字节。BytePlus明确Default策略，Bytedance不传Moderation。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 状态写入节点params / 原Asset | 主图和历史串状态，违反存量格式约束，不采用 |
| 原canvas.sqlite增表并跨表事务 | 原子性更直接，但违反当前DDL约束，不采用 |
| 仅浏览器执行与轮询 | 关闭 / 隐藏后失去调度，不采用 |
| 审核通过作为生成前提 | 与用户要求相悖，不采用 |
| 独立持久库与接受前固定引用 | 多库恢复复杂，但满足隔离 / 兼容，采用 |

## 后果

正面：画布结构保持；原文件多处引用一致；审核故障不占生成队列；未通过继续URL生成；当次生成身份固定。

负面：新增共同备份对象；Cloud POST不能承诺exactly-once；持久记录 / Vault尚无GC；通过记录对应的云端权限被撤销时不会自动改URL重提。真实权限、素材权益、编码与模型效果仍需用户验收。

## 可逆性与重审条件

卸载 / 回退不删除云端资源。备份必须覆盖主库、预审库、Vault、配置及媒体定位。已接受依赖绑定的生成未结束时不能安装0.2.53继续派发；必须排空、保持新版只查询 / 停止派发，或恢复共同停机备份。后续允许主库增表、内嵌H5认证、引入Webhook、换SDK或多实例时重审。
