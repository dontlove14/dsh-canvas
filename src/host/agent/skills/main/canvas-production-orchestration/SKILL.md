# 创作统筹

## 适用与输入

多角色创作、分阶段续作、处理专业成果冲突或局部返修时使用。先加载本方法，再读用户当前目标、限制、canvas_inspect、creative_project/creative_progress及获授成果。主级只读原文索引和进度，正文分析交获授专业角色；目录和历史摘要不能冒充已读全文。

## 工作步骤

1. **明确本轮终点**：分清要方案、专业规格、节点准备还是原任务结果核对。写可检查的完成条件及当前不包含的工作；“准备三镜视频节点”以三份有效节点回执和生成交接为终点，不以生成视频或剪出成片为终点。
2. **盘点可复用项**：逐份核对真实artifactId、作者/类型、版本、来源、依赖、状态及未决；区分已保存、主级已审阅、用户已认可、媒体技术成功。已认可且适用于本轮的成果直接引用，不能因新开对话就重做或改写旧认可。
3. **找最小缺口**：按依赖反推本轮缺哪些专业判断。用户只改标题可直接准备精确执行清单；只改一镜运动交shots相应方法。缺用户风格/模型决定交方案审阅，缺可读原文或资产规格交相应专业；不把所有缺口都交给用户回答。
4. **先选模型再派正式规格**：正式shots委派前用canvas_select_model确认视频型号与供应商；assets生图规格前确认图片型号。有效选择复用，不机械重问。从canvas_inspect动态目录取得合法时长、模式、尺寸、参考数量/时长及组合限制；主级不维护Markdown型号数值表。用户换型号后只复核受影响方案，以新批次续作。每项有明确问题、角色、获授输入和验收，用operationId、role、task、来源/成果/节点/素材ID及skillNames委派，其他模型相关任务用modelKinds明确声明；宿主自动补必需类型、实时能力和匹配提示词Skill。独立故事/外观概念可先做，不写未选模型的正式生成规格。
5. **按真实依赖启动**：需要上游决定的任务等待真实成果；独立任务可共用固定已存只读参考。专业与执行共享每作用域maxConcurrentAgents，默认4、可配1–4；不把“4个角色”当成可额外再开4个执行者。不为凑并行启动依赖未定的分支。
6. **核对交接再推进**：收到专业回执后读取对应成果，确认范围、完整性与未决。若两份成果冲突，列具体证据、影响镜头和负责角色；已有用户决定优先，专业事实缺口退回相关作者，新的审美选择交用户。主级不自行改写专业全文消除冲突。
7. **按变化范围续作**：读取原批次进度/回执与已存分段成果，保留成功项。新任务只包含已核实未完成或用户新改的范围及真实依赖，不将旧批次换ID整批重派。未知生成先canvas_task查原任务；人工接管、epoch变化或交接结束时停止旧执行计划并按新用户消息核对。

## 角色与阶段选择

| 缺口 | 负责角色/方法 | 启动所需前置 |
| --- | --- | --- |
| 故事因果、改编、对白稿 | story对应结构/长文/剧本方法 | 精确来源与已有决定 |
| 导演意图、镜头序列、单镜画面、动态提示词 | shots对应四项方法及宿主自动加载的视频模型方法 | 已确认视频模型、上游剧本或镜头目标；后一阶段引用前阶段实际成果 |
| 人物/服装/地理/道具、连续性与图片规格 | assets对应三项方法及所选图片模型方法 | 独立设计先明确实体和用途；正式图片规格须已确认图片模型 |
| 声音计划、台词估时、TTS规格 | audio对应方法 | 镜头目标/真实台词及适用模型能力 |
| 缺Fish ID且需要固定音色 | voice候选/证据方法 | 声音方向；用户已有ID直接进入主级流程 |
| 计划、引用、声音或交付的交叉核对 | review对应方法 | 可核对的成果/参数/回执，说明能否实际观察媒体 |
| 已确定的画布写入 | 同级executor，精确清单方法 | 完整commands、有效控制、模型与真实引用 |

复杂视频可沿“剧本→用户选择视频模型→导演→序列/资产→真实资产及用户认可→单镜画面/声音→模型感知动态提示词→针对性审查→节点准备→用户生成”安排，但只启动本轮确实缺的环节。序列另列叙事镜头与生成片段，优先合并同场连续且参考并集合法的内容，拆分必须说明原因，不强制填满上限。资产正式生图规格前确认图片模型；互相依赖的部分等待交接。不需要固定音色时跳过voice/TTS，原生视频声音仍默认开启。

复杂拆分、并行与续作按需读取[统筹工作表](references/orchestration-workbook.md)，模板只用于任务说明，不新建调度状态或持久化字段。

## 交付与阻塞

交付本轮目标、已复用成果、下一批role/skillNames及精确输入、依赖、验收项、用户决定点、成功项和未决范围。状态以宿主实际进度和回执为准，不根据等待时长或静默推断失败、完成或重启任务。

检查责任唯一、前置真实可读、权限随任务精确绑定、模型/预算决定有效、成功成果未重复。缺前置仅阻塞相关分支，保留独立已完成内容；用户问题只包含查不到且必须由用户决定的信息。

主级负责统筹、审阅与交接，不加载其他角色正文、不直接写画布、不替用户认可；不宣称已观看音视频、完成混音/剪辑或导出未实际存在的成片。
