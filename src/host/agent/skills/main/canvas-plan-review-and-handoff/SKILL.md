# 方案审阅与生成交接

## 适用与输入

需要用户决定具体方案，或图片/视频节点已准备好要交还生成时使用。输入：用户本轮目标和既有授权、专业成果、实际模型选择、节点/任务回执及当前图版本。先读现有决定与成果，把用户决定缺口、专业资料缺口和实际执行缺口分开。

## 准备可审阅方案

1. **先核对已有决定**：用户已明确的风格、范围与一般改稿授权直接沿用。需要图片/视频模型时canvas_select_model核验有效选择；仅有一个可配项也走真实选择，已有有效选择可复用。没有可配模型时说明所需配置，不静默换供应商或猜型号。
2. **准备具体内容**：方案写目标、数量/镜头范围、采用哪些实际成果、人物/场景/道具和声音安排、参考用途、支持的模型/模式/参数及验收条件。尚未选模型时只把可独立确定的设计写清，模型相关项标未决，不承诺数量上限或兼容性。
3. **说明改动和代价**：指出相对现有成果改变什么、保留什么、影响哪些节点/镜头、是否需要新的生成。成本有可核对依据才给数值；无依据只写生成数量及成本待核，不用“预算没问题”代替精确TTS授权。
4. **提出最少必要决定**：缺审美/范围等用户决定时，用canvas_review_plan的plan/title/question展示可审阅方案和具体待选点。缺专业依据先委派补齐，不让用户面对“是否继续”空卡。已有明确授权不重复审阅；源套件的每轮重新确认规则不进入本流程。
5. **处理修改意见**：只把新意见及其影响范围交对应作者；核对当前版本和用户人工修改，保留未受影响的认可成果。模型、范围、预算或新增付费内容有变化时核对相关决定，普通措辞修正按已有授权继续，不重开全流程。

## 核对节点后交还生成

收到executor实际回执后再canvas_inspect核对当前节点；不能用专业文字稿代替实际图。逐项检查：

- 实际nodeId、节点类型、完整prompt、当前有效模型/模式/比例/时长和其他支持参数，与本轮规格相符。
- references、prompt的真实asset token、首尾帧参数及生成当时原始依赖一致；每份用途明确，类型/总数符合当前模式。确实无关的历史依赖只给精确排除原因，不自动补边或改历史。
- 新视频有声音开关时默认开启；无音乐只排除音乐，无固定音色/音频参考/独立TTS不扩大成无声。false必须已有主级宿主绑定的精确用户依据。
- 所有目标都有真实完成回执；失败、未知、遗漏与人工变化独立列明。缺一项不把整批称为准备完成，也不重提已成功项。

全部本批目标就绪时，用当前revision、稳定operationId、实际nodeIds及必要referenceExclusions调用canvas_handoff_generation。按回执简短转告reminder和节点名称，然后结束本轮操作；交接后不继续改图、准备下一批或点击生成。

有部分就绪时报告已完成与缺口；可以在本轮范围内单独交接确已就绪的子集，须明确其余目标未交付，不隐藏整批缺口。交接状态过期或人工接管后读取当前图，不重播旧交接或让旧审阅恢复控制。

## 结果与证据尺度

| 当前证据 | 可说明 | 不应说明 |
| --- | --- | --- |
| 方案卡及用户决定 | 本方案已确认，按决定继续 | 图片/视频已生成或用户已认可媒体 |
| 节点回执+inspect+交接回执 | 参数已准备，请检查并点击生成 | 视频制作完成、自动开始生成 |
| 原任务处于等待/运行 | 正跟踪原任务，结果尚未就绪 | 因超时重提或伪造新结果 |
| 原任务技术成功/实际素材ID | 原任务已有结果，交用户查看/试听 | 已证实画面/声音质量或已成片 |

TTS按canvas-voice-choice-and-audition核对精确声音/文本/数量授权再走原队列；canvas_show_audio只展示实际原任务/素材，不自动播放、重生成或借用官网样音。用户认可只能来自真实用户决定，主级审阅和review意见不能代填认可。

复杂方案、局部返修与部分交接按需读取[方案与生成交接工作表](references/plan-and-handoff-workbook.md)。

## 交付与阻塞

交付具体方案及待决定点，或实际就绪节点、交接回执/reminder、保留成功项及未决。检查当前版本、完整参数/引用、真实回执、用户决定及完成措辞一致。

缺来源、模型、引用、声音依据或失去控制时阻塞相关目标并保留现有成果；未知任务先canvas_task查原taskId，不把重新调用生成作为检查。
