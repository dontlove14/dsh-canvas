# 音色选择与真实试听

## 适用与输入

需要固定角色声音、FishTTS试听或单参考复刻时使用。输入：用户已有声音决定/ID、获授参考音频及其真实原文，或voice角色本批保存的官网候选；另核对角色、朗读文本、适用镜头、数量和既有授权。

## 工作步骤

1. **先选输入分支**：用户已有ID直接使用，不再次委派查找或要求官网核验。明确选单音频复刻则核对该音频；无ID也无参考且确需固定音色才委派voice查官网候选。只需视频原生环境声/动作音效时无需启动voice/TTS。
2. **写少量稳定方向**：从相对音区、质感、年龄/体量听感、语速基线、口音与停顿习惯中选3–5条与用途有关的判据，附过界反例。区分稳定身份与单句情绪/重音；“本句生气”不等于换音色。同剧近似角色给可比较差异，不把性格或性别标签直接当听感事实。
3. **核对候选证据**：voice产出必须有本批真实详情id/title/description/sourceUrl/sourceHash/retrievedAt及suitability、limitation。区分官网公开文字、匹配提议和未试听事项；主级不改原字段或把猜测提升为官网记录。候选只供用户选择，不自动选第一条付费生成。
4. **处理官网不可用**：无可用ID或官网不可访问时保留真实失败说明，停止检索；指引用户在可访问设备打开https://fish.audio/，进入详情页，从`/m/`后复制ID，不含斜杠或查询参数，发回对话。收到ID后直接进入准备分支，不再次核验；不下载/转发官网样音或改用非官方ID。
5. **准备可比较试听**：写每条对应角色、声音ID或单参考、确切朗读文本、条数和验收问题。用户已授权的声音/文本/数量直接沿用；缺决定时先给具体方案并只询问缺口。多候选对比在用户授权后使用同一已确认文本与尽量一致的可控参数，不为凑比较扩大生成数量。
6. **准备精确TTS规格**：已有ID与一份已连接参考音频互斥；reference_text必须是该参考真实原文，prompt是新朗读文本，不能填音色描述、文件名或媒体token。参考未知转写交用户或audio核对已有获授文本，本轮没有转写能力时不声称已转写。
7. **核对原任务并展示**：通过canvas-execution-manifest-planning将精确TTS清单交executor与原队列。拿到真实taskId/assetId后canvas_show_audio展示；未完成只跟踪原任务，失败先canvas_task读原记录，不重提生成。播放器不自动播放、不重新合成，用户试听意见才是听觉证据。

## 选择、复刻与参考边界

| 情况 | 本轮处理 | 必须保留的区别 |
| --- | --- | --- |
| 用户提供ID并明确试听 | 按已有授权准备实际试听；ID直接使用 | ID由用户提供不等于主级已听过/兼容已证实 |
| 官网候选待选 | 展示真实证据与方向差异，用户选择后准备 | 官网描述不等于供应商实际合成效果 |
| 单音频复刻 | 一个真实音频边+参考原文，清除互斥ID | 参考原文不等于新朗读文字 |
| 试听不合意 | 记录用户听到的问题，交对应规格作者作局部调整 | 修改稿不等于新增合成已授权；旧试听保留 |

参考只借已决定的音色/口音等用途，不把样例台词、临时情绪、混响、底噪或伴奏当作目标。这个控制说明是意图，不能保证模型清理录音；无试听能力不声称参考为单人、无噪或克隆已相同。

需要跨镜声音一致性时记录已选真实ID/音频及适用范围，持续伪装等变体须有用户/剧情依据，单句表演交audio。专名发音按已有用户决定与真实文本处理，未经支持不加不存在的发音参数或保证模型读法。

视频不支持音频参考时跳过音色输入；支持时区分角色音色参考与本镜台词，不让多人共用一份声音。无固定音色、无音频参考、独立TTS或无对白均不关闭视频原生声音。

复杂选型、比较试听与复刻按需读取[音色选择工作表](references/voice-choice-workbook.md)。

## 交付与阻塞

交付用户实际决定、角色与声音映射、真实ID或单音频边、参考原文/新朗读文本、授权条数、原任务/素材ID与试听限制。区分方向提议、官网证据、技术成功和用户听觉认可。

检查ID与单参考互斥、原文与新文本正确分开、候选原字段对应本批证据、声音/数量授权覆盖当前方案、播放器只跟踪原任务。用户已有ID不追加官网要求，用户反馈未到时不填听觉结论。

缺声音/数量决定、参考授权、真实原文、节点/任务回执或模型输入能力时只阻塞相关项。主级不替用户选音色、不声称已听过、不下载样音、不自动复刻、重试或改写历史认可。
