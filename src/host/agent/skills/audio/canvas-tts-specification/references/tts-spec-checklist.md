# FishTTS 规格字段与试听交接

此表仅供专业规划，不能赋予生成权限。实际声音来源和数量由用户授权，执行通过主级精确清单和既有队列。

## 字段

| 项目 | 填什么 | 不能做什么 |
| --- | --- | --- |
| prompt | 新朗读文字 | 插媒体token、把参考原文当新文本 |
| params.type | tts | 指定图片/视频modelId |
| params.reference_id | 用户已有或已选真实音色ID | 猜ID、与参考音频并用 |
| params.reference_text | 单参考音频真实原话 | 用新台词/猜测补转写 |
| params.speed / volume | 现行契约值，默认1 / 0 | 添加未支持参数，超速硬塞对白 |
| references | 复刻时一份真实音频边建议 | 两份音频、假assetId、文本token代替连线 |
| taskId / assetId | 实际生成回执之后才有 | 用规格ID或批次ID冒充结果 |

## 单音频复刻示例

教学参考原话“今天下雨”，新朗读“欢迎回来”；reference_text与prompt各自保留真实来源。只有用户明确提供转写才可填前者。参考音频的音色、参考内容与新文本是三件事。

## 发声方向

规划人物此时意图、自然停顿、呼吸和听者反应，实际新文本仅含可朗读内容及项目已支持标记。外部模型的[sigh]、情绪参数或自动口型方案不直接移植到FishTTS。

## 试听交接

主级核对已有授权→精确清单执行一次→保留原taskId与结果assetId→只读播放器展示→用户试听选择。候选多次试听须有数量授权；不自动播放，不为第二条试听给文本加空格来绕过回执或另开任务。

## 不确定与失败

官网打不开时主级指引用户用可访问设备从/m/后取ID；收到ID无需再次核验。缺音频原文、声音来源或授权时规格可保存为有缺口，不能假装可生成。任务未知/中断先核对原队列，不重复提交。

## 完成

规格字段齐备、有真实来源/授权是“可交主级准备”，不是“语音完成”。试听质量、错读、漏词和兼容性由实际结果及用户反馈确认；音频元数据不证明已经听过。
