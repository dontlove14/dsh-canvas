# 资产生图规格

## 适用与输入

人物身份图、服装状态图、场景方位图、道具细节、风格帧或局部提示词修改使用本方法。输入：获授外观规格及不变量、用户已确认图片模型的planningModels、用户风格/语言要求、真实参考和目标镜头。加载canvas-generation-prompt-craft与canvas-model-aware-references，宿主自动注入匹配模型提示词方法；正式规格前须由主级canvas_select_model确认图片型号与供应商。未选模型时仅可另派独立外观设计，不进入生图规格。

## 工作步骤

1. **定本图用途**：先回答下游需要认清什么。身份选脸部/体态，服装选剪裁和轮廓，场景选锚点关系，道具选可操作结构与尺度；每张图有明确验收目标，不无用途生成整套板。
2. **选择视图**：在单视图、受控多视图或环境内参考中择其所需。多视图须说明同一身份/同一变体、各视图关系与清晰分区，且仅在模型和下游可用时选用；不能把并排板默认当成独立人物图，必要时向主级建议分图准备。
3. **组织静态正文**：按用途与主体 → 稳定识别锚点 → 当前单一变体 → 视角/尺度/空间关系 → 光色/材质 → 背景 → 必要文字 → 保持/排除项编写，省去不适用项。一张图只写一个时刻，不能同时要求道具打开与关闭或把完整走路过程塞进静态图。
4. **选识别布光与背景**：依据需要看清的形状、颜色或材质选光；身份图不只靠背光剪影，道具金属高光不遮住按钮，场景图不为美感搬门窗。默认避免遮住关键结构的复杂背景，用户明确的二维/三维/写实风格分别保留，不按性别/年龄或善恶套光型。
5. **约束参考**：逐份写source/真实assetId/token、主要用途、允许控制与不得带入的内容。人物参考不自动决定姿势，构图参考不带入他人身份/文字，风格参考不重写地理。所有必要输入受实际模型类型/总数/模式限制，超限或缺图交主级，不自行删掉必要一致性输入。
6. **核对文字与负向项**：用户指定文字逐字保留并说明承载面与位置；未知文字写待定或按已授权要求留白。负向只排除明确高风险误读，不能要求可读胸牌又“禁止所有文字”，也不能要求旧铜锈又“毫无磨损”。参考图残留不能靠负向保证清除。
7. **写参数建议与验收**：按实际模型支持的模式、比例/尺寸与参数填写；不把外部命令参数写进本项目接口。每图给验收点及前置缺口，文字规格不冒充真实生成结果。

## 局部修订

先读当前获授规格、真实待改图片和最新目标提示词，避免旧缓存覆盖人工修改。每项写四要素：

- **目标**：具体图、对象及区域；未有真实待改图时标缺口。
- **变化**：可观察的位置、范围、程度、色彩/材质结果，避免只说“更狼狈”。
- **保持**：先点名脸部/体态、未变衣物、固定地理、道具结构、构图与光向，再写“其余保持”。
- **连续性影响**：变化属于当前图、已有变体还是需要上游新增变体，指出受影响镜头。

修改身份、服装基准或固定地理先交对应设计/一致性方法核对；一般点名修订沿已有授权，不机械要求再批准每句文字。只改变袖口湿痕时不重写整个人物或增加无关参考。抽象风格缺决定时给少量可观察建议交主级协调。

参考的允许/禁止控制范围是提示词及检查依据，不能保证模型绝对遵守。默认中文；用户指定提示词语言才改，品牌、模型名、真实token和用户画面文字原文保持。不要照搬外部REF/IMG/PLAN编号或删掉本项目{{asset:实际UUID}}引用。

复杂视图、参考范围、文字与局部编辑按需读取[资产图片规格工作表](references/asset-image-spec-workbook.md)。

## 交付与检查

用现有asset-spec保存：每图逻辑名、用途/验收目标、规格版本、静态prompt、negativePrompt（需要时）、模型相关参数建议、真实引用表、参考边界、保持项、影响范围与缺口。已有图片ID与待生成条目明确分开，不把临时逻辑名当UUID。

通过canvas-saved-artifact-handoff交实际保存artifactId；主级据此准备精确commands，执行者创建节点并同次保存references/token，图片仍由用户检查并点击生成。

检查视图满足实际镜头、不混身份或互斥状态、所需不变量完整、文字/负向无冲突、引用与真实模型能力相符、数量有用途。缺身份、模型、授权素材或修改基准时仅阻塞相关规格；不自行换供应商、不直接建图、不生成或清理图片、不改历史任务与认可。
