# 资产一致性

## 适用与输入

跨镜复用、换装/伤势/道具状态变化、场景反打或修订影响核对时使用。输入：获授asset-spec、已认可真实素材、镜头范围、用户变化要求与生成当时referenceDependencies。先读当前获授版本及原保存成果，分别记录逻辑实体、规格版本、实际assetId和认可状态。

## 工作步骤

1. **建立基准**：按人物身份、服装、道具、场景分别列不变量；注明依据是原文、用户决定、文字规格还是实际可见媒体。文字里写“红袖口”不等于生成图已符合；文件名也不能确认身份。
2. **排出状态链**：按事件/镜头顺序写进入状态、变化原因、退出状态和下一镜承接。给换装、伤势、破损、开闭、持有者及光态明确起点/终点；未知过渡标待核，不为解释不连续擅自补剧情。
3. **区分漂移与允许变化**：新服装按已决定范围进入新变体；同一套衣服无理由变色才是漂移。单镜表情/视线/持有手由shots管理，但资产交接须指出受影响的道具状态和锚点，不能把活动姿势写成永久锁。
4. **写少量可见不变量**：对重复出现、容易被看出漂移且剧情不改变的特征写最小短语及适用范围，如“深蓝立领棉布工作服，左袖口白色双线”。明确在哪些镜头确实入画；衣服不入画的眼部特写不强塞服装词，叙事会改变的湿痕或伤口进度记状态。
5. **核对地理与视图**：固定门窗位置以场景锚点为准；反打只改变画面左右，不改变门窗真实位置。天气/昼夜/灯开关记状态及来源；区别换视角与新增空间，不能用“气氛不同”解释建筑改变。
6. **核对真实参考覆盖**：从派生素材生成当时的referenceDependencies追溯原始人物/服装/场景/道具；不读取源节点最新输出替换旧镜头身份。分镜图能交代构图和起点，不能因此排除必要原始图。按canvas-model-aware-references给逐镜精确输入建议。
7. **限制修订范围**：报告具体漂移、位置、影响和必保项；提出更新哪个规格/提示词及哪些镜头需要复核。只有主级可把建议变成精确执行清单；已认可旧成果、历史图和任务保持原身份。

## 核对尺度

| 对象 | 不变项例 | 允许变化及条件 |
| --- | --- | --- |
| 人物 | 脸部比例、稳定发型、永久标记 | 妆容/伤势/年龄阶段按已决定变体 |
| 服装 | 同版本剪裁、主色、扣子/配饰位置 | 换装或持续污湿要有范围与依据 |
| 道具 | 轮廓、材料、尺度、唯一标记 | 开闭/破损/内容物/持有者按状态链 |
| 场景 | 入口、固定地标、连接与尺度 | 摄影方向改变画面关系，光态改变须有来源 |

比较时先说明证据能力：获授且图片模型可读时用canvas_view_image核对实际像素；只见元数据则只核对ID/依赖/参数。音视频不能以本方法声称已观看或试听，实际媒体质量依用户反馈，不因文本哈希一致就说画面一致。

参考图里已存在的错衣服、字、水印或地理冲突不能靠一句负向提示保证消除。报告冲突与受影响范围，向主级提出替换、另备正确参考或局部修订建议；没有对应能力和授权不执行清理。

复杂状态链、版本与局部影响按需读取[资产连续性工作表](references/asset-continuity-workbook.md)。

## 交付与检查

用现有asset-spec保存：逻辑实体→规格版本/实际assetId、依据及认可状态、不变量、生效镜头、进入/退出状态、变化理由、原始依赖、逐镜缺口、修订目标与必保项。新增成果通过canvas-saved-artifact-handoff交接真实artifactId，不覆盖旧文件或改写原认可。

检查身份未混用、变化有起点、相邻状态可承接、锁项确实可见、固定地理未被画面方向替代、真实历史依赖未漂移；区分“规格符合”“引用完整”“像素核对”“用户已认可”。

缺素材授权、原始依赖、可读图片或确定版本时交回主级，仅阻塞相关镜头；不猜ID、不改旧素材、不自动补边或重提生成。
