# 制作审查

## 输入与审查范围

输入：本批获授brief、asset-spec、storyboard/shot-plan、audio-plan、真实来源/素材/任务元数据和用户反馈。说明范围、版本、是否独立审查或参与了当前创作；先列能证明与尚不能证明的内容。

## 工作步骤

1. 先查结构与接口：缺失/重复逻辑编号、依赖指向、真实ID、时长合计、台词/声音/文字承载、矛盾参数和越过角色边界；只用实际可读证据。
2. 再查语义：上游事实→人物目标/策略→镜头职责→起点/动作/终点→声音与下一状态。每个问题配对具体上游事实和冲突下游内容。
3. 最后查创作选择：用户已接受限制的冲突可构成问题；个人偏好的风格或可替代拍法记建议，不能以“我不喜欢”否定方案。
4. 每条Finding写位置、证据/短引文、影响、所需修订结果、必须保留内容、负责角色、严重程度和状态。避免无证据“AI味”“不够电影感”或只给分数。
5. 按阻塞、主要、次要、建议排序。重复问题按负责角色合并，明确最小修改范围及复审范围，不以局部缺口要求全稿重写。
6. 总结可继续、需修改或资料不足及条件；这些是review内容结论，不调用认可接口、不把主级/审查通过写成用户approved。

## 专业技巧

- 事实检查、专业判断与审美建议分栏，承认不确定性；输入缺失只暂停依赖它的判断。
- 以观众理解/制作影响解释严重程度，不以术语数量或规则总数判断质量。
- 复审重新读取更新目标，核对修订目标与“必须保留”集合，关闭/保留对应问题；无关成功项保持。
- 生成任务成功、文件存在或参数有声不能证明表演、口型、混音或成片质量。没有直接视听证据就标待用户验收。

具体问题格式、分级、最小修订与反例按需读取[证据审查工作表](references/review-findings.md)。

## 交付与检查

保存review：范围/版本/审查方式、结论及继续条件、通过项、问题表、证据限制、负责角色与待用户验收。依赖真实成果，任务/成果身份与用户认可分开。

检查问题是否可复核、影响是否具体、修订范围是否最小、必保项是否明确、没有虚构看过/听过。审查只读、不写受审文件/图、不自动补边或生成；主级协调修订与用户决定。
