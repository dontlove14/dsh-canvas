# 声音与交付审查

## 输入与证据等级

输入：本批声音计划、supportsAudioToggle/参考能力、实际节点参数与引用、原taskId/assetId/结果元数据、用户观看/试听反馈。分清计划、结构核验、真实生成回执和用户视听结论，不能互相替代。

## 工作步骤

1. 支持开关的新视频/本轮显式修改默认有声；false必须有主级宿主绑定的真实用户无声依据。无音色、无音频参考、无台词或FishTTS方案均不成立；无开关模型不塞字段。历史false按当时记录与本批范围核对，不自动判违规或要求重生成。
2. 区分原生声音、音频参考、独立TTS；核对台词、说话者、画内/VO/OS通道、触发声效和环境/音乐进入退出。不要把“不要配乐”扩成整体静音。
3. 核对音色参考只承担指定人物用途，新台词单独明确；TTS的ID/一份音频互斥、reference_text是真实原话，prompt是新文本，实际参数/数量符合授权。
4. 核对声画时间预算与来源：估计与实测分开，整文件duration不证明发声窗口；没有转写或试听不能判断实际错词、声效时点、音乐层次和嘴型。
5. 对逐镜图片/视频、语音、制作文档整理实际身份/版本、状态、用户反馈和缺失项。原任务查询不重提，规格草稿不冒充生成结果。
6. 将问题按准备阶段、生成结果待验收、专业计划修订或外部剪辑/混音需求分流，给最小修订范围和必保项。

## 专业技巧

- 任务success、有音轨参数、可下载文件都不等于声音质量通过；实际用户反馈才支持“已试听确认”。
- 无对白镜可以有环境/事件声；主动局部留白不等于漏音轨。音乐不应该成为固定验收必选项。
- 对白/SFX时点、层次、清晰度是可观察目标；未有测量工具就不编造LUFS、峰值或音效偏移数字。
- 插件交付逐镜素材与文档，剪辑、字幕、混音、嘴型修复和成片导出需真实工具另行设计；不能因借鉴外部Skill就宣布具备。

需要交付证据表、静音/音乐分流与试听反例时读取[声音与交付证据表](references/delivery-evidence.md)。

## 交付与检查

保存review：本批开关与授权核验、台词/音色/TTS规格、实际回执与素材清单、用户反馈、未视听项、缺口与负责角色。结论不改用户认可。

检查证据等级、当前与历史范围、声音默认、真实ID、未完成/失败状态、未知任务不重提、原成果不重渲染。审查不生成、混音或修改受审内容，不虚构完成成片或音频自动评分。
