# 镜头序列

## 适用与输入

两个以上镜头需要顺序、覆盖与节奏设计时使用；已有完整序列时只改主级点名范围。输入：获授剧本/导演意图及版本、总时长与画幅、宿主planningModels中的用户已确认视频型号与动态能力、素材条件和声音计划。正式shots委派前先选模型；独立故事因果草案可先交story。不能先写正式分镜再选型号。

## 工作步骤

1. 做来源覆盖表：剧本场次、重要动作、对白、声音和必读画面文字分别由哪一镜承载。允许省略必须说明其授权与影响，不自行删除上游事件。
2. 给每镜一句“结束时改变什么”：信息、人物策略、关系、空间、控制权或情绪落点。只有景别没有目的的镜头需要重写。
3. 先在场次层写固定锚点、人物关系、轴线和摄影机工作侧，再安排逐镜起点/动作/终点；换机位不改变真实地理。
4. 排声音、必要动作、停顿和反应时间。可并行动作与台词共用窗口；必须等台词结束的动作累加。实录时长与文本估计分开标注。
5. 按信息变化、人物发力回合、听者后果、动作变化或空间揭示放切点。长台词可在听者或插入镜延续，不靠加快语速硬塞。
6. 区分叙事镜头与生成片段：一次模型生成可包含多个叙事镜头。优先合并同场连续动作且必要参考并集合法的镜头，例如当前模型支持12秒时，把4秒与8秒连续内容安排为一个12秒片段。内部切镜仍标注；动作超载、跳时/换场或必要参考超限才说明拆段原因，不强制占满上限。用动态合法时长、模式、尺寸与参考单份/同类/组合限制核对，不把经验当硬限制。
7. 核对相邻镜终点→下一镜起点、轴线/视线、持物/接触/落点、声音进入/退出和揭示顺序；最后求和总时长。

## 专业技巧

- 一个动作只有一个主要落实镜头；后续镜头可提供反应、细节或新的理解，不把同一交接从头演两遍。
- 正反打先保护互补视线和空间关系，特写留给必须读清的事实；不按句号机械切镜。
- 过渡镜只有承担等待、空间、声音悬念或情绪落点才保留。节奏不是越多镜头越快。
- 竖屏多人场用前中后景和真实遮挡关系分层；关键文字、手部和视线保持可读。
- 有意跳时、蒙太奇或冲击重复要明确注明来源决定；不能以“连续性”强迫补无用镜头。

用canvas_skill_resource读取[序列、覆盖与修订模板](references/sequence-template.md)，包含状态表、估时示例和正反例。

## 交付与检查

保存独立shot-plan：来源覆盖、场次站位、逐镜目的/时间窗/起终状态/动作/声音，另给生成片段表（包含镜头、总时长、模式/画幅、去重真实参考并集及用途、合并或必须拆分原因）、总时长、排除或待补项。逻辑编号与真实nodeId/assetId/taskId分开。模型变化先复核受影响片段、引用和提示词，再交主级新批次，不覆写旧认可成果。

检查覆盖完整、动作不重演、知情时机、状态闭合、时长依据及实际素材。局部修订保留不受影响镜头和成果；拆并镜说明下游受影响范围，由主级协调。序列明确后独立镜头可并行，依赖未确定不让实例各自猜顺序。不建节点、不拼接视频、不重提生成。
