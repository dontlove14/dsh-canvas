# Nano Banana 提示词

输入：宿主已确认banana模型、实时能力、获授外观/布局要求、实际图片与准确文字。同族共用自然语言设计方法，不把Pro、Flash、Lite或2.1的能力互相借用。

## 步骤

1. 用连贯视觉简报描述目的、观众、画面和关键细节，而非堆关键词。写清主体在做什么、为什么这个构图能读清目标；风格落到线条、材质、配色和光线。
2. 区分画面风格与对象身份。摄影写机位/尺度/自然光和可见材质；插画写轮廓/色块/笔触；三维写体积/表面/阴影。只取用户已选方向，不混合互斥媒介。
3. 多参考逐份写真实token、对象与允许控制。身份来自A、服装来自B、布局来自C时明确对应，并描述融合后的尺度、光向与遮挡；风格图中的人物与文字不能顺带复制。
4. 布局和文字直接描述。先给视觉层级、留白和阅读顺序，再给逐字文字、位置和字体关系。模型可写文字，不能套用第三方“Banana禁止文本”规则；准确性仍待用户看图。
5. 修改写单项目标与保持清单，每个独立任务携带真实基准图和完整不变量。仅移除桌面物体时交代移除后露出的表面；换服装要保留身份、姿势和自然垂坠。不能假设跨节点对话记忆。
6. 当前适配器未提供的搜索接地、视频输入、JSON响应或多轮会话能力不调用也不暗示。尺寸、参考上限及参数只读实时capabilities；负向字段只在支持时使用，默认中文，不强制JSON或英文。

需要风格简报、多参考合成或局部修改时读取[Banana工作表](references/prompt-workbook.md)。

交付：现有asset-spec中的prompt、引用分工、明确保持/变化项、布局与文字验收点，未知能力单列。主级协调，assets只写规格。

检查：同族型号已确认；描述有可见目标；参考身份与风格分开；文字要求不自相矛盾；没有假搜索、未接入视频或虚构上下文。

阻塞：缺品牌文字、素材或型号能力时阻塞相关项；不能自行换Pro、删除必要参考、调用外部接口或重生成旧成果。
