# 提示词工作表

用于将获授创作规格转成清晰图像/视频提示词，并检查修订与冲突。字段是现有draft内容骨架，不是新工具参数；主级协调、assets/shots在职责内写规格，按原清单/用户生成流程交接。

## 1. 已明确目标

```text
依据artifactId / 版本 / 获授素材：
这一图/镜头必须传达的可见或可听信息：
已决定身份 / 服装状态 / 地理 / 动作 / 风格：
已选modelId / 实际模式 / 比例 / 时长（视频）：
提示词语言（默认中文；用户明确要求除外）：
用户指定画面文字原文 / 位置：
未决项与具体影响：
```

## 2. 图像骨架

```text
主体身份、稳定外观及真实参考用途：
单一瞬间的姿态、表情和相对位置：
景别、机位、主次与留白：
场景地理、道具外观和归属：
光线方向、材质、风格：
指定画面文字（准确内容、位置、大小关系）：
允许变化与必须保持：
prompt：
negativePrompt（实际模型支持且必要时）：
真实references用途表：
```

静态图只表达一个状态。参考板或多视图要有实际用途/用户要求，不能为了“丰富”固定生成。

## 3. 视频骨架

```text
起点：人物/场景/道具状态与位置：
动作顺序：时间预算、主体、方向、可见变化：
摄影：机位、主运动、速度与终点：
终态：站位、朝向、道具与下一镜衔接：
对白：说话人、真实台词、表演、停顿预算：
动作声/环境声/音乐及出现时机：
实际模式支持音频参考时的角色音色用途：
原生声音默认开启；若明确无声则核宿主精确授权：
prompt / 必要且支持的negativePrompt：
实际时长/比例/模式与真实references：
```

时间段是可读创作预算，不保证当前模型逐帧、口型或指定文字精确兑现；真实结果由用户观看/试听核对。只有用户指定首尾帧且实际模式支持时锁定相应状态，不因单图自动切frames。

## 4. 局部修订

```text
真实目标素材 / 原成果版本：
用户授权变化：
必须保持（身份、站位、场景地理、其他参数）：
相邻镜头/资产状态的连续性影响：
新draft及独立artifactId：
待主级协调项：
```

修订建议不等于已执行，不覆写旧成果/认可，不重渲染原文件或重提旧任务。

## 5. 正反例

以下UUID、秒数和情境仅教学，正式规格必须使用实际获授输入。

**静态图。** “人物参考{{asset:11111111-1111-4111-8111-111111111111}}保持脸与红外套；此刻站在门左侧，右手握信、目光朝向门把手；平视中景，门与人物同框，窗在门右侧，左侧窗光照亮信封。”反例：“走进门、换衣、坐下、起身，全部发生在一张图里。”

**五秒动作。** “起点站在门左侧；前2秒抬头，随后向画面右侧走两步，末尾停在门前；摄影机缓慢侧移保持中景；脚步声按落脚出现，保留街道环境声，无配乐。”反例：“5秒跑过街道、进屋争吵并换装；摄影机同时推近、拉远和旋转。”

**文字。** 用户要招牌原文“归来”，写准确两字、招牌位置和画面主次，生成后人工核字；negativePrompt不写“禁止文字”。品牌/token原文保持，不能为中文默认翻译它们。

**声音。** “不加音乐，保留衣物摩擦、脚步与环境声”，原生声音仍开启；另计划Fish对白不自动静音。反例：无音色参考就写“无声视频”，或原文引用“静音”当成真实用户授权。

**局部变化。** 用户只要求红外套改蓝，稿中保持脸、姿态和门窗地理，说明后续仍用红外套的镜头需要主级判断衔接；另存新成果，不能覆写旧认可或自动生成整组镜头。

**正负一致。** 正向“自然侧移，两步后停住”，负向只在支持时排除肢体畸变等具体伪影；不能写“锁死姿态、不发生运动”。缺参考或剧情未决须报告，不能堆负向词掩盖。

## 6. 交接检查

- 一图一个状态；视频动作、对白与摄影预算适合实际时长。
- 身份、参考控制、地理、动作方向、终态和相邻镜头一致。
- prompt语言、原文文字、token与真实references一致。
- negativePrompt和其他参数受实际能力支持，正向/负向无矛盾。
- 声音计划服从镜头并保留默认有声，未决项可见。
- 交的是保存后的创作规格与回执；节点准备、生成结果和质量认可各按真实证据。
